TL;DR — 一句话看懂 M5

M5 在 M0–M4b（SiLU 全模式）之上补 softmax 反向（范围：no_group = batched + jagged）。核心做法是把 SiLU 的 MAIN pipeline fork 成一条新 pipeline，只改两个 STAGE：STAGE2 把「silu(S)·scale_p」换成「p = exp(α·S − LSE)」（log2 域 exp2 实现），STAGE5 把「ds = dp·g」换成「ds = p·(dp − D)」。其余 5 个 GEMM、KV/Q/dO 预载、收尾缩放逐字不变。

softmax 需要两个 SiLU 路没有的输入：归一化子 LSE（前向产、自然对数）和行点积 D=ΣvO·dO（新增 PRE kernel 现算）。两者都按 [batch,head,seq] 连续-seq 布局，前向写、PRE 写、MAIN 读、reference 读四方共址——这是整个 M5 最关键、也最易 silent-wrong 的对齐点。

1  M5 是什么：在 SiLU 之上补 softmax 反向

HSTU 注意力有两条激活路：SiLU（M0–M4b 已实现）和 softmax（本里程碑）。前向阶段二者的 P 不同（silu(S)·scale_p vs softmax_row(S)），反向的链式法则也随之不同。M5 只做 softmax 反向，且只覆盖 no_group（batched + jagged）；group softmax 与 cross-attention 是后续（M5b）。

白话：M5 做的四件事

  • ① fork 一条 softmax MAIN pipeline（新文件 hstu_attention_with_softmax_bwd_pipeline.hpp）：复制 SiLU pipeline，operator() 多收 LSE / D 两个 dram window、去掉 scale_p；只改 STAGE2/STAGE5。
  • ② 新增 softmax kernel + PRE kernel（hstu_attention_bwd_kernel.hpp）：HstuAttentionBwdDQDKDVSoftmaxKernel 多建 LSE/D window；hstu_bwd_dot_do_o_kernel 现算 D=ΣvO·dO。SiLU kernel 一行没改。
  • ③ dispatch 接 RunSoftmax（hstu_attention_batched_backward_dispatch.hpp）：去掉 kUseSoftmax 的 throw，launch 顺序 PRE → memset dq_acc → MAIN → POST。
  • ④ harness 消费上游 fwd LSE（example_hstu_attention_bwd.cpp）：softmax 时打开前向 is_training 产 LSE（连续-seq 布局），取回后转置喂 CPU reference；分配 d_dev。前向逻辑零改动。
为什么 softmax 能复用 SiLU pipeline？ 两条路的反向骨架完全一样：5 个 GEMM（dV=PᵀdO、dP=dO·Vᵀ、dK=dSᵀQ、dQ=dS·K 等）、KV/Q/dO 的 HBM→LDS→Reg 预载、shuffle、early-exit 都不变。区别只在「P 怎么算」（STAGE2）和「dS 怎么算」（STAGE5）这两个 elementwise 块。SiLU pipeline 本身又是 FMHA kr_ktr_vr bwd pipeline 的 fork——softmax 等于把 FMHA 里被 SiLU 删掉的 LSE/D 加载又搬了回来（见 §5）。

2  数学：softmax 反向的链式法则

设 S = α·(Q·Kᵀ)（α = attn_scale）。前向 P = softmax_row(S)、O = P·V，并存下归一化子 LSE。反向给定 dO，要算 dQ / dK / dV。

前向留下的两个量

LSE[sq] = log( Σ_sk exp(S[sq,sk]) ) // 前向存，自然对数；masked-out 的 S=−∞ P[sq,sk] = exp( S[sq,sk] − LSE[sq] ) // 用 LSE 一步恢复 P，免二次 softmax 归约

关键技巧：有了 LSE，反向不需要重跑两遍 softmax 归约（一遍求 max、一遍求 sum），单次 exp(S−LSE) 即恢复整行 P。masked-out 位置 S=−∞，exp(−∞−LSE)=0 自然清零。

反向链路（reference = oracle，reference_hstu_attention_bwd.hpp:39-50）

dV[sk] = Σ_sq P[sq,sk] · dO[sq] // dV = Pᵀ @ dO dP[sq,sk] = dO[sq] · V[sk] // dP = dO @ Vᵀ D[sq] = Σ_v O[sq,v] · dO[sq,v] // 行点积；= Σ_sk dP·P（softmax Jacobian 的归约项） dS[sq,sk] = P[sq,sk] · ( dP[sq,sk] − D[sq] ) // softmax 的 Jacobian dQ[sq] = α · Σ_sk dS[sq,sk] · K[sk] // dQ = α · dS @ K dK[sk] = α · Σ_sq dS[sq,sk] · Q[sq] // dK = α · dSᵀ @ Q
D 的两种等价写法。 数学上 D[sq] = Σ_sk dP[sq,sk]·P[sq,sk]（softmax Jacobian 对角项），但因为 O=P·V、dP=dO·Vᵀ，交换求和顺序可证 D[sq] = Σ_v O[sq,v]·dO[sq,v]（reference:46-48 给了完整推导）。后者只依赖前向输出 O 和 dO、与 sk 无关，所以可以在一个独立小 kernel（PRE）里 per-row 现算，省掉 MAIN 里的一次跨 sk 归约。这正是 M5 引入 PRE kernel 的原因。

softmax 路 vs SiLU 路：差在哪

环节SiLU 路（M0–M4b）softmax 路（M5）
P 恢复p = silu(α·S)·scale_pp = exp(α·S − LSE)
masked-out 置值S = 0（禁 −∞，silu(0)=0）S = −∞（exp→0）
dSds = dp · g，g=scale_p·dsilu(α·S)ds = p · (dp − D)
需要前向产物无（SiLU 反向不依赖 O / LSE）LSE（前向）+ D（PRE 现算）
scale_p用（1/max_seqlen 或显式）不用（softmax 自带归一化）
α 接线dQ*=α、dK*=α、dV 不乘相同
掩码方向是最易写反的一处。 SiLU 把 masked-out 置 0（因为 silu(0)·scale_p=0，且 silu 不能吃 −∞）；softmax 必须置 −∞（exp(−∞)=0）。两条路在同一份 STAGE2 骨架里方向相反——fork 时若照抄 SiLU 的 set_tile_if(0) 就会 silent-wrong。M5 用的是 set_tile_if(−inf)（见 §4）。

5  怎么复用 FMHA：LSE/D 加载、PRE kernel、smem 复用

复用边界一句话：SiLU pipeline = FMHA kr_ktr_vr bwd 的 fork（删了 LSE/D、换 silu）；softmax = 把 FMHA 删掉的 LSE/D 加载搬回来 + 换回 exp/LSE 数学。所以 softmax pipeline 的 LSE/D 加载代码、LDS 偏移与 FMHA 同款，只是 mask 是 HSTU 五因子 mask。

LSE / D：HBM → LDS → Reg（pipeline L318-364）

hstu_attention_with_softmax_bwd_pipeline.hpp · LSE LDS 偏移 L325-329 // LSE 落在 QT+OGrad+OGradT+Q 之后（FMHA 同款偏移）——这块 SiLU 早已在 GetSmemSize 预留 LSEDataType* lse_lds_ptr = ... smem_ptr + GetSmemSizeQT + GetSmemSizeOGrad + GetSmemSizeOGradT + GetSmemSizeQ; // D 再 +GetSmemSizeLSE；dS 再 +GetSmemSizeD（L349-372）
smem 总量为什么不变？ SiLU pipeline 的 LDS 布局里本就给 LSE / D 留了空洞（只是 SiLU 不填），Policy::GetSmemSize 覆盖了这些 region。softmax 只是把这两块空洞填上、并把 dS 的起点照常推到 D 之后。所以两条 pipeline 共用同一 GetSmemSize，无 LDS 增量、无越界。

PRE kernel：D = Σv O·dO（kernel L1204-1265）

hstu_attention_bwd_kernel.hpp · hstu_bwd_dot_do_o_kernel L1239-1264 // 每线程一行 (i_batch, i_nhead, sq)；hdim_v=64 小，单线程 float 累加 if(is_jagged) { const int q_start = seq_q_offsets[i_batch]; const long_index_t token = q_start + sq; o_base = token * o_seq_stride + i_nhead * o_nhead_stride; // O/dO: [b,seq,head,hd] d_base = i_nhead * d_nhead_stride + token; // D: [head,seq] 连续（seq stride 1） } else { ... d_base = i_batch*d_batch_stride + i_nhead*d_nhead_stride + sq; } if(sq >= seqlen_q) return; // jagged 跨批越界保护 → 每 D 位精确写一次（免 memset） float acc = 0.f; for(int v = 0; v < hdim_v; ++v) acc += type_convert<float>(o_ptr[o_base + v]) * type_convert<float>(do_ptr[o_base + v]); d_ptr[d_base] = type_convert<DDataType>(acc);
D 写出的布局 == MAIN 读 D 的布局。 PRE 用 param.nhead_stride_lsed / batch_stride_lsed 写 D（dispatch:291-292），MAIN 的 softmax kernel 用同一对 stride 读 LSE/D（kernel:717-722，MakeKargs:332/340）——构造上不可能错位。注意 PRE 对 O 与 dO 共用 O 的 strides（dispatch:284-287 有注释），本 harness O/dO 同 shape 恒成立；cross/异布局 dO 需另传。

6  【图2】LSE/D 四方布局溯源（最大 silent-wrong 风险）

这是整个 M5 最容易出 silent-wrong 的地方：LSE/D 被四方触碰——前向写、PRE 写、MAIN 读、reference 读——只要任一方地址算错就会「悄悄算错但不报错」。统一约定 [batch,head,seq] 连续-seq（head stride = phy_seqlen_q，seq stride = 1）。下图把四方地址画在同一条数轴上，证明它们落在同一元素。

图2：LSE/D 的四方（前向写 ① / MAIN 读 ② / PRE 写 ③ / reference 读 ④）地址在同一数轴上汇聚到同一元素。PRE 写与 MAIN 读共用同一对 stride，构造上不可能错位。

诚实标注 — LSE 数值盲区： GPU-bwd 与 CPU reference 共用同一份 GPU-产的 LSE（harness 取回后转置喂 reference）。这意味着对拍结构上无法独立验证 LSE 的数值是否正确——即便 LSE 整体算错，两侧也会「双错相等」而 PASS。此盲区的闭合方式：①前向写的 m+log(l) 正是产出 O 所用的归一化子本身，写读布局一致 → P_bwd ≡ P_fwd ≡ P_ref，既自洽又正确；②残余信任锚 = 前向里程碑对 LSE 数值的验证（M5 未改前向逻辑）。三方 review 一致判定可接受。
