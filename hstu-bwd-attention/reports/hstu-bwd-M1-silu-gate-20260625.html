CK · HSTU Backward · M1 代码改动 review

HSTU Attention Backward — M1（SiLU MAIN 闸门）：第一段真实反向数学落地

M1 把 M0 的 RunSilu memset 桩换成真正的 5-GEMM / 7-stage 反向流水：以 FMHA kr_ktr_vr 为蓝本，在 STAGE2 注入 SiLU 的 p/g、STAGE5 算 ds=dp·g，收尾 dq/dk 乘 alpha。范围 = batched + SiLU(no-softmax) + no-mask + bf16 + atomic + hd64。这是整条 M 链的风险闸门：R1（policy 能否零覆写复用）与 R2（留 g 会不会 spill/掉 occupancy）都在此一次性闭环。所有引用以 git show 1b3c90b4:<file> 行号为准。

读者：要 review HSTU bwd 第一段真实数学 + 风险闸门结论的工程师（关键术语配一句白话）
TL;DR — 一句话看懂 M1

M1 = SiLU 路反向数学 + 双闸门。新写一个 HstuAttentionBwdDQDKDVPipelineKRKTRVR pipeline，结构照搬 FMHA kr_ktr_vr，policy 零覆写直接复用（R1）；自写 kernel wrapper 携带 alpha + scale_p 两个标量（FMHA 只能传一个 raw_scale），dQ 走 float dq_acc atomic 累加 + POST elementwise convert。

对拍在 attn_scale=1.0（梯度量级 ~5 的真实信号）下 dQ/dK/dV 全 PASS，dK 逐位为 0；资源 VGPR=248 / Scratch=0 / occupancy=2，留 g 未引发 spill 也未掉 wave（R2）。两闸门 MET。

M1 最精妙 / 最易错处：双缩放轴 + dV 不乘 alpha。 HSTU 有两个缩放：alpha（QK 分数缩放，进 GEMM0 之后的 s）与 scale_p（SiLU 输出缩放，吃进 p/g）。FMHA bwd 的 kernel 只能传一个 raw_scale，所以必须自写 wrapper 把两个标量都带进 pipeline。链式法则上：p,g 已含 scale_p，而 alpha 通过 s=alpha·S 进入非线性，故 dQ/dK 末尾各乘一次 alpha；dV 只经 p 不经 s，绝不能乘 alpha（pipeline:510-512 只缩 dk、return dv 原样）。乘错一处，dV 的对拍立刻崩。

3  逐文件 review（为什么这样改）

① no_softmax_bwd_pipeline.hpp — SiLU 反向数学（核心）新增

  • :13-33 文件头自述设计：以 FMHA kr_ktr_vr 为结构蓝本改写（不直接 include），KV-resident 寄存器布局 / Q·dO·dS 的 LDS staging / shuffle 与 early-exit 全部沿用 FMHA，HSTU 差异只收敛在 STAGE2 / STAGE5 / 收尾三处。
  • :34-35 HstuAttentionBwdDQDKDVPipelineKRKTRVR<Problem, Policy = BlockFmhaBwdPipelineDefaultPolicy>——默认 policy 就是 FMHA 的，零派生（R1 的代码体现）。
  • :80 static_assert(!kUseTrLoad)：M1 走非 trload 的 kr_ktr_vr；gfx950 专用 trload 是 M8 perf。
  • :98-101 GetSmemSize 直接转发 Policy::GetSmemSize——LDS 字节与 FMHA 完全一致（保留未用的 LSE/D/bias 段，换来「布局原样复用、不必重证」；裁掉它们省 LDS 是 R6/M8）。
  • :108-116 operator() 签名比 FMHA 多带 float alpha, float scale_p（再加 smem_ptr 在末位，ck_hstu 约定）。这是双缩放轴落进 pipeline 的入口。
  • :137 mask.GetTileRangeAlongY(...) 无条件调用（P1-D）：M1 用 GenericAttentionMask<false> 返回 (0, seqlen_q)、IsMasking=false 把 edge-tile 掩码编译掉；HSTU 5 因子 mask 是 M2。
  • :365-371 fp32 sigmoid 函子（镜像 HSTU fwd f_silu）：float 路用 __builtin_amdgcn_rcpf(1+__expf(-x))，其余路 1/(1+exp(-x))。
  • :391-393 STAGE1 gemm_0 出未缩放的 s_acc（alpha 留到 STAGE2 再乘，与 fwd 口径对齐）。
  • :441-449 STAGE5 ds = dp_acc · g——g 已携 scale_p，故此处不再额外缩放（注释 :441 明示）。
hstu_attention_no_softmax_bwd_pipeline.hpp:395-412 — STAGE2：把 SiLU 的 p 与 g 一次算出// STAGE 2, HSTU SiLU: s = alpha*S; p = silu(s)*scale_p; g = scale_p*dsilu(s) auto p = SPBlockTileType{}; auto g = SPBlockTileType{}; constexpr auto p_spans = decltype(p)::get_distributed_spans(); sweep_tile_span(p_spans[number<0>{}], [&](auto idx0) { sweep_tile_span(p_spans[number<1>{}], [&](auto idx1) { constexpr auto i_j_idx = make_tuple(idx0, idx1); const CompDataType s = alpha * type_convert<CompDataType>(s_acc[i_j_idx]); // alpha 进非线性 const CompDataType sig = f_sigmoid(s); const CompDataType silu = s * sig; const CompDataType dsilu= sig * (1.0f + s * (1.0f - sig)); p(i_j_idx) = silu * scale_p; // → dV (STAGE3) g(i_j_idx) = scale_p * dsilu; // → dS (STAGE5) }); });
hstu_attention_no_softmax_bwd_pipeline.hpp:493-512 — 收尾缩放：dQ/dK 乘 alpha，dV 原样// dQ scale by alpha (FMHA raw_scale slot) tile_elementwise_inout([&alpha](auto& x) { x = x * alpha; }, dq_acc); if constexpr(kIsDeterministic) store_tile(dq_dram_window, dq_acc); // M6 路径 else update_tile(dq_dram_window, dq_acc); // atomic_add 进 float dq_acc // ... 为什么 dV 不乘 alpha？ 前向 O = (silu(alpha·S)·scale_p) @ V。对 V 求导得 dV = pᵀ @ dO，其中 p 只含 silu 与 scale_p、不含 alpha（alpha 是 s 内部的参数，不在 p→V 这条乘法链上）；而 dQ/dK 经 ds→s 反传，链上恰好带一个 ∂s/∂(QKᵀ)=alpha，故末尾各补乘一次。

闸门结论：R1 / R2

R1（policy 可否零覆写复用）= MET。 用 BlockFmhaBwdPipelineDefaultPolicy 配 BlockFmhaBwdPipelineProblem（BiasEnum=NO_BIAS + dummy BiasDataType），SiLU pipeline 原样调用 policy 的全部 Make*/Get* 描述子 + 5 个 GEMM + PTFromGemm0CToGemm1A/SGradTFromGemm2CToGemm3A；GEMM 之间插入的 dsilu/elementwise 与 policy 的中间寄存器分布完全兼容，无需派生 HstuBwdPolicy。
R2（留 g 会否 spill / 掉 occupancy）= MET。 -Rpass-analysis=kernel-resource-usage 实测 MAIN kernel：VGPR=248 · AGPR=0 · ScratchSize=0（零 spill）· occupancy=2 waves/SIMD。CDNA4 加法模型 occupancy = ArchVGPR + AGPR = 248 → 512/248 ≈ 2 waves，与编译器报告一致；为反向多留的 g（≈ +32 VGPR）既未触发 spill 也未掉到 1 wave。AGPR=0 说明累加器落统一 VGPR 池，R2 设计期担忧的「g 叠加在独立 AGPR 累加器之上」最坏情形未出现。

4  设计动机小结

  1. 蓝本复用，差异收敛三点：以 FMHA kr_ktr_vr 为结构蓝本，LDS 布局 / shuffle / early-exit 全沿用；HSTU 的不同只压在 STAGE2（p,g）、STAGE5（ds=dp·g）、收尾缩放三处（pipeline:13-33）。
  2. policy 零覆写（R1）：默认模板实参就是 BlockFmhaBwdPipelineDefaultPolicy，dsilu/elementwise 与 policy 寄存器分布兼容，省掉一整层派生。
  3. 双缩放轴，必须自写 kernel：FMHA kargs 只能带单 raw_scale，HSTU 需 alpha+scale_p 两个，故自写 HstuAttentionBwdDQDKDVKernel 携双标量（kernel:74-75）。
  4. dV 不乘 alpha（易错点）：链式法则上 dV 不经 s，只 dQ/dK 末尾各乘一次 alpha（pipeline:493-512）。
  5. dQ float 累加 + 末段 convert：atomic 路 nsplits=1 走 float dq_acc 累加，POST 纯 elementwise cast 成 bf16，保数值精度；deterministic reduce+convert 留 M6。
  6. 闸门即门票：harness 退出码改 pass?0:-2（harness:507），R1+R2 实测闭环——后续 M2–M8 才敢在此基座上增量。
