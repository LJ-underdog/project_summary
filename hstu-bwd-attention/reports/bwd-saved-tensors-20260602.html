Attention Backward 到底要从 Forward 存哪些副产物？

为什么反向传播需要前向算过的某些量？为什么 O / LSE / D 的"存不存"是激活函数相关的——softmax 路径必须存 O，SiLU 路径却不用。从零推导那一个"啊哈"时刻。

适合：懂一点神经网络、但不熟 attention 反向传播推导的工程师
起因：报告 ck-vs-hstu-bwd-20260529.html 符号表里一格 — O | Forward 输出 | 必存(FMHA) | 仅 softmax 路径必存(HSTU)  ·  2026-06-02
TL;DR — 那一格怎么读

反向传播按链式法则倒着算梯度，会用到前向算过的一些中间量。但 attention 的中间矩阵 S、P 大到 O(S²)（几十 GB），放不下，所以策略是：只存极少量的小东西，其余在 backward 里重算。候选小副产物只有三个：O、LSE、D。

关键："存不存"取决于激活函数。 softmax 路径的反向里藏着一项 row-sum ρ，它能神奇地化简成 D = rowsum(O⊙dO) — 算它就必须有前向输出 O。SiLU 是逐元素激活，反向根本没有这一项，于是 O / LSE / D 全都不需要。

所以那一格：FMHA 永远走 softmax → O 必存；HSTU 有两条路径，只有走 softmax 时才像 FMHA 一样需要 O，默认的 SiLU 路径不需要。

1. 为什么 backward 需要 forward 的中间量？

先建立直觉。训练时，前向（forward）算出 loss，反向（backward）从 loss 出发、沿计算图倒着把梯度一层层传回每个输入。

链式法则的本质是：要算某一步的梯度，往往得用到那一步前向时的输入或输出。最简单的例子，y = a·b，那么 ∂L/∂a = ∂L/∂y · b — 算 a 的梯度需要 b 的前向值。attention 也一样：反向要用到前向算过的 S（注意力分数）、P（激活后的权重）、O（输出）等。

问题：把中间矩阵全存下来，存不下

attention 的中间量里，S 和 P 都是 [seqlen_q × seqlen_kv] 的方阵，大小是 O(S²)（S 指序列长度）。序列一长，它就爆炸：

一个数字感受一下： seqlen = 8K、batch = 4、head = 32、fp16。单看 S 矩阵：4 × 32 × 8192 × 8192 × 2 bytes ≈ 16 GB。P 再来一份。一张卡的显存就这么被一个中间矩阵吃光了 — 显然不能为了 backward 把它们留着。

解法：只存小东西，大东西重算（这就是 FlashAttention 的核心取舍）

既然 O(S²) 的 S/P 存不起，那就不存它们；反向需要时，再用前向存下的小量 + 原始输入 Q,K,V 临时重算。代价是多算一遍，收益是省下海量显存与带宽 — 这笔账在 GPU 上非常划算。

于是问题收敛成：到底要存哪几个"小东西"？ 候选只有三个，全都是 O(S·d) 或 O(S) 级别的小量：

候选 1
O — 前向输出
形状 [S, d]，O(S·d)。每个 query 一个 d 维输出向量。它本来就是前向要返回给用户的结果，"顺手"存下成本低。
候选 2
LSE — log-sum-exp
形状 [S]，每行一个标量，O(S)。softmax 的归一化常数的对数，存它能让反向一趟恢复 P。
候选 3
D — rowsum(O⊙dO)
形状 [S]，每行一个标量，O(S)。它不是前向产物，而是反向开始时用 O 和 dO 算出来的辅助量。下面会看到它是关键。

接下来两节分别看 softmax 路径和 SiLU 路径，会发现这三个量"要不要"完全由激活函数决定。

2. softmax 路径的 D-trick — 理解"O 必存"的钥匙

这一节是全文的"啊哈"时刻。我们会一步不跳地推导出：softmax 反向里那个 row-sum 项，恰好等于 O 和 dO 的逐行点积。正因如此，softmax 路径必须从前向存下 O。

2.1 前向回顾

softmax 路径（标准 attention / FMHA）的前向，每一行 query i：

S_ij = scale · (Q_i · K_j) 注意力分数（O(S²) 矩阵） P_ij = exp(S_ij − LSE_i) 行内归一，每行 ∑_j P_ij = 1 O_i = ∑_j P_ij · V_j 输出（O(S·d) 向量） LSE_i = log ∑_j exp(S_ij) 归一化常数的对数（O(S) 标量）

P_ij = exp(S_ij − LSE_i) 这一步值得停一下：前向已经算好每行的 LSE_i，反向时只要再算一遍 S，就能一趟直接恢复 P，不必像标准 softmax 那样先求 max、再求 sum 跑两趟。这正是存 LSE 的价值。

2.2 反向核心公式

对 softmax 求导（标准结果，推导略），得到 dS 的形式：

dP_ij = ∑_d dO_id · V_jd (= dO @ Vᵀ) dS_ij = P_ij · (dP_ij − ρ_i) 其中 ρ_i = ∑_j P_ij · dP_ij ← 一个跨 j 的 row-sum 项

注意 ρ_i（读作 rho）：它是对一整行的 P_ij · dP_ij 求和。这个 row-sum 正是 softmax 反向区别于逐元素激活的地方 — 它来自 softmax 的归一化（每行和=1 这个约束让所有 j 互相耦合）。

2.3 插曲：dP = dO · Vᵀ 这步是怎么来的

上面那行 dP_ij = ∑_d dO_id·V_jd (= dO @ Vᵀ) 常让人卡住：为什么是 dO 乘 V 的转置？是不是写错了？这一节把它一步步推出来 — 公式没错，只是前面只写出没推导。下一节的化简会直接用到它，所以先把它讲透。

① 先回顾前向 O = P·V 的逐元素形式

把三个矩阵的形状摆清楚（行在前、列在后）：

P : [Sq, Sk] 行 = query i，列 = key j → P_ij V : [Sk, d] 行 = key j，列 = 维度 d → V_jd（第 j 个 key 的第 d 维） O : [Sq, d] 行 = query i，列 = 维度 d → O_id O_id = ∑_j P_ij · V_jd 每个输出 = 用 P 的一行，对所有 key 加权求和 V

② 链式法则推 dP_ij

dP_ij 是 ∂L/∂P_ij — 即"P_ij 这一格变一点，loss 变多少"。关键观察：P_ij 出现在 O_id 里，而且对所有 d 都出现（看上面 O_id = ∑_j P_ij·V_jd，固定 i、对每个 d，求和里都有 P_ij 这一项）。所以梯度要把所有 d 的贡献加起来：

dP_ij = ∂L/∂P_ij = ∑_d (∂L/∂O_id) · (∂O_id/∂P_ij) 链式法则，对所有受影响的 O_id 求和 = ∑_d dO_id · V_jd 因为 ∂O_id/∂P_ij = V_jd

为什么 ∂O_id/∂P_ij = V_jd？因为 O_id = ∑_{j'} P_{ij'}·V_{j'd} 对 P_ij 求导时，求和里只有 j'=j 那一项含 P_ij，留下系数 V_jd，其余项导数为 0。所以 dP_ij = ∑_d dO_id·V_jd 完全正确。

③ 为什么矩阵形式要写成 dO @ Vᵀ

这是最容易卡住的一步。矩阵乘法的本质是"对中间那个维度求和"：[A,B]·[B,C] = [A,C]，被消掉的是中间的 B。我们这里要对 d 求和，所以 d 必须站在两个因子的"中间位置"才能对齐：

  • dO 形状 [Sq, d]，d 在第二维（列）。
  • V 形状 [Sk, d]，d 也在第二维（列） — 两个 d 都在列，没法直接相乘（中间维对不上）。
  • 把 V 转置成 Vᵀ : [d, Sk]，d 翻到第一维（行）。现在 [Sq, d]·[d, Sk] = [Sq, Sk]，正好是 dP 的形状，中间的 d 被求和消掉。

取出结果的 (i,j) 元素验证一下，和逐元素公式一字不差：

(dO @ Vᵀ)_ij = ∑_d dO_id · (Vᵀ)_dj = ∑_d dO_id · V_jd ✓
Sq / Sk（序列维，保留） d（被求和消掉的中间维）

图 D：矩阵乘消掉中间维 d — 把 V[Sk,d] 转置成 Vᵀ[d,Sk] 让 d 落到中间位置，dO[Sq,d]·Vᵀ[d,Sk] 沿 d 求和得到 dP[Sq,Sk]。转置不是笔误，是让求和维对齐的必然操作。

一句口诀： 任何 C = A·B 的反向都只有两条 — dA = dC·Bᵀ、dB = Aᵀ·dC。套到 O = P·V 就是 dP = dO·Vᵀ 和 dV = Pᵀ·dO。所以那个 Vᵀ 不是笔误，是矩阵求导规则里必然出现的转置。
澄清两个常见误解：（1）V_jd 不是 V 的转置，它就是 V 本身第 j 行、第 d 列的那个数；转置只发生在写成矩阵乘 Vᵀ 的时候，目的是让求和维 d 对齐。（2）逐元素写法 ∑_d dO_id·V_jd 与矩阵写法 dO @ Vᵀ 是同一东西的两种记法，不矛盾 — 前者讲"每个格子怎么算"，后者讲"整块怎么一次算完"。

2.4 dS 这步：softmax 的 Jacobian 反向

§2.2 直接写出了 dS_ij = P_ij·(dP_ij − ρ_i) 却没推导，很多人卡在这里。这一节把 dP → dS 从 softmax 的导数一步步推出来 — 你会看到那个 ρ_i 不是凭空冒出来的，而是 softmax 整行耦合的必然产物。

① softmax 定义与关键性质

P_ij = e^{S_ij} / ∑_k e^{S_ik} 分母是整行求和 ∑_j P_ij = 1 每行归一

关键点：P 的整行都依赖 S 的整行 — 因为分母 ∑_k e^{S_ik} 把同一行所有 S_ik 都搅进来了。所以挪动一个 S_ij，会同时影响这一行每一个 P_ik。这与逐元素激活（动 S_ij 只影响 P_ij 自己）形成根本对立，也正是 ρ_i 的来源。

② softmax 的 Jacobian

对 softmax 求偏导，标准结果是（δ_kj 是 Kronecker delta，k=j 时为 1、否则为 0）：

∂P_ik / ∂S_ij = P_ik · (δ_kj − P_ij) 对角项 (k = j): P_ij · (1 − P_ij) 自己对自己 非对角 (k ≠ j): − P_ik · P_ij ← 整行互相耦合的来源

非对角项 −P_ik·P_ij 就是"动一个 S_ij 会拉低同行其它 P_ik"的数学表达（归一化是零和的：一个涨，别的就得跌）。

③ 链式法则逐步推 dS_ij

S_ij 影响了整行 P_ik，所以梯度要对 k 求和（把所有受影响的 P_ik 的贡献收齐）：

dS_ij = ∑_k dP_ik · ∂P_ik/∂S_ij = ∑_k dP_ik · P_ik · (δ_kj − P_ij) 代入 Jacobian = ∑_k dP_ik·P_ik·δ_kj − ∑_k dP_ik·P_ik·P_ij 拆成两项 = dP_ij·P_ij − P_ij·∑_k P_ik·dP_ik δ_kj 只留 k=j；P_ij 提出 = P_ij · ( dP_ij − ρ_i ) 其中 ρ_i = ∑_k P_ik·dP_ik

逐行说明：

  • 第 2→3 步： 把括号 (δ_kj − P_ij) 拆开，分配到求和里，得到两项。
  • 第 3→4 步： 第一项里 δ_kj 让求和只剩 k=j 一项 → dP_ij·P_ij；第二项里 P_ij 与求和哑标 k 无关，提到 ∑_k 外面。
  • 第 4→5 步： 提出公因子 P_ij，并把那个 row-sum ∑_k P_ik·dP_ik 记作 ρ_i（哑标 k 与 §2.2 里的 j 等价，只是换个字母）。

这就推回了 §2.2 那行 dS_ij = P_ij·(dP_ij − ρ_i)，无误。

ρ_i 的本质： 它正是 softmax Jacobian 那些非对角耦合项 −P_ik·P_ij 求和后的产物。逐元素激活（如 SiLU）的 Jacobian 是纯对角的 — 非对角全是 0 — 于是这一项根本不存在，也就没有 ρ_i。这就是"softmax 反向区别于逐元素激活"的精确含义。下一节（§2.5）会进一步把这个 ρ_i 化简成 dO_i·O_i，从而引出"为什么要存 O"。
有值（对角） 有值（非对角耦合） 恒为 0

图 E：softmax 的 Jacobian 是满矩阵——对角项 P_ij(1−P_ij) 外，非对角 −P_ik·P_ij 也非零，行内全耦合，求和后产生 ρ；逐元素激活（SiLU）的 Jacobian 只有对角线，非对角恒 0，没有 ρ。

2.5 关键化简：ρ_i = dO_i · O_i

直接算 ρ_i = ∑_j P_ij·dP_ij 需要把 O(S²) 的 P、dP 整行摊开。但我们可以把它化简掉。每一步都列出来：

ρ_i = ∑_j P_ij · dP_ij = ∑_j P_ij · (∑_d dO_id · V_jd) 把 dP_ij = dO_i · V_j 代入 = ∑_d dO_id · (∑_j P_ij · V_jd) 交换求和顺序，把 dO_id 提出 = ∑_d dO_id · O_id 因为 ∑_j P_ij·V_jd = O_id（前向定义！） = dO_i · O_i = rowsum(O ⊙ dO) =: D_i

逐行翻译这四步：

  • 第 1→2 步： 把 dP_ij = ∑_d dO_id·V_jd 原样代入。
  • 第 2→3 步： 交换两个求和符号的顺序（∑_j 和 ∑_d 都是有限和，可以随便换），并把只跟 d 有关的 dO_id 提到 ∑_j 外面。
  • 第 3→4 步（关键）： 括号里的 ∑_j P_ij·V_jd 正好就是前向输出 O_id 的定义！直接替换。
  • 第 4→5 步： 剩下的 ∑_d dO_id·O_id 就是向量 dO_i 和 O_i 的点积，也即逐元素相乘再按行求和 — 记作 D_i。
啊哈时刻

那个看起来要摊开整个 O(S²) 矩阵才能算的 row-sum ρ_i，竟然等于 D_i = dO_i · O_i — 只用前向存下的 O（O(S·d)）和反向输入 dO 就能算，完全不碰巨大的 P / dP。

所以：正因为反向要算 D，softmax 路径的 backward 必须从 forward 存下 O。 这就是符号表里"O 必存"那一格的根。

图 A：朴素地算 ρ_i 要遍历 O(S²) 的整行 P·dP；化简后等价于 O 与 dO 的逐行点积，只碰 O(S·d) 的两个短向量。

2.6 代码印证：FMHA 的 95 行 PRE-pass kernel

在标准 FMHA 的 GPU 实现里，算 D 这件事被独立成一个前置 kernel（pre-pass），它唯一的活就是 D = rowsum(O ⊙ dO)，算好后喂给主反向循环。整个文件只有 95 行：

// ck/include/ck_tile/ops/fmha/pipeline/block_fmha_bwd_dot_do_o.hpp (全文 95 行) // 对每个 (sq, head)：把 O 和 dO 这两块加载进来，逐元素相乘后按 d 维求和 sweep_tile_span(o_spans[number<0>{}], [&](auto idx0) { // 行 (sq) 方向 sweep_tile_span(o_spans[number<1>{}], [&](auto idx1) { // 列 (d) 方向 d(i_idx) += (type_convert<DDataType>(o[i_j_idx]) * // D_i += O_id * dO_id type_convert<DDataType>(do_[i_j_idx])); }); }); tile_elementwise_inout([&p_undrop](auto& x){ x = x * p_undrop; }, d); // dropout 缩放 store_tile(d_dram_block_window_tmp, d); // 写回 D

结构和我们推导的 D_i = ∑_d O_id·dO_id 一字不差。FMHA 把它单拎出来做 pre-pass；HSTU 的 CPU reference 则把它内联在主循环里（见下文）。

3. SiLU 路径（HSTU 默认）为什么不需要 O

同样一套反向，把激活从 softmax 换成 SiLU，那个 row-sum 项就消失了 — 于是 D 不需要，O 不需要，LSE 也不需要。差别全在"激活是不是逐元素的"。

3.0 先消一个反直觉：省 O ≠ 省 dO

常有人一听"SiLU 连 O 都不需要"就懵："那它的 loss 从哪来？输出都不要了，还怎么训练？" 这是把两个不同的东西搞混了 — 先把它掰开。

一句话消解

"SiLU 不需要 O" 指的是 反向不必回读前向存下的 O 数值，不是说 O 不产生 loss。loss 照样从 O → 下游 → Loss 来；梯度照样从 dO = ∂L/∂O 这个入口进。被省掉的只是"反向时再翻一遍 O 的旧值"这项需求 — 而不是 O 本身、更不是 dO。

O 和 dO 是两回事

O = P · V 前向输出的数值；继续往下游走，最终算出 Loss dO = ∂L/∂O loss 对 O 的梯度；反向传到本块时，上游交给我们的输入

关键：dO 才是 loss 在反向里的"来处"——它是整个 backward 的入口，两条路径都一直在用，谁也没省。被省的是 O 这个前向数值的存档：softmax 反向要回读它（算 D），SiLU 反向压根不碰它。省"O 的存档" ≠ 省"dO 这个梯度入口"。

SiLU 反向到底用了谁

逐步看 SiLU 反向每一步的输入，O 的数值一次都没出现：

步骤公式用到 O 的数值吗
dVPᵀ · dO❌ 否（用 P、dO）
dPdO · Vᵀ❌ 否（用 dO、V）
dSdP · scale_p · dsilu(S)❌ 否（用 dP、重算的 S）
dQ / dKα·dS·K / α·dSᵀ·Q❌ 否（用 dS、Q、K）

整条 SiLU 反向 O 的数值一次没出现 → 前向把 O 喂给下游后即可丢弃，不必存档回读。而 dO 在第一、二步就用上了，全程在线。对比 softmax：它多一步 D = rowsum(O⊙dO) 必须回读 O（见 §2.5），所以 softmax 才必存 O。

O 的数值（前向产生 loss） dO 梯度入口（两路都用） 仅 softmax：回读 O 算 D

图 F：前向 O 的数值一路产生 loss；反向 dO=∂L/∂O 是入口、两条路径都用。softmax 多一条红色虚线"回读 O 算 D"，SiLU 没有这条 — 省掉的正是这条回读，而非 dO。

一个类比： O 像接力选手把棒（输出）往前传，跑出成绩（loss）；回来时收到一张"修正单"（dO）。softmax 的反向算法额外要翻"当时 O 是多少"（O⊙dO）；SiLU 只看修正单 dO + 重算的 S/P 就够。修正单 dO 始终在手，被省的是"O 的那份存档"。

3.1 前向：SiLU 是逐元素激活，行内不归一

S_ij = alpha · (Q_i · K_j) P_ij = silu(S_ij) · scale_p silu(x) = x · σ(x)，逐元素，行内不归一 O_i = ∑_j P_ij · V_j

注意和 softmax 的根本区别：P_ij = silu(S_ij)·scale_p 只依赖自己这一格的 S_ij，跟同一行其它 j 毫无关系（softmax 的每个 P_ij 则依赖整行，因为分母是整行的和）。没有归一化 = 没有跨 j 的耦合。

3.2 反向：Jacobian 是对角的，没有 row-sum

因为激活逐元素，∂P_ij/∂S_ij' 只在 j=j' 时非零（数学上叫"Jacobian 是对角矩阵"，对照 §2.4 图 E 右边那张只有对角线的图）。链式法则直接逐格相乘，不产生任何跨 j 的求和项。下面把结果一步步推出来。

① 先推 dsilu(x)

SiLU 定义 silu(x) = x·σ(x)，其中 sigmoid σ(x) = 1/(1+e^{−x})。它是两个函数 x 与 σ(x) 的乘积，用乘积法则 (uv)' = u'v + uv'（取 u=x、v=σ(x)）：

silu'(x) = (x)'·σ(x) + x·σ'(x) = σ(x) + x·σ'(x) 代入 sigmoid 导数 σ'(x) = σ(x)·(1 − σ(x))： = σ(x) + x·σ(x)·(1 − σ(x)) 提出 σ(x)： dsilu(x) = σ(x)·(1 + x·(1 − σ(x)))

这正好对上文档与源码里那行 dsilu(x) = σ(x)·(1 + x·(1 − σ(x)))（reference_hstu_attention_bwd.hpp:152-156）。

② 再推 dS_ij

前向 P_ij = silu(S_ij)·scale_p 是逐元素的：P_ij 只依赖 S_ij 这一个元素，不碰同行其它格子。所以链式法则不对其它项求和（与 §2.4 softmax 那条要对整行 k 求和形成鲜明对比）：

dS_ij = dP_ij · ∂P_ij/∂S_ij = dP_ij · scale_p · silu'(S_ij) scale_p 是常数，提出 = dP_ij · scale_p · dsilu(S_ij) (masked-in) = 0 (masked-out, 显式置零，见下)

对比 softmax 的 dS_ij = P_ij·(dP_ij − ρ_i)：SiLU 这条没有 ρ_i / D_i 那一项 — 因为逐元素 → Jacobian 纯对角 → 无行耦合 → 没有那个 row-sum。既然反向用不到 D，那也就不需要 O（O 的唯一作用就是喂 D-trick），同样也不需要 LSE（LSE 是 softmax 恢复 P 用的）。

③ masked-out 为什么必须"显式"置零

关键在"显式"二字。 masked-in 的格子用上面公式算 dS；masked-out 的格子不该有梯度流过，dS 必须等于 0。问题是怎么变成 0：
• softmax 能自然清零：masked 处令 S = −∞ ⇒ P = exp(−∞ − LSE) = 0，前向后向都自动归零，不用特判。
• SiLU 不能：dsilu 在任何点都不会"恰好抹掉梯度"。例如 dsilu(0) = σ(0)·(1 + 0) = 0.5 ≠ 0。若放着不管，在 masked 位置套公式会算出非零的 dS = dP·scale_p·0.5，污染 dQ / dK。
所以代码必须在 masked-out 位置手动写 dS = 0（前向同样要手动把 P 置 0），不能像 softmax 那样指望它自动消失。这与 §3.4「小坑」讲的是同一件事的一体两面：前向 silu(0)·scale_p ≠ 0 与反向 dsilu(0) = 0.5 ≠ 0，都源于 SiLU 没有"−∞ 自然归零"这个性质。

3.3 代价转移到哪了？

SiLU 路径省了 O / LSE / D，但有个代价：要算 dsilu(S_ij) 就必须有 S_ij — 所以得重算 S。不过别急着记成"额外开销"：

softmax 路径其实也要重算 S（它要 S 才能恢复 P = exp(S − LSE)）。所以"重算 S"是两条路径共同的成本，不是 SiLU 独有的。SiLU 真正省下的是：① O 的读带宽，② LSE 的存储与读带宽。

3.4 一个小坑：silu(0)·scale_p ≠ 0

masked-out 位置的清零问题。 softmax 路径里，被 mask 掉的格子设 S = −∞，于是 exp(−∞ − LSE) = 0，自然清零。但 SiLU 不行：silu(0)·scale_p ≠ 0，给个 0 进去出来不是 0。所以 SiLU 路径必须显式把 masked-out 的 S（或 dS）置 0，不能靠激活自己归零。
// reference_hstu_attention_bwd.hpp // 前向重算 S 时，masked-out 位置：SiLU 置 0，softmax 置 -inf (line 274-279) if constexpr(!kUseSoftmax) locals_S[sk] = type_convert<CompDataType>(0.0f); // SiLU: 显式 0 else locals_S[sk] = -ck_tile::numeric<CompDataType>::infinity(); // softmax: -inf // 算 dS 时，SiLU 的 masked-out 也要显式置 0 (line 380-385) if(mask.IsTokenPairInsideMask(sq, sk)) locals_dS[sk] = locals_dP[sk] * scale_p * dsilu(locals_S[sk]); else locals_dS[sk] = type_convert<CompDataType>(0.0f); // 显式清零

4. 三个副产物的路径对照表

把前面三节归纳成一张表。颜色约定：clay = softmax 路径 / FMHA，olive = SiLU 路径 / HSTU 默认。

副产物是什么 softmax 路径 SiLU 路径
O 注意力输出 [S, d]，前向本就要返回 必存 — 喂 D-trick（D = dO·O） 不需要
LSE log ∑_j exp(S)，每行一个标量 [S] 必存 — 反向用 P = exp(S−LSE) 单趟恢复 P 不存不读
D rowsum(O⊙dO)，每行一个标量 [S] 需要 — FMHA 走独立 PRE-pass kernel；HSTU 走主循环 inline 不需要（没有 row-sum 项）
S / P 分数 / 权重矩阵 [S, S]，O(S²) 都不存 — O(S²) 太大，反向里从 Q,K(,LSE) 重算
一句话记忆： 大矩阵（S/P）一律重算；小量（O/LSE/D）是否存，取决于激活函数有没有那个 row-sum 项 — softmax 有 → 三个都要；SiLU 没有 → 三个都不要。

5. 回到那一格：精确解读

报告符号表里那行 O | Forward 输出 | 必存(FMHA) | 仅 softmax 路径必存(HSTU)，现在可以逐列拆开了。

FMHA 那列
"O 必存"
FMHA 永远走 softmax，没有别的路径。softmax 反向必算 D，D 必用 O → 所以 O 一定要存。无条件。
HSTU 那列
"仅 softmax 路径必存"
HSTU 有 两条路径。走 softmax（kUseSoftmax=true）时和 FMHA 一样需要 O；走默认的 SiLU 路径时不需要 O。
为什么是"激活路径相关"
钥匙是 row-sum
softmax 的归一化制造了 row-sum 项 → D → O；SiLU 逐元素、无 row-sum → 无 D → 无 O。存不存 = 激活有没有耦合。
两条路径都要 仅 softmax 路径额外需要

6. 延伸：kStoreLSE 这个"接线柱"

既然 LSE 只有 softmax 路径才需要，前向就不应该无脑把它写回显存。HSTU 前向为此加了个模板开关 kStoreLSE。

kStoreLSE 是 HSTU 前向侧的一个模板形参（编译期布尔），控制前向算完 LSE 之后要不要写回 DRAM（显存）。它和本文的第 2、3 节直接相关：

  • 走 softmax 路径且未来要做反向 → LSE 反向有用 → 应 kStoreLSE=true，把它存下来。
  • 走默认 SiLU 路径 → 反向根本不读 LSE → kStoreLSE=false，连存都省了。
当前 branch 的状态： 前向的所有 caller 目前一律传 kStoreLSE=false（18_hstu_attention 下 6 个 dispatch 文件共 9 处实例化，无一例外）— 因为 GPU 反向还没上线，且默认的 SiLU 路径本来就不需要 LSE。等到 softmax 路径的 GPU 反向真正落地，才会有 caller 切到 true。所以现在它是一个预留的接线柱：线已经接好，开关暂时关着。
一个无效组合： kStoreLSE=true && kUseSoftmax=false。意思是"走 SiLU 路径、却又要存 LSE" — SiLU 路径根本不产生也不需要 LSE，存它没有意义。这个组合在语义上是矛盾的，不应出现。

7. Q&A

S 和 P 为什么不存？
它们是 O(S²) 的大方阵，序列一长就几十 GB，显存放不下。而且它们能从 Q, K（softmax 还需 LSE）重算出来，重算的算力开销远小于存它们的显存与带宽开销。
重算 S 不是很慢吗？
每个 (sq, sk) 格子要多做一次 Q·K 点积（hdim 量级的 FLOP）。但换来的是省下海量显存占用和显存读写带宽 — 在 GPU 上后者才是瓶颈。这种"用算力换带宽"正是 FlashAttention 的核心取舍。
为什么 FMHA 给 D 单开一个 kernel，HSTU 却放主循环里？
纯实现选择。FMHA 用独立 PRE-pass kernel（block_fmha_bwd_dot_do_o.hpp，95 行）把 D 解耦出来，便于调度和复用；HSTU 的 CPU reference 图简单，直接 inline 在主反向循环里算（reference_hstu_attention_bwd.hpp line 390-413）。两者算的是同一个 D = rowsum(O⊙dO)。
SiLU 路径既然不存 LSE / O，是不是整体更省？
反向确实省了读 O 和 LSE 两块的带宽，也省了前向写 LSE。但它仍然要重算 S（softmax 也要重算，这点打平）。净收益是"少读两块东西"— 带宽更省，不是免费午餐。
那 dO 为什么不用"存"？
因为 dO = ∂L/∂O 是上游传下来的梯度，它本来就是反向传播的输入，由计算图的下一层提供，不属于"前向要不要保存"的范畴。O / LSE / D 才是前向需要决定存不存的副产物。
