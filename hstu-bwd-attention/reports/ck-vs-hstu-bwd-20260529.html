TL;DR

两者在 dV = Pᵀ dO / dP = dO Vᵀ / dQ = α·dS K / dK = α·dSᵀ Q 四步 GEMM 上结构一致。最关键差异：HSTU 默认激活是 SiLU 而非 softmax，这条直接波及 LSE 依赖、是否重算 S、mask 是否能自然清零、scale 参数数量。

1.2 标准 Softmax Backward 推导

从 O = PV 与 softmax Jacobian 出发，得到 5 条公式；关键是把 row-sum ρ 化简成 D。

dVkd = ∑i Pik dOid -- GEMM: Pᵀ @ dO dPij = ∑d dOid Vjd -- GEMM: dO @ Vᵀ dSij = Pij (dPij - ρi), ρi = ∑k Pik dPik 化简: ρi = ∑d dOid Oid = Di dQid = scale · ∑j dSij Kjd -- GEMM: dS @ K dKjd = scale · ∑i dSij Qid -- GEMM: dSᵀ @ Q
关键 trick：用 P = exp(S - LSE) 单次恢复 P（无需 two-pass softmax），masked-out 位置 S=-∞ ⇒ P=0 自然清零；D 用独立 pre-pass kernel block_fmha_bwd_dot_do_o.hpp 算好喂主循环。

1.3 HSTU SiLU Backward（新）

HSTU 默认路径。激活变成 element-wise 的 silu(x)·scale_p，反向需要 dsilu(S)，必须重算 S。

Chain rule： ∂L/∂S = (∂L/∂P) · (∂P/∂S) = dP · ∂(silu(S) · scale_p) / ∂S = dP · scale_p · dsilu(S)

Pij = silu(Sij) · scale_p, silu(x) = x · σ(x) dSij = dPij · scale_p · dsilu(Sij) (masked-in) = 0 (masked-out, 显式置零) dsilu(x) = σ(x) · (1 + x · (1 - σ(x))) 
// reference_hstu_attention_bwd.hpp:145-156
auto silu = [&](CompDataType x) {
  return x / (one + std::exp(-x));
};
// dsilu/dx = sigmoid(x) * (1 + x*(1 - sigmoid(x)))
auto dsilu = [&](CompDataType x) {
  CompDataType sig = one / (one + std::exp(-x));
  return sig * (one + x * (one - sig));
};
SiLU 路径三个关键点：(1) 不读 LSE，fwd 也无需保存 LSE 张量，节省 [B, Sq, H] fp32；(2) 必须重算完整 S 才能算 dsilu(S)（element-wise 非线性，无法从 P 反推）；(3) mask-out 位置 silu(0)·scale_p ≠ 0，不能像 softmax 那样靠 exp(-∞)=0 自然清零，必须显式 if-else（参见 §3.6）。
数值稳定性：x → -∞ 时 std::exp(-x) → +∞，依赖 IEEE-754 1/inf = 0 自然衰减；x → +∞ 时 (1-σ)e^{-x} 双向衰减更快，结果 → 1。当前实现未做 clamp，与 GPU kernel 对拍时需保持同一 naive 形式。

1.4 HSTU Softmax Backward（与标准基本一致）

kUseSoftmax=true 时与标准 FMHA bwd 在数学上完全相同；仅实现细节有差异。

Pij = exp(Sij - LSEi) (LSE 来自 fwd, line 295-310) Di = ∑d dOid Oid (主循环内 inline, line 391-411) dSij = Pij (dPij - Di)
与 FMHA 的差异：① 没有 base-2 exp2 优化（reference 用 std::exp）；② D 是主循环内每个 sq inline 算，不是独立 pre-pass kernel；③ masked-out 处仍用 S=-∞ 自然清零（line 274-278）；④ LSE=-∞ 时整行 P 显式置 0 防 NaN（line 301-304）。

3.3 SiLU 路径实现

// reference_hstu_attention_bwd.hpp:282-287, 376-387
if constexpr(!kUseSoftmax) {
  for(int sk = 0; sk < seqlen_kv; sk++)
    locals_P[sk] = silu(locals_S[sk]) * scale_p;
}
// ... later, Step 4 (SiLU branch)
for(int sk = 0; sk < seqlen_kv; sk++) {
  if(mask.IsTokenPairInsideMask(sq, sk))
    locals_dS[sk] = locals_dP[sk] * scale_p * dsilu(locals_S[sk]);
  else
    locals_dS[sk] = 0.0f;          // 必须显式置零
}
SiLU 路径全貌：(1) Step 1 算 P = silu(S)*scale_p；(2) Step 4 用 dsilu(S) 算 dS，masked-out 显式置 0。重算 S 的代价：每 (sq, sk) 一次 Q·K dot 共 hdim_qk FLOP；vs softmax 路径同样要重算 S，所以 SiLU 路径并不额外增加 GEMM 量，只多了 element-wise 一个 exp。

fwd 侧 problem 模板新增的 bool 形参，控制「计算完每行 softmax LSE 后是否写回 DRAM」。

4.4 三个关键差异 callout

DIFFERENCE 1
SiLU 路径需重算 S
SiLU 是 element-wise 非线性，dsilu(S) 必须从原 S 取值；无法像 softmax 那样仅靠 P 反推。代价：每 (sq, sk) 多一次 Q·K 重算；收益：省去 [B, Sq, H] fp32 的 LSE 存储与读带宽。
DIFFERENCE 2
HSTU bwd 暂无 GPU kernel
当前 branch 仅 855 行 CPU reference + fwd 侧 kStoreLSE 接线柱。GPU 路径需基于 FMHA bwd 体系（4800+ LoC）扩展 SiLU 分支 + HSTU 5-因子 mask + jagged/group 索引。预计单独工作量约 1.5-2× FMHA bwd。
DIFFERENCE 3
Mask 组合数 5 vs 2
FMHA: causal / sliding-window；HSTU: causal + contextual_seqlen + local window + num_targets + cross/self 五因子。通过 BOOL_SWITCH_2(kHasLocal, kIsCross) 双层编译期分派 + HstuBlockMasking 模板特化，bwd 必须复用 fwd 同一组工厂保等价。

5.3 常见问题

HSTU 为什么 SiLU 路径不需要 LSE？
SiLU 是 element-wise 非线性（P = silu(S)·scale_p，无 row-wise 归一），反向 dS = dP·scale_p·dsilu(S) 只依赖原 S 与 dP；既无需「单趟恢复 P」也不存在 softmax 那种 row-sum 项。fwd 因此可以不存 LSE，bwd 直接重算 S。Softmax 路径则与标准 FMHA 一样需要 LSE。
kStoreLSE 当前 branch 全传 false，那它什么时候启用？
这是为未来 HSTU GPU bwd kernel 预留的「接线柱」。一旦 GPU bwd 上线，Softmax 路径的 fwd dispatch 需切到 kStoreLSE=true 让 LSE 落盘，bwd 直接读；SiLU 路径始终不需要，仍传 false。理论上 kStoreLSE=true && kUseSoftmax=false 是无效组合，但目前未加 static_assert。
HSTU bwd GPU kernel 何时实现？能复用 FMHA bwd 多少？
当前 branch 仅 855 行 CPU reference，GPU kernel 尚未提交，进度可参考 hstu_attention_fwd_bwd branch 的后续 commits。可复用的：FMHA bwd 的 5-GEMM tile 调度、LDS 复用策略、dQ atomicAdd/split-workspace 两路、convert_dq POST kernel 框架。必须重写的：SiLU 路径的 Step 4（含 dsilu(S)）+ HSTU 5-因子 mask 的 block-level skip + jagged/group 寻址 + scale_p 在 Step 1 和 Step 4 的两处乘法。粗估生产代码量 1.5-2× FMHA bwd。
