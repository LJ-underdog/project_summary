HSTU Attention Backward — M6：让 dQ 逐位可复现，atomic 与 deterministic split 两条路

这份文档讲清 M6 如何把 dQ 从 atomic_add 并行归约（顺序不定、非逐位可复现）改造成 deterministic split + 固定序 reduce（bit-reproducible）。重点讲两条路的机制差异、为什么 split 路构造上保证可复现、关键实现（kernel 的 mop 分叉 + split 偏移、固定序 POST、num_splits=grid.x）、以及验证（含 atomic-vs-determ 逐位 diff=0）。范围 = no_group（batched+jagged）× SiLU+softmax。诚实标注 O1：group+determ 现静默走 atomic，待 M6b 修。所有片段引磁盘真实行号（git c79d3296）。

TL;DR — 一句话看懂 M6

dQ 是反向里唯一需要跨 KV-block 累加的梯度（每个 KV-block 都对全体 Q 行有贡献）。此前用 atomic_add 把 N 个 block 的贡献加进一份 dq_acc——并行原子加的完成顺序不定，浮点加不满足结合律，所以结果不逐位可复现。M6 加一条 deterministic 路：每个 KV-block 用 plain store（无 atomic）写进自己专属的 split 副本，再由 POST 按固定升序 Σ_s 归约——无竞争、求和序固定 ⇒ 与 block 调度无关 ⇒ bit-reproducible。

实现极克制：两条 MAIN pipeline 早就有 if constexpr(kIsDeterministic) store_tile else update_tile 分支（M6 未碰 pipeline）。M6 只在 kernel 加 mop = determ ? set : atomic_add + split 偏移、加一个固定序 POST reduce kernel、dispatch 抽 launch_main_and_post + determ 模板轴、entry BOOL_SWITCH_3、generate_instances 加 determ 轴。

1  为什么需要 determinism

反向的 dK / dV 各自只在「自己的 KV-block」内累加（一个 block 写一段 dK/dV，无跨 block 竞争）。但 dQ 不一样：dQ[sq] = α·Σ_sk dS[sq,sk]·K[sk] 要对所有 KV-block 求和——而 grid 是沿 KV 维切块的，每个 block 只持有一段 sk。于是同一个 Q 行的 dQ，是 N 个 KV-block 各算一部分、再加到一起。

atomic_add 为什么不可复现

dq_acc[q] = Σ_{block b} (block b 对 q 的贡献) // N 个 block 都要加到同一个 dq_acc[q] atomic_add：哪个 block 先加、哪个后加 → 由硬件调度决定，每次跑可能不同 float 加法不满足结合律： (a+b)+c ≠ a+(b+c)（舍入不同） ⇒ dQ 的低位 bit 随 block 完成顺序漂移 → 非逐位可复现

对训练复现、回归调试、对拍兜底而言，「同样输入跑两次得到逐位相同的梯度」是刚需——否则无法区分「真 bug」与「浮点顺序噪声」。这就是 M6 要解决的问题。注意：dK/dV 无此问题（无跨 block 累加），所以 M6 只动 dQ。

白话： atomic 路不是「错」，它的梯度数值是对的（已对拍）；它只是「每次低位 bit 可能不同」。M6 的 deterministic 路产出的是同样正确的梯度，额外保证逐位稳定。代价是多一份 split workspace 和一次 POST 归约（perf 取舍）。

2  【图1】atomic 路 vs deterministic split 路

两条路的唯一区别在「N 个 KV-block 的 dQ 贡献怎么汇总」。atomic 路（上）：N 个 block 直接 atomic_add 进一份 dq_acc，顺序不定。determ 路（下）：N 个 block 各 store 进自己的 split 副本（无竞争），POST 再按固定升序归约。

图1：atomic 路（上）N 个 KV-block 竞争 atomic_add 进单份 dq_acc，顺序不定 → 非逐位可复现；deterministic 路（下）每 block store 进专属 split 副本（base += i_tile_n·split_stride），POST 按固定升序 Σ_s 归约 → bit-reproducible。num_splits = KV-block 数 = grid.x。

3  关键实现

M6 的改动集中在三处：kernel 的 dq_acc 窗口（mop 分叉 + split 偏移）、固定序 POST reduce、dispatch 的共享 launch_main_and_post。两条 pipeline 未碰——它们早有 determ 分支。

① kernel：dq_acc 窗口编译期分叉（SiLU L360-386 / softmax L793-810）

hstu_attention_bwd_kernel.hpp · SiLU kernel L363-386（softmax L794-810 同构） auto dq_dram_window = [&, i_tile_n_ = i_tile_n, i_nhead_ = i_nhead]() { // 编译期选 memory_operation:determ=plain store(set);atomic=atomic_add constexpr auto mop = kIsDeterministic ? memory_operation_enum::set : memory_operation_enum::atomic_add; AccDataType* dq_acc_ptr = ...kargs.dq_acc_ptr + i_nhead_*nhead_stride_dq_acc + batch_offset_dq_acc; if constexpr(kIsDeterministic) dq_acc_ptr += static_cast<long_index_t>(i_tile_n_) * kargs.split_stride_dq_acc; // 本 KV-block 的专属 split auto dq_acc_dram = pad_tensor_view( make_naive_tensor_view<address_space_enum::global, mop>(dq_acc_ptr, ...), ...); return make_tile_window(dq_acc_dram, ..., {0, 0}); }();
kernel 的 mop 与 pipeline 的 store/update 严格配对。 pipeline 早有分支：if constexpr(kIsDeterministic) store_tile(dq_dram_window,dq_acc) else update_tile(...)（no_softmax_bwd_pipeline.hpp:523-529、with_softmax:561-567）。store_tile 对应 mop=set（plain 写），update_tile 对应 mop=atomic_add（原子加）。两层一致——这是 M6 「pipeline 不用改」的根因：模式相关的寻址（split 偏移）和 memory_op 都在 kernel 层定好，pipeline 只管把 tile 写出去。

② POST：固定序 reduce-then-convert（L1672-1686）

hstu_attention_bwd_kernel.hpp · hstu_bwd_reduce_convert_dq_kernel L1672-1686 // dq_acc 是 num_splits 份堆叠的单份副本(stride=split_stride)。s 升序求和与 block 调度无关 const long_index_t i = blockIdx.x * blockDim.x + threadIdx.x; if(i >= n) return; float acc = 0.f; for(int s = 0; s < num_splits; ++s) acc += type_convert<float>(dq_acc[static_cast<long_index_t>(s) * split_stride + i]); dq[i] = type_convert<QGradDataType>(acc); // float 累加后才 convert
固定求和序是 bit-reproducible 的核心。 s = 0,1,…,num_splits−1 是编译期固定的升序循环，与哪个 block 先写完无关。每个线程负责一个 flat idx i，串行累加它在所有 split 里的分量。atomic 路则保留原 hstu_bwd_convert_dq_kernel（纯 cast，num_splits 等价 1），未改。

③ dispatch：共享 launch_main_and_post + determ 模板轴（L70-133）

4  为什么 deterministic 路构造上保证可复现

可复现性不是「调出来的」，而是从结构上消除了两个不确定来源：

不确定来源atomic 路deterministic 路
写竞争（多 block 同地址）有：N block atomic_add 同一 dq_acc[q]无：每 block 写自己的 split 副本（plain store）
求和顺序由 block 完成顺序定（每次可能不同）固定：POST s=0..num_splits−1 升序
结果低位 bit 随调度漂移逐位稳定，与调度无关
atomic 的「稳定」只是偶然。 本机实测 atomic 路两次也常常 byte-identical（此规模 HW 原子加顺序未发散）——但那是硬件/规模的偶然，不是契约。换 GPU、换 occupancy、换 seqlen 都可能破。deterministic 路是构造上的保证：无论怎么调度，无 atomic + 固定序 ⇒ 必然逐位相同。这正是 M6 的价值。

6  范围与 O1（诚实标注）

M6 范围 = no_group（batched + jagged）× SiLU + softmax 的 dQ deterministic。group determ 不在本单，是 M6b。这里必须如实说明一个当前行为缺陷 O1。

O1 — group + determ 现「静默走 atomic」，不报错也不可复现（待 M6b 修，HANDOFF 为准）。

O1 根因（源码级，我已独立核到）

两处源码共同导致 O1 // ① group entry 硬编 false、无 determ 轴（hstu_attention_group_backward_bf16.cpp:17-22） BOOL_SWITCH_2(param.use_causal, kUseCausal, param.use_softmax, kUseSoftmax, [&] { run_group_backward_dispatch<bf16_t, kUseCausal, kUseSoftmax, false, false /*kIsDeterministic*/, 64>(...); }); // ② group dispatch 的 throw 是 if constexpr —— 只以 false 实例化 → 该分支编译期裁掉，永不可达 // (hstu_attention_group_backward_dispatch.hpp:318-319) if constexpr(kIsDeterministic) throw std::runtime_error("HSTU bwd: deterministic path not implemented yet (M6)");
