CK · HSTU Backward · cross-attention（seqlen_q ≠ seqlen_kv）实现讲义

HSTU Attention Backward — cross-attention：让 bwd 处理 Q/KV 不同长，办法是「把唯一钉死成 self 的 mask 翻成运行时 cross 开关」

这份文档讲清 cross-attention 里程碑如何把 bwd 从 仅 self（seqlen_q == seqlen_kv）扩到 seqlen_q 与 seqlen_kv 任意（含 jagged/group 的 kv > q）。核心不是写新算法——bwd 在内存 / grid / loop / PRE 层面早就 cross-ready（kv offset 三元组本就接好），唯一真正的破绽是 MASK 被钉死成 self。

把 HstuBlockMasking<false /*cross*/> 翻成运行时 BOOL_SWITCH(is_cross_attention) 选的 kIsCrossAttention 轴、4 个 kernel mask 构造用 if constexpr 分叉到 cross builder（seqlen_kv 喂进 seqlen_k 槽）即可。cross 是运行时开关、不是 instance 轴（零 instance 增长）；CPU reference 本就 cross-ready，一行未改。难点同样不在开关，而在怎么证明没有 silent-wrong——mask 钉死 self 是头号陷阱，等长测试永远抓不到。

TL;DR — 一句话看懂 cross-attention

bwd 的 K/V/dK/dV DRAM view 本就用 kargs.seqlen_kv、grid 本就 kv-tile-major、jagged 每 batch 本就独立拆 q/kv offset、reference oracle 本就接受 is_cross_attention 首参——整条路结构性 cross-ready，唯独 mask 被硬编码成 <false /*cross*/>。若今天强行 is_cross_attention=true，会加载正确的 K/V 但用 self 几何去 mask 它们 ⇒ 数值错、不崩溃。这是头号 silent-wrong 陷阱。

修法镜像 fwd：dispatch 5 处 mask typedef 外包 BOOL_SWITCH(param.is_cross_attention)、kernel 4 个 mask 构造 if constexpr(kIsCrossAttention) 分叉到 make_hstu_cross_attention_block_mask_*（seqlen_kv → seqlen_k 槽，经 wrapper 保参序）。新增唯一字段 max_seqlen_kv 是纯 host 字段（device MakeKargs 不读 ⇒ 设备码不变 = 零回归基石），bwd 是 KV-block-parallel，grid/num_splits 须按它开。pipeline / reference 一行未改（git diff 为空）；不新增 instance（cross 非 codegen 轴）。

1  cross-attention 是什么：让 bwd 处理 seqlen_q ≠ seqlen_kv

self-attention 里 Q 与 K/V 同一条序列（seqlen_q == seqlen_kv）。cross-attention 里 Q 和 K/V 是两条独立序列，长度可不同（如 query 128、kv 256）。本里程碑让 HSTU 的 backward 正确算 dQ/dK/dV，覆盖两个方向（q < kv 与 q > kv，含 jagged/group 的 kv > q）× 全模式（batched / jagged / group）× SiLU+softmax × causal{0,1} × 5 因子 mask × atomic+deterministic × bf16+fp16。

In scope（本里程碑解禁）
seqlen_q ≠ seqlen_kv 任意方向
q < kv（如 128/256）与 q > kv（256/128）双向；no_group jagged / group / batched-uniform 全覆盖；5 因子 mask（causal / window / contextual / min_full / num_target）逐配置。
Out of scope（结构性，诚实标注）
target_in_kv == true
cross mask 硬假设 max_k_uih_len = seqlen_k（注释 // assuming target_in_kv == false，hstu_block_masking.hpp:53,:566）。本里程碑 targets 只在 Q 侧；targets-in-KV 是结构性新路，不做。
Out of scope（留后续）
独立 dO layout（R7）/ 非方形 tile
PRE 用 O 的 stride 读 dO；测试给 dO 与 O 同 layout 规避，独立 dO layout 留后续。非方形 tile 由 M7c 已界定 out-of-scope。
命名警告：本里程碑的 “cross” = cross-attention（Q/KV 不同长）。测试驱动里既有的 “P1-1 cross” / “CROSS MATRIX” 指的是配置笛卡尔积（causal × 因子），与本里程碑同名异义。新增用例一律 xattn- 前缀避免混淆。

2  核心洞察：mask 钉死 self 是唯一真破绽 + 两大利好

结论：bwd 在内存 / grid / loop / PRE 层面已经结构性 cross-ready，唯一真正的破绽是 MASK 被钉死成 self。 下表是「本就做对的」与「唯一缺的」对照。

层cross 是否本就就绪证据
K/V/dK/dV DRAM view就绪 用 kargs.seqlen_kv 不是 seqlen_qbwd_kernel.hpp:320/330（k/v）、:432/442（dk/dv）
jagged 每 batch base就绪 q/kv 各自从自己的 offset delta 求 seqlenquery_start=q_off[i]; key_start=kv_off[i]
grid就绪 kv-tile-major：grid.x = ceil(seqlen_kv/kN0)early-exit i_n0 >= seqlen_kv
kv offset 三元组（dispatch）就绪 is_cross ? kv_off : q_off 早接好batched/group dispatch 都已选
PRE dot_do_o / POST convert就绪 纯 q-seq，本就 cross-safeD=rowsum(O⊙dO) 对 q-sized buffer
CPU reference oracle就绪 已接受 is_cross_attention 首参，独立求两 seqlenreference_hstu_attention_bwd.hpp 一行未改
MASK 几何钉死 self HstuBlockMasking<false /*cross*/>dispatch 5 处 + kernel 4 处 —— 本里程碑唯一要改的行为分叉点

两大利好让这件事「小而稳」

利好 1 · reference 零改
oracle 本就 cross-ready
reference 两个 struct 都已接 is_cross_attention 首参、独立从 q/kv offsets 求两 seqlen、BOOL_SWITCH_2 选 cross mask、调 make_hstu_cross_attention_*。对拍 oracle 一行未改 ⇒ GPU 与 ref 不是「同一份错码自证」。
利好 2 · 零 instance 增长
cross 是运行时 BOOL_SWITCH
镜像 fwd：两腿在同一 .cpp 内编译，generate_instances.py 无 cross 轴。64 个 batched instance + group entry 文件名/数量不变。成本是编译期多实例化一份 mask<true>，不是 instance 数爆炸。
利好的代价（诚实）
group entry TU 变 build 瓶颈
group 已持 local+nolocal 双 pipeline，加 cross 子腿 ⇒ 每 group 入口 {local,nolocal}×{cross,self} = 4 腿，单 TU 实测 14m9s = build 关键路径（R11，per-hdim 拆 TU 留 M8）。

self → cross 数据流与 diff_q_kv_len 对齐

self 只有单个 seqlen，diff_q_kv_len=0；cross 跟踪 diff_q_kv_len = max_k_uih_len − max_q_uih_len = seqlen_kv − (seqlen_q − num_target)（targets 仅 Q 侧,max_k_uih_len=seqlen_kv 不减 num_target,见 §2/§8），在距离比较前对 row 加偏，把 causal 对角线对齐到右下角（hstu_block_masking.hpp:73,:194）。把 seqlen_q 误喂 seqlen_k 槽 ⇒ diff_q_kv_len=0 ⇒ self 几何静默复活（这正是 R1/R2 反证要锁的洞）。

dispatch：mask typedef 外包 BOOL_SWITCH（镜像 fwd）

hstu_attention_batched_backward_dispatch.hpp — mask 轴（嵌在 pad / use_local switch 内）// cross 是 RUNTIME switch，不是 instance 轴：两腿在同一 .cpp 内编译。 // 只包 mask typedef + 下游 Pipeline/Kernel；false 腿解析到与 M7c 同一 Type ⇒ byte-identical。 BOOL_SWITCH(param.is_cross_attention, kIsCrossAttention, [&] { using Mask = typename ck_tile:: HstuBlockMasking<kIsCrossAttention, kUseCausal, kUseLocal>::Type; if constexpr(kUseSoftmax) RunSoftmax<Mask, kPadHeadDimQ, kPadHeadDimV>(param, stream); else RunSilu<Mask, kPadHeadDimQ, kPadHeadDimV>(param, stream); });

kernel：4 个 mask 构造 if constexpr 分叉到 cross builder

hstu_attention_bwd_kernel.hpp — SiLU with_local 构造（softmax / group 三处同型）if constexpr(FmhaMask::kIsCrossAttention) { // 经 wrapper 保 ctor 参序（R2/R3）；seqlen_kv 喂进 seqlen_k 槽 return make_hstu_cross_attention_block_mask_with_local<FmhaMask>( /*is_tile_in_first_split=*/true, kargs.seqlen_q, kargs.seqlen_kv, // <- seqlen_k = seqlen_kv kargs.contextual_seqlen, num_target, kargs.max_attn_len, eff_min_full); } else { /* 现有 self builder 逐字不动 ⇒ false 腿 dead-code-elim 到 M7c 同指令 */ return make_hstu_self_attention_block_mask_with_local<FmhaMask>( true, kargs.seqlen_q, kargs.contextual_seqlen, num_target, kargs.max_attn_len, eff_min_full); }
R2/R3 陷阱（编译通过但静默错）：cross with-local wrapper 签名是 (is_first, seqlen_q, seqlen_k, contextual, num_target, max_attn_len, min_full)，但 ctor 取 num_target 最后，wrapper 内部重排（:873-889）。绝不直接调 ctor、绝不改 wrapper 参序，否则 max_attn_len ↔ num_target 静默互换、小 shape 仍可能过。kernel 与 reference 都走同一 wrapper、参序逐字一致 ⇒ 这点静态可证。

为什么 max_seqlen_kv 是「纯 host 字段」= 零回归基石

bwd 是 KV-block-parallel：grid.x = ceil(max_seqlen_kv / kN0)，每个 KV-block 一个 split。新增的 max_seqlen_kv 只被 dispatch 的 grid/num_splits sizing 读，device 端 MakeKargs 不读。所以加这个字段 + 改 grid 全是 host 码，设备指令流逐字不变——这是后面 870/870 byte-identical 的机制保证。self 路 caller 设 max_seqlen_kv == max_seqlen_q ⇒ grid/num_splits 与 pre-cross 完全相同。

4  闸门决策 Option B：做全（含 kv > q），并修 grid silent-wrong

设计 critique 抓到两条互锁的洞，lead 闸门据此裁决「做全」并补字段：

闸门裁决（2026-06-15）：范围 = Option B 做全，支持 seqlen_kv 任意方向（含 jagged/group 的 seqlen_kv > seqlen_q）。新增 max_seqlen_kv 字段进两个 bwd params，并接进 jagged/group dispatch 的 grid + num_splits sizing。
critique 抓到的 silent-wrong：pre-cross 的 dispatch grid 按 max_seqlen_q 开（grid_seqlen_kv = is_jagged ? max_seqlen_q : seqlen_kv），且两个 bwd params 只有 max_seqlen_q。cross 下 seqlen_kv > seqlen_q 时 grid.x 短 ⇒ 尾部 KV 块根本没启动 ⇒ dK/dV 静默归零、dQ 漏其贡献。这是 R4 红旗，必修。
R4 修复：dispatch 的 kernel 启动 grid + determ num_splits + harness 的 dq_acc workspace 三处都从 max_seqlen_q 改按 max_seqlen_kv。self 路 max_seqlen_kv == max_seqlen_q ⇒ 不变。例：kv=512、q=128、kN0=128 ⇒ 4 个 KV 块。

5  怎么证「没有 silent-wrong」（本里程碑的工程亮点）

cross 的所有红旗都是 numerically-wrong 但不崩溃。等长 self 测试一律抓不到。这一节讲透三条「判伪」论证——不是「跑过了」，而是「主动制造错误，证明检查会响」。

① self 零回归：co_symbols 870 / 870 byte-identical

机制保证 false 腿 byte-identical（见 §3）。reviewer 从干净 M7c worktree 自产设备符号基线（不复用 coder 产物），再 verify cross binary：

第三个 binary build_r1 = cross 版 + 故意把 8 处 cross builder 的 seqlen_kv 槽喂成 seqlen_q（diff_q_kv_len=0 ⇒ self 几何复活），DRAM view 的 seqlen_kv 不动。同一 cross 案对照：
