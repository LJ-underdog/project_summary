HSTU Attention Backward — M5（softmax 反向路径）：fork 一条 SiLU 流水线，载 LSE 把 P 解回来

M5 给 no_group（batched + jagged）补齐 softmax 反向。核心是 fork 一份 MAIN pipeline（hstu_attention_with_softmax_bwd_pipeline.hpp）：从 fwd 存的 LSE 把概率 P 在 log2 域解回来，再加一个 PRE kernel 算 D=rowsum(O·dO)。SiLU 路逐字不变。所有引用以 git show 476bc16a:<file> 行号为准。

读者：要 review 这条 softmax bwd 路径的工程师（关键 stage / 数学口径 / 布局对齐配白话）
TL;DR — 一句话看懂 M5

M5 = SiLU MAIN 的 softmax fork。SiLU 路把 S 过 SiLU 当门；softmax 路要把 S 还原成概率 P=exp(α·S−LSE) —— 这需要 fwd 存的 LSE 和一个新的 PRE kernel 产出的 D=rowsum(O·dO)。整条路 dispatch 成 RunSoftmax：PRE → memset dq_acc → MAIN → POST。fwd 只切了一个 is_training 开关来吐 LSE，SiLU 路 byte-identical 零回归。

3  逐文件 review（为什么这样改）

① with_softmax_bwd_pipeline.hpp — softmax MAIN（SiLU 的 fork）新增

  • 数学口径（注释钉死）：:18-20 写明 LSE=log(Σexp(α·S)) 自然对数（fwd 存），P=exp(α·S−LSE)，但在 log2 域计算成 exp2(scale·s−log2e·lse)，scale=α·log2e。这样硬件原生的 exp2 才能跑得快，数学上与 reference 的 exp(αS−LSE) 等价。
  • operator() 签名：:103-112 比 SiLU 多收 lse_dram_block_window_tmp + d_dram_block_window_tmp 两个窗口，且丢掉 scale_p（softmax 无 P 输出缩放）。
  • LSE/D 的 HBM→LDS→Reg：:319-372 用 policy MakeLSEDDramTileDistribution / MakeLSEDLds{Write,Read}BlockDescriptor 载入。LDS 偏移直接复用 FMHA 同款——LSE 起于 QT+OGrad+OGradT+Q 之后，D 再 +LSE。这些 region SiLU policy 的 GetSmemSize 已预留，故 smem 总量不变（:31 / :91-93）。
  • STAGE2 解 P：见下方代码块。edge-tile 越界位置置 −inf，再 p=exp2(scale·s_acc−row_lse)。
  • STAGE5：:505-513 ds=p·(dp_acc−d[i_idx])，替换 SiLU 的 ds=dp·g，无 dropout/undrop 分支。
  • 收尾缩放：:559 dq_acc*=alpha、:575-576 注释「dK scale by alpha; dV unscaled」+ dk_acc*=alpha —— dV 不乘 alpha，与 SiLU 一致。
hstu_attention_with_softmax_bwd_pipeline.hpp:445-469 — STAGE2 掩 −inf + log2 域解 P// STAGE 2, mask + softmax recovery. // 运行时门 IsEdgeTile（非编译期 IsMasking）→ causal=0+num_target 也掩（沿用 P1-1 教训） if(mask.IsEdgeTile(seqlen_q_step, k_origin.at(number<0>{}), number<kM0>{}, number<kN0>{})) { auto is_masked_out = [&](auto tile_idx) { const int row = seqlen_q_step + tile_idx.at(number<0>{}); const int col = k_origin.at(number<0>{}) + tile_idx.at(number<1>{}); return !mask.IsTokenPairInsideMask(row, col); }; set_tile_if(s_acc, -numeric<AccDataType>::infinity(), is_masked_out); // softmax 用 -inf（SiLU 用 0!） } auto p = SPBlockTileType{}; sweep_tile_span(p_spans[number<0>{}], [&](auto idx0) { const auto row_lse = log2e_v<LSEDataType> * get_validated_lse(lse[i_idx]); // -inf→0 防 NaN sweep_tile_span(p_spans[number<1>{}], [&](auto idx1) { p(i_j_idx) = exp2(scale * s_acc[i_j_idx] - row_lse); // = exp(α·S − LSE), scale=α·log2e }); });
为什么是 −inf 而不是 0？ softmax 要让被掩位置的概率 P→0。因为 P=exp2(...)，只有把指数项打到 −inf 才能让 exp2(−inf)=0；若像 SiLU 那样置 s_acc=0，会得到 exp2(−row_lse)≠0 的杂散概率。反过来 SiLU 禁用 −inf（其门函数对 −inf 行为未定义）。这是两条 pipeline 唯一不能互抄的地方。

4  设计动机小结

  1. fork 而非分支：softmax MAIN 独立成新 pipeline 文件（with_softmax_bwd_pipeline.hpp），SiLU pipeline/kernel 一字不改 → 零回归（44 SiLU 案仍 PASS，见 M5-done §6）。
  2. log2 域算 P：scale=α·log2e、exp2(scale·s−log2e·lse)（:409-410），用硬件原生 exp2 提速，数学等价 exp(αS−LSE)。
  3. 复用预留 smem：LSE/D 载进 SiLU policy GetSmemSize 已留的 LDS region（:31），smem 总量不变，无需改 occupancy。
  4. D 用 PRE 全覆盖写：hstu_bwd_dot_do_o_kernel 输出布局即 MAIN 读 D 布局（[batch,head,seq]），MAIN 前 launch 全写，省一次 memset。
  5. 同一份 LSE 喂两侧：harness 把 GPU LSE 转置后喂 reference，保证两侧 P 完全一致，对拍逐位级佐证布局/域均正确。

5  遗留 / 边界（M5 明确不做）

已知盲区（诚实写）： 对拍无法独立验 LSE 的数值——GPU-bwd 与 reference 共用同一份 GPU-产 LSE，所以 LSE 自身若错，两侧会一起错而对拍仍 PASS。该风险靠代码审计（数学口径核为自然对数：fwd 用 __expf、pcomp*=scale_s、lse=m+log(l)）+ fwd 里程碑的 LSE 验证兜底（M5-done §4 / commit 文末）。
