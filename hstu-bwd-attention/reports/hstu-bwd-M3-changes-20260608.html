HSTU Attention Backward — M3（jagged 变长）改了哪些代码、为什么、怎么连

这份文档忠实记录 M3 里程碑在仓库里真实发生的代码改动：变长（jagged）序列怎么用 同一个 SiLU MAIN kernel、靠运行时 is_jagged 分支处理；packed 布局与 cu_seqlens 怎么算；dispatch / harness / 对拍怎么接线；以及 10 档 jagged sweep + 测试套件两层证据。所有片段以当前源码为准（bwd 文件未跟踪，无 git 基线，按 M2 文档同法以代码区段呈现）。

TL;DR — 一句话看懂 M3

M3 没有新增任何 kernel 实例。变长序列（jagged）和定长（batched）共用同一个 SiLU MAIN kernel，只在运行时用一个 if(is_jagged) 分支选择「每个 batch 的起始偏移 + 该 batch 的 seqlen」。

jagged 的本质：把所有 batch 的 token 沿 dim1 紧密拼成一条 dim0=1 的 token-major packed 张量 [1, ΣL, H, D]，再配一组 cu_seqlens（前缀和偏移）告诉 kernel 每个 batch 从哪开始、有多长。没有 padding，所以全 buffer 都能参与对拍。

白话：M3 的四件事

  • ① kernel 加 jagged 分支（hstu_attention_bwd_kernel.hpp）：kargs 加 is_jagged + 两个 offsets 指针；operator() 里把「算 base offset」那块改成 if(is_jagged){…}else{…}，并覆盖该 batch 的 seqlen_q/kv，再加一条 early-exit。
  • ② dispatch 接线（...batched_backward_dispatch.hpp）：MakeKargs 传 is_jagged + offsets；dq_acc 清零字节数 / POST 元素数按 jagged（dim0 全量）vs batched（num_batch×）；grid.x 的 seqlen 按 max_seqlen_q vs seqlen_kv。
  • ③ harness 加 -jagged（example_hstu_attention_bwd.cpp）：packed [1,ΣL,H,D] 分配、cu_seqlens 前缀和、per-batch seqlen 逗号列表、BOOL_SWITCH_3 喂 reference<kIsJagged=true>。
  • ④ 测试套件（test/run_bwd_tests.py）：把原 reject-jagged 升级为 8 个 jagged pass case。
为什么「运行时分支」而非新写一套 jagged kernel？ jagged 与 batched 的差别只在每个 batch 的内存起点和长度 —— 一旦 base offset 和 seqlen 定好，后面的 window / mask / OOB 处理全都是布局无关的。所以 M3 没必要复制一份 kernel，只在「定位 batch」这一处分叉。代价是每个 thread block 多一次运行时 if，收益是零实例膨胀、batched 路径完全不动。
一个关键诚实声明（与 M2 不同）： M2 文档里提醒过 git status 有 198 个 fwd instance「再生成噪音」。M3 本次没有这类噪音 —— M3 没碰 generate_instances.py / instances/（实测它们 mtime 仍停在 06-04，而 M3 改的文件是 06-08）。git status 里仍显示的 ~203 个 instance 修改是 M2 期遗留（里程碑间未 commit，故一直挂着），不属于 M3 改动。详见 §2。

4  kernel 的 is_jagged 分支（代码）

M3 在 kernel 里只动两处：① kargs 多三个字段；② operator() 里把「算 base offset」改成分支并覆盖 seqlen，再加一条 early-exit。pipeline 计算本体一行没改。

① kargs 新增字段

hstu_attention_bwd_kernel.hpp（Kargs，~L69–75）// jagged (variable-length) mode (M3). When is_jagged: dim0=1 packed tensors, // per-(batch) base offset = seq_*_offsets_ptr[i_batch]*seq_stride (token-major), // and seqlen_{q,kv} are derived per batch from the offsets (the scalar // seqlen_q/seqlen_kv below are then ignored). Batched mode: is_jagged=false. bool is_jagged; const void* seq_q_offsets_ptr; // int32, size num_batch+1 const void* seq_kv_offsets_ptr; // int32, size num_batch+1 (== q offsets for self-attn)

② base offset 分支 + 覆盖 seqlen + early-exit

hstu_attention_bwd_kernel.hpp（operator()，~L247–280） if(kargs.is_jagged) { const auto* q_offsets = reinterpret_cast<const int32_t*>(kargs.seq_q_offsets_ptr); const auto* kv_offsets = reinterpret_cast<const int32_t*>(kargs.seq_kv_offsets_ptr); const long_index_t query_start = q_offsets[i_batch]; const long_index_t key_start = kv_offsets[i_batch]; batch_offset_q = query_start * kargs.stride_q; // q/do/dq_acc 用 query_start batch_offset_k = key_start * kargs.stride_k; // k/v/dk/dv 用 key_start ... // per-batch sequence lengths (token-major packed); overrides the scalar kargs kargs.seqlen_q = q_offsets[i_batch + 1] - q_offsets[i_batch]; kargs.seqlen_kv = kv_offsets[i_batch + 1] - kv_offsets[i_batch]; } else { batch_offset_q = static_cast<long_index_t>(i_batch) * kargs.batch_stride_q; // …(原 batched 路) ... } // jagged: grid.x is sized for the largest sequence, so KV tiles past this // batch's seqlen_kv have no work. (Batched grid is exact -> never triggers.) if(i_n0 >= kargs.seqlen_kv) return;
关键设计 1
覆盖 seqlen，后续零分支
jagged 分支算完 base offset 后，直接把 kargs.seqlen_q/kv 写成 per-batch 值。这样后面的 window / mask / OOB 处理原样复用 —— 它们读的就是 kargs.seqlen_*，不需要再为 jagged 分叉。
关键设计 2
early-exit 护短 batch
grid.x 按最长序列开，短 batch 的越界 KV-tile 用 if(i_n0>=seqlen_kv) return; 直接退出，避免越界 atomic 写。这也是「大段差」对拍能过的关键。
batched 安全性
定长路径零变化
batched 的 grid 是精确的（grid.x = seqlen_kv），i_n0 永远 < seqlen_kv，early-exit 永不触发；else 分支即原 M1/M2 代码。所以 batched 行为可证零变化。
q 用 query_start、k/v 用 key_start： 反向里 q/dO/dQ_acc 沿 query 轴定位，k/v/dK/dV 沿 key 轴定位。self-attention 下两套 offsets 相等（dispatch 把 kv 指针传成 q），但代码保留两条以便 M4/cross 复用。

5  【图2】jagged 数据流与对拍

M3 的可信度靠「GPU jagged 路 vs CPU reference jagged 路」逐 token 对拍。下面是整条管线：harness 造 packed 数据 + cu_seqlens，两路各自算梯度，再 check_err。

图2：harness 造 packed 数据 + cu_seqlens 同时喂 GPU 与 CPU 两路；两路输出 packed 梯度，check_err 逐元素比对。packed 无 padding（ΣL 精确），每个 token 都被两路写到，所以全 buffer 对拍合法。

同源 1
max_seqlen_q 决定 scale_p
scale_p = 1/max_seqlen_q，GPU 与 reference 用同一个 max_seqlen_q = max_uih + max_target + contextual，保证两路缩放完全一致。
同源 2
self-attn：kv == q
M3 只做 self-attention，seq_kv_offsets == seq_q_offsets，phy_seqlen_kv = phy_seqlen_q。dispatch 把 kv 指针直接传成 q 指针。
为何全 buffer 可比
packed 无 padding
ΣL 是精确的 token 总数，packed 张量里没有任何「填充位」。每个位置都参与计算并被写，所以可以整段 buffer 对拍，不必逐 batch 切片。

6  dispatch 改动（接线代码）

dispatch 把 jagged 信息接进 MakeKargs，并按布局调整三处尺寸/网格。注意 Run() 里没有 jagged 的 throw —— jagged 走的就是 SiLU 主路。

MakeKargs 传 is_jagged + offsets

hstu_attention_batched_backward_dispatch.hpp（MakeKargs，~L126–137） auto kargs = Kernel::MakeKargs(param.q_ptr, ... , param.dq_acc_ptr, param.is_jagged, param.seq_q_offsets_ptr, param.is_cross_attention ? param.seq_kv_offsets_ptr : param.seq_q_offsets_ptr, // self: kv 传 q param.seqlen_q, param.seqlen_kv, ...);

dq_acc 清零字节 / POST 元素数 / grid.x（按布局）

hstu_attention_batched_backward_dispatch.hpp（~L171–186） // zero the float dq_acc workspace before atomic accumulation. Batched layout // is [num_batch, sq, h, hdim]; jagged is the dim0=1 packed [1, ΣL, h, hdim] // whose dim0 stride (batch_stride_dq_acc) is the full element count. const size_t dq_acc_elems = param.is_jagged ? static_cast<size_t>(param.batch_stride_dq_acc) // dim0 全量 = ΣL*H*hdim : static_cast<size_t>(param.num_batch) * param.batch_stride_dq_acc; HIP_CHECK_ERROR(hipMemsetAsync(param.dq_acc_ptr, 0, dq_acc_elems * sizeof(typename TC::GemmAccDataType), stream)); // jagged: grid.x must cover the largest per-batch seqlen_kv (== max_seqlen_q for self) const ck_tile::index_t grid_seqlen_kv = param.is_jagged ? param.max_seqlen_q : param.seqlen_kv; dim3 grid = Kernel::GridSize(param.num_batch, param.num_head, grid_seqlen_kv);

Run()：没有 jagged throw（同一主路）

hstu_attention_batched_backward_dispatch.hpp（Run，~L209–214） // M3: jagged (variable-length) is handled by the same SiLU MAIN kernel — only // the per-batch base offset / seqlen differ (selected at runtime by // param.is_jagged inside the kernel + MakeKargs above). No separate instance.
POST 也按 dq_acc_elems 走。 dQ 累加用 float workspace + atomic，最后 POST 把它 cast 回 bf16。POST 是对整段连续 buffer 的 elementwise cast —— packed 布局同样是一段连续 buffer，所以 POST 逻辑零改动，只是元素数取 dq_acc_elems。

7  harness 的 -jagged（造数据 + 喂 reference）

harness 是对拍的「出题人」：开 -jagged 后按 packed 分配、算 cu_seqlens 前缀和、把 per-batch 不同 seqlen 喂给 GPU 与 CPU 两路。

cu_seqlens 前缀和（token-major packed）

example_hstu_attention_bwd.cpp（~L186–203） std::vector<int> seq_offsets_q; int phy_seqlen_q = 0; if(is_jagged) { seq_offsets_q.push_back(0); for(int i = 0; i < num_batch; i++) { const int batch_seqlen = seq_lengths_q[i] + // per-batch 物理长度含 num_target + contextual（与 fwd harness 一致） (num_targets.empty() ? 0 : num_targets[i]) + contextual_seqlen; phy_seqlen_q += batch_seqlen; seq_offsets_q.push_back(phy_seqlen_q); // 前缀和 → cu_seqlens } phy_seqlen_kv = phy_seqlen_q; // self-attention } else { phy_seqlen_q = max_seqlen_q; phy_seqlen_kv = max_seqlen_kv; } const std::vector<int>& seq_offsets_kv = seq_offsets_q; // self: kv == q
分配 dim0： batches_for_alloc = is_jagged ? 1 : num_batch。jagged 下 Q/K/V/O/dO/dQ/dK/dV/dq_acc 全部按 [1, ΣL, H, D] 分配；-seqlens 在 jagged 下接受 per-batch 逗号列表并 supplement 到 num_batch。

BOOL_SWITCH_3 喂 reference 的 jagged 模板分支

example_hstu_attention_bwd.cpp（~L430–442） const std::vector<int> empty_offsets; // batched: 无 jagged offsets const std::vector<int>& ref_q_offsets = is_jagged ? seq_offsets_q : empty_offsets; const std::vector<int>& ref_kv_offsets = is_jagged ? seq_offsets_kv : empty_offsets; BOOL_SWITCH_3(is_jagged, kIsJagged, use_softmax, kUseSoftmax, use_causal, kUseCausal, [&] { ck_tile::reference_no_group_hstu_attention_bwd<InOutDataType, GemmAccDataType, CompDataType, kIsJagged, kUseSoftmax, kUseCausal>::Run( is_cross_attention, q_host, k_host, v_host, ... , max_seqlen_q, max_seqlen_kv, ref_q_offsets, ref_kv_offsets, num_targets, contextual_seqlen, window_size, min_full_attn_seqlen); });
GPU fwd 也喂 jagged 参数。 harness 先跑 GPU fwd 产 O（SiLU bwd 本身不用 O，但保持 jagged 布局正确、避免 packed 上越界读），再跑 bwd；offsets 同时上传给 fwd 参数、bwd 参数、CPU reference 三处 —— 三方同源是逐 token 对拍能成立的前提。

10  遗留与边界（诚实标注）

  • M4 group 是 jagged 的超集。reference_group_… 已就绪；需接 HstuAttentionGroupBwdParams（目前空 struct）+ group dispatch（per-group window/contextual/minfull/max_seqlen/attn_scale 设备指针，i_group = i_batch / num_batch_per_group）。M3 的 jagged offset 索引可直接复用 —— group 只是在 jagged 之上多了 per-group 超参。
  • cross-attention jagged 仅 self。kernel / harness 现只走 self（kv offsets == q）；cross 需独立 kv offsets + cross mask 构造（mask 成员 M2 已加），待对应里程碑。
  • perf（M8）：jagged 短 batch 的 early-exit 已避免越界 KV-tile 的 atomic，但 grid 仍按 max 开（短 batch 的 block 启动后立即退出，仍有调度开销）；GetTileRangeAlongY 仍保守全 Q 扫描（M2 遗留）。
  • 无未解决阻塞点。offset 计算 / reference jagged 分支 / packed stride 三处均经「大段差 + 非整除 + tiny」交叉验证 —— 若任一错会暴露大误差，实测均 bf16 舍入级。
给 reviewer 的一句话总结： M3 是一次「同 kernel、加一条运行时分支」的扩展 —— 没有新 kernel 实例、没有 instance 噪音、batched 路可证零变化。要 review 的逻辑集中在 kernel 的 is_jagged 分支（base offset + 覆盖 seqlen + early-exit）、dispatch 的三处 sizing、harness 的 cu_seqlens 前缀和。
