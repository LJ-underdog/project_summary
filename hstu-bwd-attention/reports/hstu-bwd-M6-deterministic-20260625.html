HSTU Attention Backward — M6（deterministic dQ）：把 dQ 从「偶然一致」做成「构造可复现」

M6 给 no_group（batched + jagged）× SiLU + softmax 的 dQ 加一条 bit-reproducible 路：每个 KV-block 用 set（非 atomic）把自己的 dQ 贡献 plain-store 到专属 split 副本，再由一个新 POST kernel 按固定升序归约 + 转换。所有引用以 git show 48673726:<file> 行号为准。

读者：要 review 这条确定性 dQ 路径的工程师（含浮点结合律 / atomic 归约序背景一句白话）
TL;DR — 一句话看懂 M6

默认（atomic）dQ 把所有 KV-block 的贡献 atomic_add 进同一份 dq_acc → 归约顺序随调度抖动 → 浮点加法不满足结合律 → 不可逐位复现。M6 deterministic：每个 KV-block 写自己的 split 副本（无竞争），POST 按 s=0..num_splits-1 固定序求和 → 构造上 bit-reproducible。代价是 dq_acc workspace 扩到 num_splits 倍。

1  总览：M6 到底改了什么

一句话四件事：

机制
每 split 独立写 + 固定序 reduce
KV-block 用 set 写第 i_tile_n 份副本（bwd_kernel.hpp:360-385），POST 升序归约（:1666-1687）。
编译期分叉
dq_acc 窗口 constexpr mop
determ mop=set+split 偏移，atomic atomic_add 无偏移——同一 kernel 两条路靠 kIsDeterministic 编译期切。
选型
真模板轴 + 共享 helper
kIsDeterministic 成真轴穿进 Problem；dispatch 抽 launch_main_and_post（dispatch:70-130）统一两路收尾。
实例 / 构建
determ 轴 → 8 实例
generator determ 轴 [False]→[False,True]（generate_instances.py:183/234）；entry BOOL_SWITCH_2→_3。
M6 核心张力： 浮点加法不满足结合律，(a+b)+c ≠ a+(b+c)。atomic_add 把多个 KV-block 的部分 dQ 累进同一地址，硬件调度决定到达顺序 → 同一输入两次跑可能得到逐位不同的 dQ（数值都对，只是末位 bit 抖）。M6 用「每 split 独立写 + 单线程固定序 reduce」把归约序钉死，换来逐位可复现——代价是 workspace 从 1 份变 num_splits 份。

3  逐文件 review（为什么这样改）

① bwd_kernel.hpp — MAIN：dq_acc 窗口编译期分叉 改动

  • :115 SiLU kernel 的 Kargs 加 split_stride_dq_acc（per-split 单份元素数）；:160 MakeKargs 加同名形参，:205 落盘。softmax kernel 同款：:546 / :594 / :642。
  • :360-385 dq_acc 窗口改成 lambda 即调，把 i_tile_n/i_nhead 按值捕进去：:364 constexpr auto mop = kIsDeterministic ? set : atomic_add；:370-372 determ 时基址 += i_tile_n_ * split_stride_dq_acc（即「写第 split_idx=i_tile_n 份副本」）。atomic 不加偏移（共用单份）。
  • :790-818 softmax kernel 同一处理（注释明写「see SiLU kernel」），两个 kernel 各一处，逻辑对称。
  • pipeline 未改：set vs atomic_add 的实际写动作由 pipeline 既有的 if constexpr(kIsDeterministic) store_tile else update_tile 落地（no_softmax :523-531、with_softmax :561），M1 起就在位——M6 只是把上游 mop 与 split 偏移接上。
hstu_attention_bwd_kernel.hpp:360-374 — dq_acc 窗口：constexpr mop + split 偏移// dQ_acc window. Deterministic (M6): plain store (set) into THIS KV-block's own // split slot (base += i_tile_n * split_stride_dq_acc) -> no atomic, bit-reproducible; // POST reduces over splits. Atomic (default, nsplits=1): atomic_add into one slot. auto dq_dram_window = [&, i_tile_n_ = i_tile_n, i_nhead_ = i_nhead]() { constexpr auto mop = kIsDeterministic ? memory_operation_enum::set : memory_operation_enum::atomic_add; AccDataType* dq_acc_ptr = reinterpret_cast<AccDataType*>(kargs.dq_acc_ptr) + static_cast<long_index_t>(i_nhead_) * kargs.nhead_stride_dq_acc + batch_offset_dq_acc; if constexpr(kIsDeterministic) dq_acc_ptr += static_cast<long_index_t>(i_tile_n_) * kargs.split_stride_dq_acc; // 第 i_tile_n 份副本

② bwd_kernel.hpp — 新 POST：固定序归约 + 转换 新增

  • :1672-1687 新 hstu_bwd_reduce_convert_dq_kernel：每线程负责单份里的一个元素 i，:1684 for(s=0..num_splits-1) acc += dq_acc[s*split_stride + i]，:1686 转回 QGradDataType 写 dq[i]。
  • 为什么可复现：求和序固定为 s 升序，与 block 调度无关 → 同输入同输出，逐位一致（:1667-1670 注释明写「summation order is fixed … bit-reproducible」）。
  • atomic 的旧 hstu_bwd_convert_dq_kernel（单份纯 convert，num_splits=1）保留不动，两路 POST 并存。
hstu_attention_bwd_kernel.hpp:1672-1687 — 固定升序 split 归约（构造上 bit-reproducible）template <typename QGradDataType, typename AccDataType> __global__ void hstu_bwd_reduce_convert_dq_kernel(const AccDataType* __restrict__ dq_acc, QGradDataType* __restrict__ dq, long_index_t n, // 单份元素数 int num_splits, long_index_t split_stride) { const long_index_t i = static_cast<long_index_t>(blockIdx.x) * blockDim.x + threadIdx.x; if(i >= n) return; float acc = 0.f; for(int s = 0; s < num_splits; ++s) // 固定 s 升序,与调度无关 acc += type_convert<float>(dq_acc[static_cast<long_index_t>(s) * split_stride + i]); dq[i] = type_convert<QGradDataType>(acc); }

4  设计动机小结

  1. 用结构换确定性：浮点加法非结合 → atomic 归约序不定 → 非确定。M6 让每 KV-block 写专属副本（无竞争）+ POST 单线程固定升序求和，把归约序从「硬件调度决定」变成「代码写死」，构造上保证逐位可复现（bwd_kernel.hpp:1672-1687）。
  2. 编译期分叉，零运行时开销：dq_acc 写法靠 constexpr mop + if constexpr（:364-372）在编译期切 set/atomic，determ 与 atomic 各成独立实例,互不拖累。
  3. 复用既有 store_tile 分支：pipeline 的 if constexpr(kIsDeterministic) store_tile else update_tile M1 起就在位,M6 只把上游 mop 与 split 偏移接上——pipeline 字节不改。
  4. 抽 helper 消重：launch_main_and_post 把 SiLU/softmax 两路的 num_splits/memset/MAIN/POST 统一（:70-130),两路只剩一行调用。
  5. 实例随生成器同步：determ 轴一改,4 个 instance + 8 个 extern ref 由 generator 一并产出（:183/:234),杜绝手写漂移与缺符号。
