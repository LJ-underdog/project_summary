HSTU Forward SplitKV for Softmax Path

b1052e87 branch hstu_attention_fwd 19 files +1138 / -162 follow-up: 1dbd127d
TL;DR

HSTU attention 的 splitkv 路径此前仅支持 no-softmax (SiLU) 模式。本 commit 新增 softmax 路径的 split kernel LSE 输出 + combine pipeline（logsumexp 归并 + 加权累加），同时在 batched / jagged / group 三种 dispatch 中删除 !kUseSoftmax 门控，使 softmax 路径也能在 CU 占用率不足时自动启用 splitkv 加速。

1. Algorithm -- HSTU + SplitKV

1.1 HSTU Attention vs FlashAttention

HSTU (Hierarchical Sequential Transduction Units) 是 Meta 面向生成式推荐的 attention 变体。核心公式：S = Q @ K^T → mask → SiLU → P → O = P @ V。

DimensionFlashAttentionHSTU Attention
Activationrow-wise softmax (max + LSE)SiLU element-wise, no row reduction ("no-softmax" path)
Maskcausal / sliding windowcausal + context_len + min_full_len + local diagonal window + target
Batch layoutdense [B,H,S,D]jagged (variable-length flat) + group (multi-group batch)
Pipelinesingle softmax pipelinewith_softmax_* / no_softmax_* two parallel pipelines

1.2 Why SplitKV

Standard FlashAttention parallelism = batch * head * ceil(seqlen_q / tile_M). When batch and head are small but KV sequence is long (inference: B=1, few heads, S_kv in thousands~100k), GPU CUs are underutilized. SplitKV partitions the KV dimension into num_splits segments, each processed by an independent workgroup, multiplying parallelism by num_splits.

1.4 New Combine Pipeline -- Key Algorithm

File: hstu_attention_with_softmax_fwd_splitkv_combine_pipeline.hpp (270 lines new)

// Step A: load per-split LSE
auto lse_acc = load_tile(lse_acc_dram_window);

// Step B: row-wise max across splits (numerical stability)
auto lse_max = block_tile_reduce<LSEDataType>(
    lse_acc, sequence<1>{}, f_max, -numeric<LSEDataType>::infinity());

// Step C: exp(lse_split - lse_max); all-inf rows → 0
lse_exp(i_j_idx) = exp(lse_acc[i_j_idx] - lse_max[i_idx]);

// Step D: sum → logsumexp = log(sum) + max
auto lse_sum = block_tile_reduce<LSEDataType>(lse_exp, sequence<1>{}, f_sum, 0);
lse_logsum(i_idx) = log(lse_sum[i_idx]) + lse_max[i_idx];

// Step E: scale = exp(lse_split - lse_global); reuse lse_acc register
lse_acc_type& lse_scale = lse_acc;
lse_scale(i_j_idx) = exp(lse_acc[i_j_idx] - lse_logsum[i_idx]);

// Step F: write scale to LDS for random (row, split) access
store_tile(lse_scale_lds_write_window, lse_scale, partition_index);
block_sync_lds();

// Step G: weighted accumulation over splits
for(int i_split = 0; i_split < num_splits; i_split++) {
    auto o_acc_tile = load_tile(o_acc_dram_window);  // offset by split stride
    o_acc(i_j_idx) += o_acc_tile[i_j_idx] * lse_scale_lds(row, i_split);
}
Design: LDS serves as a lookup table for scale weights; O tile distribution differs from LSE tile distribution, so scales are materialized in LDS for random row-indexed access. Register reuse via reference aliasing avoids extra register pressure.

1.5 Pseudocode

combine_pipeline(lse_acc[kM][kMaxSplits], o_acc[kM][kHeaddim] x num_splits):
    # ---- LSE merge ----
    lse[m][s]     := load_lse(m, s)
    lse_max[m]    := max_s lse[m][s]
    lse_exp[m][s] := exp(lse[m][s] - lse_max[m])
    lse_sum[m]    := sum_s lse_exp[m][s]
    lse_logsum[m] := log(lse_sum[m]) + lse_max[m]       # = LSE_global
    scale[m][s]   := exp(lse[m][s] - lse_logsum[m])      # sum_s scale == 1
    store_lds(scale)

    # ---- O weighted accumulate ----
    O[m][d] := 0
    for s in 0..num_splits-1:
        O_partial := load(o_acc + s * split_stride)
        O[m][d]  += O_partial[m][d] * scale[m][s]        # via LDS row lookup
    return O

3. Impact -- Triggers, Performance, Tests

3.1 Trigger Condition

// hstu_attention_fwd_setting.hpp:499-507
static bool shall_use_splitkv(int num_batches, int num_heads, int max_seqlen_q) {
    const float threshold = 0.8f;
    if(get_estimated_cu_coverage_ratio(num_batches, num_heads, max_seqlen_q) < threshold)
        return true;
    return false;
}
Criterion: CU utilization < 80%. When batch * nhead * ceil(seqlen_q/64) < 0.8 * 2 * num_CUs, splitkv activates. num_splits derived by get_suggested_num_splits(), upper-bounded at 64. Env var HSTU_DISABLE_SPLITKV for global override.

3.2 Performance Expectations

Benefits
  • CU occupancy improves from <0.8 toward 1.0
  • Best case: small batch + long seqlen (inference)
  • CU-ratio heuristic more general than fixed seqlen threshold
Costs
  • hipMallocAsync/hipFreeAsync for o_acc + lse_acc workspace
  • Combine kernel launch overhead
  • LSE reduce cost grows with num_splits

3.3 Test Coverage

Coverage Gap Warning

Existing softmax tests (b=10, nhead=4, seqlen~256) do trigger splitkv on gfx950 (256 CUs) since ratio = 160/512 = 0.3125 < 0.8. Happy path is covered. However:

  • Corner cases missing: extreme num_splits near 64, padding boundaries (kPadNumSplits), very long seqlen (≥4096)
  • No splitkv on/off comparison: no script runs both HSTU_DISABLE_SPLITKV=0 and =1 to assert numerical consistency
  • Jagged + softmax + splitkv is a new path combination -- needs b=1~2, variable seqlens, softmax=1 end-to-end case
  • Hardware-dependent: same params may not trigger splitkv on GPUs with different CU counts

3.4 API Compatibility

hstu_attention_api.hpp is unmodified. Source-compatible; ABI change only in params structs (added lse_acc_ptr), managed internally by dispatch -- callers need not change.

4. Risks & Open Items

1
LSE Numerical Stability & OOB Handling
When num_splits < kMaxSplits, padding LSE must be -inf to avoid polluting exp(lse_split - lse_max). b1052e87 uses manual sweep_tile_span fill; 1dbd127d switches to buffer_view OOB. Review: does kAlignmentLSEacc = kPadNumSplits ? 1 : ... affect buffer_load OOB semantics? Do all padding positions map to OOB addresses?
2
Combine Overhead at Large num_splits
MAX_SPLITS_SWITCH instantiates 16/32/64, then kMaxSplits may be multiplied up to 4x (to satisfy kM * kMaxSplits >= kBlockSize). Extreme case kMaxSplits=256: LDS/register pressure + 256-way reduce. kBlockPerCu=2 is hardcoded. Needs real-device profiling.
3
Jagged + Softmax + SplitKV Interaction
LSE workspace sized by num_batch * max_seqlen_q * nhead * num_splits (max, not actual seqlen). Combine must strictly follow seq_q_offsets_ptr for valid rows. This is a new path combination; no existing test covers jagged variable-length + softmax + splitkv together.
4
Workspace Allocation Leak
Two hipMallocAsync calls (o_acc, lse_acc): if the second fails, the first is not freed (no cleanup path). Softmax path doubles the leak surface by adding lse_acc_ptr.
