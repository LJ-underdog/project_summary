HSTU Attention Backward — M5b：softmax 从 no_group 扩到 group，「复用不重写」怎么做到

这份文档讲清 M5b 如何把 softmax 反向接到 group 路：它是 M4（group SiLU 双 pipeline）与 M5（no_group softmax）的合流——MAIN softmax pipeline、PRE、POST 三件直接复用，只新写一个 group-softmax kernel + group RunSoftmax + group harness 产 LSE。重点讲 per-group 超参取数、运行时 window>0 选 softmax 双 pipeline、softmax 为何不读 scale_p、以及 group packed [head,ΣL] 的 LSE/D 四方布局。所有片段引磁盘真实行号（git dc8c6b21）。

TL;DR — 一句话看懂 M5b

M5b = M4 ＋ M5。M4 给了 group kernel 的骨架（i_group 取 per-group 超参 + jagged offset + 运行时 window>0 选 with/without-local 双 pipeline）；M5 给了 softmax 的全部数学与加载（log2 域 P 恢复、LSE/D dram window、PRE 现算 D）。M5b 把两者焊在一起：新写一个 group-softmax kernel，骨架照搬 M4，但双 pipeline 换成 M5 的 softmax pipeline、并接上 LSE/D window、去掉 scale_p。

「复用不重写」是核心：M5 的 MAIN softmax pipeline、PRE kernel、POST kernel 三个文件一字未改（mode-agnostic，group 是 jagged 超集）。三个 M5/SiLU 已 promoted 的禁改文件 byte-identical。group 的 LSE/D 是 packed [head,ΣL]，与 M5 jagged 路布局完全相同。

1  M5b 是什么：M4 × M5 合流

softmax 反向到 M5 为止只覆盖 no_group（batched + jagged）。M5b 把它扩到 group（多组、每组独立超参）。group 在内存上是 jagged 的超集（dim0=1 token-major packed + cu_seqlens），所以 M5 的 packed 加载逻辑能整体复用；要补的只是「按 i_group 取 per-group 超参」和「同一次 launch 里有的 group 带 window、有的不带」这两件 M4 已解决的事。

白话：M5b 做的三件事

  • ① 新写 group-softmax kernel（hstu_attention_bwd_kernel.hpp 的 HstuAttentionBwdDQDKDVGroupSoftmaxKernel）= M4 group kernel 骨架（per-group 取数 + jagged offset + 双 pipeline 选择 + 共享 write_dkdv）＋ M5 的 LSE/D window 构造 + 调 softmax pipeline（去 scale_p）。
  • ② group dispatch 接 RunSoftmax（hstu_attention_group_backward_dispatch.hpp）：去掉 kUseSoftmax 的 throw，组 softmax 的 with/without-local 两条 pipeline，launch PRE → memset → MAIN → POST。SiLU 分支 RunSilu 逐字不变。
  • ③ group harness 产 O+LSE（example_hstu_attention_bwd.cpp）：softmax 时跑 GPU group fwd（is_training=true）产 O 和 LSE（[head,ΣL] 连续-seq），取回后转置喂 reference；分配 o_dev/lse_dev/d_dev。CMakeLists.txt 把 group fwd entry 链进 bwd target。

2  复用边界：哪些直接用、哪些新写、为什么能复用

M5b 最值得讲的是它的「克制」——能复用的全复用。下表把每个组件标清来源与处理，复用 表示一字未改，新写 表示本里程碑新增，改动 表示已有文件内加 group-softmax 部分。

为什么 M5 pipeline 能「mode-agnostic」地复用？ 关键设计在 M5：所有「模式相关」的东西（per-batch / per-group offset、per-group 超参、mask 构造）都在 kernel 层处理完，传给 pipeline 的只有已经定位好的 dram window + 一个 mask 对象 + alpha。pipeline 内部只跑 5 个 GEMM 和 STAGE2/5 的 elementwise，完全不碰寻址。所以无论 no_group 还是 group，pipeline 这一层看到的接口完全一样——这正是 M5b 能「不重写」的根因。

3  group-softmax kernel：per-group 取数 + 双 pipeline + 无 scale_p

这是 M5b 唯一的新逻辑。代码引 hstu_attention_bwd_kernel.hpp（HstuAttentionBwdDQDKDVGroupSoftmaxKernel，~L1392-1560）真实行号。

per-group 取数：i_group 取 window / contextual / min_full（L1411-1418）

hstu_attention_bwd_kernel.hpp · L1411-1418 // i_group 在 wave 内对所有 lane 相同 → readfirstlane 提示标量 const index_t i_group = __builtin_amdgcn_readfirstlane(i_batch / kargs.num_batch_per_group); const index_t window_size = ...group_window_size_ptr[i_group]; const index_t contextual_seqlen = ...group_contextual_seqlen_ptr[i_group]; const index_t min_full_attn_seqlen = ...group_min_full_attn_seqlen_ptr[i_group]; // 注意:不读 group_attn_scale_ptr / group_max_seqlen_q_ptr —— softmax 不用 scale_p
softmax 为什么不读 scale_p？ SiLU 路的 P = silu(α·S)·scale_p 需要 scale_p（=group_attn_scale 或 1/group_max_seqlen_q 的回退）做缩放；softmax 路的 P = exp(α·S − LSE) 由 LSE 自带归一化，不需要 scale_p。所以 group_attn_scale_ptr / group_max_seqlen_q_ptr 虽然仍在 Kargs（接口与 M4 一致、dispatch 照传），但 kernel 从不解引用它们。pipeline 调用也只传 kargs.alpha（global），形参里根本没有 scale_p 槽位（见下）。

运行时 window>0 选 softmax 双 pipeline（L1536-1558）

hstu_attention_bwd_kernel.hpp · L1536-1558 if(window_size > 0) // per-group window 决定走哪条（同 M4 运行时选择） { const int eff_min_full = (seqlen_q - num_target > min_full_attn_seqlen) ? min_full_attn_seqlen : (seqlen_q - num_target); auto mask = make_hstu_self_attention_block_mask_with_local<LocalMask>( /*first_split=*/true, seqlen_q, contextual_seqlen, num_target, window_size, eff_min_full); auto [dk, dv] = PipelineLocal{}(q_win, k_win, v_win, do_win, lse_dram_window, d_dram_window, dq_win, mask, kargs.alpha, smem_ptr); write_dkdv(dk, dv); // ← 注意:无 scale_p 形参 } else // window==0 → without-local { auto mask = make_hstu_self_attention_block_mask_without_local<NoLocalMask>( seqlen_q, contextual_seqlen, num_target); auto [dk, dv] = PipelineNoLocal{}(q_win, k_win, v_win, do_win, lse_dram_window, d_dram_window, dq_win, mask, kargs.alpha, smem_ptr); write_dkdv(dk, dv); }
选的是 softmax，不是 SiLU。 两条 PipelineLocal / PipelineNoLocal 在 dispatch 里实例化为 HstuAttentionWithSoftmaxBwdDQDKDVPipelineKRKTRVR<ProblemFor<...>>（group_backward_dispatch.hpp:201-204）——是 M5 的 softmax pipeline，不是 M4 SiLU 的 HstuAttentionBwdDQDKDVPipelineKRKTRVR。M4 的「运行时 window>0 双 pipeline 选择」机制原样照搬，只是被选的两条实例换成了 softmax。GetSmemSize=max(两 pipeline, 两 epi)，运行时每 block 只跑一条。

LSE/D 定位（group packed，L1432 / L1448-1453）

hstu_attention_bwd_kernel.hpp · L1432 + L1448-1453 const long_index_t batch_offset_lsed = query_start; // LSE/D seq stride 1（packed） const LSEDataType* lse_ptr = ...kargs.lse_ptr + i_nhead * kargs.nhead_stride_lsed + batch_offset_lsed; const DDataType* d_ptr = ...kargs.d_ptr + i_nhead * kargs.nhead_stride_lsed + batch_offset_lsed; // 1-D packed view over seqlen_q（= M5 jagged 路一字不差） const auto lse_dram = make_naive_tensor_view_packed<...>(lse_ptr, make_tuple(seqlen_q), number<kM0>{});

4  【图2】group packed LSE/D 四方布局溯源

和 M5 一样，LSE/D 被四方触碰（fwd 写 / bwd 读 / PRE 写 / reference 读），是最易 silent-wrong 的对齐点。group 的布局是 packed [head, ΣL]：head stride = ΣL（packed 总 token 数），seq stride = 1，没有 batch 维（group 恒 packed，batches_for_alloc=1）。下图把四方地址画在同一数轴上，证明落同一元素 [h·ΣL + (query_start+sq)]。

图2：group packed LSE/D 的四方地址（fwd 写 ① / MAIN 读 ② / PRE 写 ③ / reference 读 ④）汇聚到同一元素 [h·ΣL + (query_start+sq)]。布局与 M5 jagged 完全相同。

诚实标注 — LSE 数值盲区（沿用 M5）： GPU-bwd 与 CPU reference 共用同一份 GPU-产的 LSE（harness 取回后转置喂 reference），对拍结构上无法独立验证 LSE 的数值正确性——即便整体算错也会「双错相等」而 PASS。闭合方式：①前向写的归一化子正是产 O 所用，写读布局一致 → P_bwd ≡ P_fwd ≡ P_ref；②残余信任锚 = 前向里程碑对 LSE 数值的验证（M5b 未改 fwd 逻辑）。D 同理：reference 自算 D=dO·O、GPU 用 PRE 产 D，二者吃同一份 GPU-fwd O。三方 review 一致判定可接受。

为什么不会重复符号？ hstu_attention_group_forward_bf16.cpp 出现在两处，但属两个不同可执行 target：INTERFACES_SRCS（CMakeLists:6）喂 fwd 例子 tile_example_hstu_attention；BWD_INTERFACES_SRCS（CMakeLists:38）喂 bwd 例子 tile_example_hstu_attention_bwd。两 target 各自独立链接，互不冲突。bwd target 内该 entry 仅列一次；FWD_BF16_INSTANCE_SRCS glob 是 instances/*forward_bf16*.cpp（子目录的 instance TU，符号不同），不含根目录的 entry。干净重建链接成功即铁证（reviewer A1）。

6  范围与后续

  • 本单范围：softmax × group（self-attention）× bf16 × hdim64。前向逻辑零改动（仅 group harness 切 is_training 产 O+LSE）。
  • cross-attention softmax：no_group / group 现均仅 self（kv offsets == q）；cross 待对应里程碑。
  • group 双 pipeline 代码体积（perf M8）：with-local / without-local 两条 softmax pipeline 都实例化进二进制，运行时每 block 只跑一条——同 M4 的已知 perf 取舍，不影响正确性。
  • M6 deterministic / M7 fp16+hdim96-256：group dispatch 已留 throw 门（dispatch:316/319），逻辑不变。
  • 验证包络：α 缩放仅以 α=1 数值验证（贯穿性约束，非 M5b 引入）；LSE/D 数值由前向里程碑兜底（§4 盲区已闭合）。无未解决阻塞点。
