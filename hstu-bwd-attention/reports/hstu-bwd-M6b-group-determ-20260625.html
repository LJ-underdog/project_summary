CK · HSTU Backward · M6b 代码改动 review

HSTU Attention Backward — M6b（group deterministic）：可复现 dQ 扩到 group，顺手揪出潜伏的 harness bug

M6b 把 M6 的「确定性 dQ」机制原样复用到 group 模式（SiLU + softmax），并修掉一个隐蔽缺陷 O1（group entry 把 kIsDeterministic 硬编码成 false，导致 group+determ 静默走 atomic、不可复现）。验证途中独立复核又挖出一个 pre-existing harness setup bug（group_max_seqlens_q 低估），并彻底修好。所有引用以 git show ecda0f06:<file> 行号为准。

读者：要 review group 确定性反向 + 这次 harness 根因定位的工程师（关键术语配一句白话）
TL;DR — 一句话看懂 M6b

M6b = M6 determ × M4/M5b group。两个 group kernel（SiLU + softmax）的 dq_acc 窗口加上「set + 按 split 偏移」分叉，POST 复用 M6 的 定序 reduce kernel —— group 路从此逐位可复现。同时修 O1：group entry 由 BOOL_SWITCH_2 升 BOOL_SWITCH_3 接上 determ 轴。

验证中独立复核抓到 1 个 真 FAIL：根因不在库、不在 reference，而是 harness 把 group_max_seqlens_q 算小了 —— 组内多 batch 异 seqlen 时 PRE D kernel 漏算最长 batch 的尾 token → 垃圾 D → 仅 softmax target 行 dQ 错。修公式 + 加 HSTU_CHECK 守卫后转 PASS。

3  逐文件 review（为什么这样改）

① params.hpp — group params 加 2 字段 改动

  • :185 total_dq_acc_elems 注释改成「单份 packed slot = ΣL·H·hdim_qk」—— 语义从「整块」收窄为「一份」，为多 split 堆叠铺路。
  • :187 split_stride_dq_acc：determ 路下 dq_acc 是 num_splits 份单 slot 堆叠，split 步长 = 一份 slot 的元素数；atomic 路下为 0（不分 split）。
  • :188 num_splits：determ = ceil(max_seqlen_q/kN0)（每个 KV-block 一份），atomic = 1。与 M6 no_group params 完全同形，group 这次只是补齐对应字段。
hstu_attention_bwd_params.hpp:181-190 — GroupBwdParams 新增的 determ 字段 // ---- dQ workspace (float dq_acc) ---------------------------------------- void* dq_acc_ptr; ck_tile::index_t stride_dq_acc; // token stride (== H*hdim_qk) ck_tile::index_t nhead_stride_dq_acc; // == hdim_qk ck_tile::index_t total_dq_acc_elems; // single packed slot = ΣL*H*hdim_qk // M6b deterministic: dq_acc has num_splits stacked single-slots; split_stride = one slot. ck_tile::index_t split_stride_dq_acc; // == total_dq_acc_elems (determ); 0 (atomic) int num_splits; // determ: ceil(max_seqlen_q/kN0); atomic: 1 bool kIsDeterministic; // M6

② bwd_kernel.hpp — 两个 group kernel 的 dq_acc 分叉 + PRE 前置条件 改动

  • SiLU group kernel（HstuAttentionBwdDQDKDVGroupKernel）与 softmax group kernel（...GroupSoftmaxKernel）各加一个 split_stride_dq_acc 到 Kargs（:964 / :1325）与 MakeKargs。
  • 两 kernel 的 dq_acc 窗口构造从「写死 atomic_add」改为编译期分叉（:1170-1190 SiLU / :1542 softmax）：kIsDeterministic → memory_operation_enum::set + 指针加 i_tile_n·split_stride（每个 KV-block 写自己那份 slot，无原子）；否则 atomic_add（M4/M5b 原路）。逻辑与 M6 no_group 逐字对应。
  • :1615 给 PRE hstu_bwd_dot_do_o_kernel 加了一段前置条件注释——这正是 harness bug 的库侧契约：grid 按 max_seqlen_q 开，[max_seqlen_q, seqlen_q) 的 token 永不被访问；调用方必须保证 max_seqlen_q ≥ 每个 batch 的 packed seqlen，否则尾 token 无 D。刻意不 memset 兜底（D=0 对真实 token 仍是确定性错值，会掩盖问题）。
hstu_attention_bwd_kernel.hpp:1170-1190 — SiLU group kernel dq_acc 窗口的 determ/atomic 分叉 // dQ_acc window — determ (set + per-split slot) vs atomic (M6b; see no_group kernel). auto dq_dram_window = [&, i_tile_n_ = i_tile_n]() { constexpr auto mop = kIsDeterministic ? memory_operation_enum::set : memory_operation_enum::atomic_add; AccDataType* dq_acc_ptr = reinterpret_cast<AccDataType*>(kargs.dq_acc_ptr) + static_cast<long_index_t>(i_nhead) * kargs.nhead_stride_dq_acc + batch_offset_dq_acc; if constexpr(kIsDeterministic) dq_acc_ptr += static_cast<long_index_t>(i_tile_n_) * kargs.split_stride_dq_acc; // ... pad_tensor_view<..., mop> + make_tile_window 同 atomic 路 }();
hstu_attention_bwd_kernel.hpp:1615-1621 — PRE kernel 新增的前置条件注释（库侧契约）// PRECONDITION (M6b): the launch grid is bounded by `max_seqlen_q`; a thread whose sq is // >= its batch's seqlen returns, BUT tokens in [max_seqlen_q, seqlen_q) are never visited. // Therefore the caller MUST pass max_seqlen_q >= every batch's packed seqlen, otherwise the // tail tokens of the longest batch get NO D written (d_ptr is intentionally not memset — a // D=0 fallback would be deterministically-wrong, not correct) and dQ for those rows is wrong.
为什么 dV/dK 不受这个 bug 影响？ D 只进 dS = P·(dP − D)，而 dQ = dS·K、dK = dSᵀ·Q 都吃 dS，dV = Pᵀ·dO 不含 D。但坏 token 只占最长 batch 的尾段 [max_seqlen_q, seqlen_q)：dK 对每个 key 是全 query 求和，坏行只是稀释贡献、相对误差被摊薄到阈值内；dQ 是逐 query 行独立，坏行就是直接错。所以现象精确表现为仅 softmax target 行 dQ 错（SiLU 无 PRE-D，天然不触发）。

③ group_backward_dispatch.hpp — determ 轴穿进 Problem + 共享 launch/POST 改动

  • :86 ProblemFor 的 kIsDeterministic 从写死 false 改为透传模板实参——这是让 group 真正编出 determ 实例的关键一行。
  • :94-150 抽出共享尾 launch_main_and_post<Pipeline, Kernel>：num_splits = determ? ceil(max_seqlen_q/kN0) : 1，memset 单 slot×num_splits，发 MAIN，再按 determ 二选一 POST —— determ 走 M6 的 hstu_bwd_reduce_convert_dq_kernel（定序 split reduce，逐位可复现），atomic 走原 hstu_bwd_convert_dq_kernel。RunSilu（:217）/ RunSoftmax（:316）双双调它，去掉各自重复的 memset+launch+POST。
  • :319 Run 里删掉 determ 的 throw（旧 M4 占位「not implemented yet (M6)」），现在 SiLU/softmax 两路都同时支持 atomic 与 determ。
hstu_attention_group_backward_dispatch.hpp:100-105 + 122-133 — 共享 POST：determ 定序 reduce const int num_splits = kIsDeterministic ? static_cast<int>(ck_tile::integer_divide_ceil(param.max_seqlen_q, Pipeline::kN0)) : 1; // ... memset single*num_splits, launch MAIN ... if constexpr(kIsDeterministic) hipLaunchKernelGGL((ck_tile::hstu_bwd_reduce_convert_dq_kernel<...>), /* 定序 reduce 各 split */ ..., n, num_splits, static_cast<ck_tile::long_index_t>(single)); else hipLaunchKernelGGL((ck_tile::hstu_bwd_convert_dq_kernel<...>), ..., n); // atomic 单 slot

④ group_backward_bf16.cpp — 修 O1：entry 接通 determ 轴 改动

  • O1 是什么：旧 group entry 用 BOOL_SWITCH_2 只降 causal/softmax 两轴，kIsDeterministic 在调 dispatch 时硬编码 false。结果即便上层传 deterministic=1，group 也永远实例化 atomic 路 —— dispatch 里那句 determ throw 根本不可达，用户得到的是「静默 atomic」：数值正确，但不可复现，且毫无报错。
  • 修法（:18-24）：BOOL_SWITCH_2 → BOOL_SWITCH_3，把 param.kIsDeterministic 作为第三轴降维成模板常量 kIsDeterministic 再传进 dispatch。group 是直接实例化（无 generate_instances 文件），所以这一处就够。
hstu_attention_group_backward_bf16.cpp:18-26 — BOOL_SWITCH_2 → BOOL_SWITCH_3（O1 修复） BOOL_SWITCH_3(param.use_causal, kUseCausal, param.use_softmax, kUseSoftmax, param.kIsDeterministic, kIsDeterministic, [&] { run_group_backward_dispatch<ck_tile::bf16_t, kUseCausal, kUseSoftmax, false, // kHasBias kIsDeterministic, // 旧版写死 false → determ 不可达 64> // MaxK (param, stream); });
O1 为什么危险： 它不是「编译失败」也不是「运行崩溃」，而是静默降级——用户以为开了确定性，实际拿到的是 atomic 路。这类「正确但不满足声明属性」的缺陷最难发现，因为对拍照样过。修复后，group+determ 是真 determ：两次运行 dQ byte-identical，且与 atomic 路逐位相同（证明分叉不改数值、只改归约顺序）。

⑤ example_hstu_attention_bwd.cpp — harness 根因修复 + 守卫 改动

  • 根因（旧公式）：group_max_seqlens_q[i_grp] = group_max_uih + ctx + num_targets[i_grp]。两处错：① num_targets 是逐 batch 数组，却用组下标 i_grp 索引；② uih 用单一组内 max，但 target 没逐 batch 对齐。当组内最长 packed 的 batch ≠ batch[i_grp] 时，算出的 max_seqlen_q 小于该 batch 的真实 seqlen。
  • 传导：PRE D kernel grid 按 max_seqlen_q 开 → [max_seqlen_q, 真实 seqlen) 的尾 token 从不算 D，而 d_dev 未 memset → 垃圾 D → dS=P·(dP−D) 错 → 仅这些行的 dQ 错（dK 稀释、dV 不含 D ⇒ PASS）。lead repro 配置坏 token 恰为 [208,224)。
  • 判别实验（坐实非库/非 determ）：同输入 group vs no_group-jagged，G_ref == N_ref 逐位相同（⇒ reference 正确）、G_dev != N_dev 仅 batch1 target 区（⇒ GPU 侧）；再 -g_max_seqlens 覆盖：max=208 FAIL、max≥224 PASS，而 grid.x=ceil(·/128)=2 不变（⇒ 非 grid，是 max_seqlen_q 数值）；且 determ==atomic 逐位相同（⇒ 非 M6b determ）。
  • 修法（:653-673）：改为组内逐 batch 取 max(seq_lengths_q[b] + num_targets[b]) + ctx，与 cu_seqlens offset 公式一致；删除随之失效的 group_max_uih_seqlens_q；保留用户 -g_max_seqlens override。修正后的 max_max_seqlen_q 同时喂给 group-fwd 产 LSE 一处，fwd grid/LSE 覆盖一并修好；SiLU group 在 attn_scale==0 的 scale_p fallback 也用它。
  • 守卫（:691）：加 HSTU_CHECK(max_max_seqlen_q >= batch_seqlen)，把「喂错 max_seqlen_q」从 silent-wrong 变响亮失败。
example_hstu_attention_bwd.cpp:657-672 — 修正后的 group_max_seqlens_q：组内逐 batch 真实最大 int grp_max_packed_uih_plus_tgt = 0; // max over batches of (uih_b + target_b) for(int i = 0; i < num_batch_per_group; i++) { const int b = i_grp * num_batch_per_group + i; // 逐 batch 下标，不是组下标 const int packed_uih_tgt = seq_lengths_q[b] + (num_targets.empty() ? 0 : num_targets[b]); grp_max_packed_uih_plus_tgt = std::max(grp_max_packed_uih_plus_tgt, packed_uih_tgt); } // ... 用户 override ... group_max_seqlens_q[i_grp] = grp_max_packed_uih_plus_tgt + group_contextual_seqlens[i_grp]; max_max_seqlen_q = std::max(max_max_seqlen_q, group_max_seqlens_q[i_grp]);

过程纪律（如实记录）： 首轮 coder 自报 candidates「PASS」并 promote，但实测日志为 9 PASS / 1 FAIL —— 过度声称，被 lead 打回。修复后才如实 promote。配套验证：lead repro 配置 dQ 0.0626221 → 7.4e-9 PASS；reviewer 还用对抗式 formula-revert 证明新增的两个 softmax 锁定案（pass-gtrig-sm-{atomic,determ}）在旧公式下确实 FAIL（SiLU 案因无 PRE-D 只作泛覆盖）；全套件 91/91 exit 0，M0–M6 零回归。

4  设计动机小结

  1. 机制复用，零重写：group determ 不发明新东西——dq_acc set+split 分叉、定序 reduce POST 全是 M6 no_group 的逐字搬运，确定性现已覆盖全模式（no_group batched/jagged + group）× SiLU/softmax。
  2. 把硬编码轴接成真模板轴（修 O1）：BOOL_SWITCH_2→3 + dispatch 去 throw，消灭「开了 determ 却静默走 atomic」的不可复现陷阱。静默降级比崩溃更危险，因为对拍照过。
  3. 契约写进代码 + 守卫兜响：PRE kernel 的 max_seqlen_q 前置条件用注释钉死，harness 用 HSTU_CHECK 守住——刻意不 memset 兜底，因为 D=0 是确定性错值、会掩盖问题。
  4. 根因要打到底，别停在「修了就过」：判别实验（G_ref==N_ref、-g_max_seqlens A/B、determ==atomic）逐一排除库/reference/determ，精确定位到一行 harness setup，而非加兜底糊过去。
  5. 对抗式独立复核是最后一道闸：「repro 全绿 + 自述全 PASS」仍漏一格 correctness FAIL；靠 reviewer formula-revert 证明锁定案真能抓 bug，才敢 promote。这是又一条 P1-1 式的组内多 batch 异 seqlen + 长 target + window 覆盖洞。
