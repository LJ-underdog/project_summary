HSTU Attention Backward — M7c（非对称 / 非典范 hdim）：激活那台「已接好但被掐死」的 head-dim pad 机器

M7c 让 bwd 接受 hdim_qk != hdim_v 与任意非典范 head dim（48/80/100/192/200…）——靠的不是新写 padding，而是打开 pre-M7c 已经布线完整、却被喂 constexpr 0 + guard-throw 掐死的那条 pad 通路：用一次运行时 BOOL_SWITCH_2 镜像 fwd 把它点亮，零新增实例。只改 4 个文件，pipeline/kernel/reference 字节级未动。所有引用以 git show fc13643e:<file> 行号为准。

读者：要 review 这套 bwd head-dim padding 激活的工程师（含「为什么不用写新代码」的来龙去脉）
TL;DR — 一句话看懂 M7c

M7c = 把死代码救活。bwd 的每个 DRAM view / LDS window / epilogue 早就 honor kPadHeadDimQ/V（和 fwd 一样),但 M7b 给它们喂的是 constexpr 0、入口又有一道 guard-throw 把非典范 hdim 拦在门外——通路完整却从未通电。M7c 在 dispatch 里用 pad = !(hdim % tile == 0) 派生出真实 pad 标志,经 BOOL_SWITCH_2 镜像 fwd 注入,放松 guard 到只挡 hdim > MaxK。

典范 hdim（pad 全 false）时设备符号与 M7b 294/294 字节级一致;非典范 hdim 用 harness 的 -poison_pad（尾列填 NaN）正面证明 OOB head-dim 的 load-zero / store-skip,而不是靠 bf16 容差糊过去。

3  逐文件 review（为什么这样改）

① bwd_shape.hpp — 取模除数 + workspace 尺寸 改动

  • 每个典范 HstuBwdShape<MaxK> 加 3 个 static constexpr:kQKHeaddim / kVHeaddim(方阵 tile,== MaxK,是 dispatch 里 !(hdim % tile == 0) 取模 pad 的除数)+ kN0(bn0,k-seqlen block,给 harness 的 determ workspace 定大小)。hd64 在 :45-47、hd96 :74-76、hd128 :103-105、hd256 :137-139。
  • hd256 是特例:kN0=64(其余 preset 都是 128),见 :135-136 的 NOTE。bn0 减半 ⇒ determ 的 split 数(ceil(seqlen/kN0))翻倍;harness 的 kN0_bwd 必须读这个值,否则 dq_acc workspace 欠分配 ⇒ determ reduce 越界。
hstu_attention_bwd_shape.hpp:43-47 (hd64) & :135-139 (hd256) — 取模除数 + kN0// M7c: tile head-dim (bhdq/bhdv, square == MaxK) for the pad modulo predicate, and // kN0 (bn0, k-seqlen block) for the harness determ workspace sizing. static constexpr ck_tile::index_t kN0 = 128; // hd64/96/128 都 128 static constexpr ck_tile::index_t kQKHeaddim = 64; static constexpr ck_tile::index_t kVHeaddim = 64; // ── hd256 特例 ── // NOTE kN0=64 (bn0) — half the other presets -> determ split count doubles; harness // kN0_bwd must read this (not a hardcoded 128) or the dq_acc workspace under-allocates. static constexpr ck_tile::index_t kN0 = 64; static constexpr ck_tile::index_t kQKHeaddim = 256; static constexpr ck_tile::index_t kVHeaddim = 256;

② batched dispatch — 把 pad 从死救活 改动

  • RunSilu / RunSoftmax 长出 NTTP:签名从 <typename Mask> 变成 <typename Mask, bool kPadHeadDimQ, bool kPadHeadDimV>(:119 RunSilu、:230 RunSoftmax),函数体里那两行 constexpr kPadHeadDim* = 0 被删掉,改由调用方传入(:122-124 的注释把这件事说死)。
  • 这两个 pad 标志一路喂进早就存在、本次未动的 DRAM-view / epilogue 谓词:(kPadHeadDimQ > 0) 在 :166、(kPadHeadDimV > 0) 在 :171。这就是「机器一直在,只是没通电」的实证——M7c 没碰这些行,只是让上游不再喂 0。
  • guard 放松:M7b 的 hdim_qk!=hdim_v || hdim_qk!=MaxK -> throw 被替换成只挡 hdim<=0 || hdim>MaxK(:375-376)。HDIM_SWITCH 已保证 MaxK >= max(hdim_qk,hdim_v),真正的 hdim>256 reject 仍留在 hstu_attention_hdim_switch.hpp 的 else-throw。
  • 取模派生 + 单次 hoist::378-381 从 shape 取 kQKHeaddim/kVHeaddim,算 pad_qk=!(hdim_qk%kQKHeaddim==0) / pad_v=!(hdim_v%kVHeaddim==0);:385 一次 BOOL_SWITCH_2 把两个运行时 bool 降成 NTTP,SiLU 与 softmax 共用这一层(:389-392 用 if constexpr(kUseSoftmax) 二选一)。
hstu_attention_batched_backward_dispatch.hpp:374-393 — guard 放松 + 取模派生 + BOOL_SWITCH_2// Q-group flag (kQKHeaddim) and V-group flag (kVHeaddim) are tracked SEPARATELY. if(param.hdim_qk <= 0 || param.hdim_v <= 0 || param.hdim_qk > MaxK || param.hdim_v > MaxK) throw std::runtime_error("... hdim_qk/hdim_v must be in (0, MaxK]; hdim>256 unsupported"); constexpr ck_tile::index_t kQKHeaddim = HstuBwdShape<MaxK>::kQKHeaddim; constexpr ck_tile::index_t kVHeaddim = HstuBwdShape<MaxK>::kVHeaddim; const bool pad_qk = !(param.hdim_qk % kQKHeaddim == 0); // fwd 同款取模 const bool pad_v = !(param.hdim_v % kVHeaddim == 0); const bool use_local = (param.window_size > 0); // Hoist the pad BOOL_SWITCH_2 once (fwd style) so SiLU+softmax share it. M7c 最精妙处: QK-group 标志(覆盖 Q/K/dQ/dK/dQ_acc,用 kQKHeaddim)与 V-group 标志(覆盖 V/dO/dV/O,用 kVHeaddim)各自独立追踪、从不交叉——这正是 hdim_qk != hdim_v(非对称)能成立的根:两组用各自的除数取模、各自一支 NTTP,所以一边 pad 一边不 pad 也对。:122-124 的注释把这条边界写死。

  • Run() 镜像 batched:同样的 guard 放松(:310)、同样的取模派生(:312-315)、同样一层 BOOL_SWITCH_2 包住 SiLU/softmax 二选一(:319-323)。

为什么不靠容差? OOB head-dim 的 load-zero / store-skip 是「读到 0 / 不写」的结构性保证,bf16 容差对它无能为力(泄漏值可能恰好在容差内)。poison 把 pad 尾置成 NaN:NaN 一旦被 load 进算式就传染到真实列、被 store 进尾列就留痕——非真即假,无灰区。这是把「容差对拍」升级成「污染传播证明」。

4  设计动机小结

  1. 救活,而非新写:bwd 的 pad 通路在 fwd 同款基建里早已布线完整(DRAM view/LDS window/epilogue 全 honor kPadHeadDim),M7c 只删 constexpr 0 + 放松 guard,把它接上运行时开关——pipeline/kernel/reference 字节级未动。
  2. pad 不是 codegen 轴:严格镜像 fwd,用每个 MaxK 符号内部的 BOOL_SWITCH_2,故零新增实例、典范路径设备符号 294/294 与 M7b 逐字节相同。
  3. QK / V 两组独立取模:用各自 kQKHeaddim/kVHeaddim 派生各自 pad 标志、各走一支 NTTP(:378-381),这才让 hdim_qk != hdim_v 成立——两组从不交叉。
  4. guard 收窄到真边界:只挡 hdim<=0 || hdim>MaxK(:375-376 / group :310);真正的 hdim>256 reject 留给 HDIM_SWITCH else-throw,职责单一。
  5. 正面证明而非容差糊:-poison_pad 用 NaN 尾列把 OOB load-zero / store-skip 变成非真即假的硬断言(:264-341 / :676-700),reverse-proof(强制 pad=false ⇒ NaN FAIL)证明检查非空洞。
