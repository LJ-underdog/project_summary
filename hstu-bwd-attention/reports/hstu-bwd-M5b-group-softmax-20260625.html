HSTU Attention Backward — M5b（group softmax）：合流但不碰已 promoted 的代码

M5b 把 softmax 反向路径落到 group 模式——即「M4 的 group 结构 × M5 的 softmax 路径」合流,补齐了 softmax 在三种模式(batched / jagged / group)上的最后一块覆盖。卖点是复用不重写:M5 softmax pipeline、PRE、POST 逐字复用,M5 no_group 与全部 SiLU 路径 byte-identical(零回归)。本文按最佳阅读顺序逐文件解读,所有引用以 git show f7db567d:<file> 行号为准。

读者:要 review 这套 group softmax bwd 合流改动的工程师(零基础友好,关键术语配一句白话)
TL;DR — 一句话看懂 M5b

M5b = M4 group × M5 softmax 的融合点。它只新写一个 MAIN kernel(HstuAttentionBwdDQDKDVGroupSoftmaxKernel)+ 一条 group dispatch(RunSoftmax)+ 让 group harness 跑 GPU group fwd 产 O+LSE。其余全靠复用:M5 的 with_softmax pipeline、PRE hstu_bwd_dot_do_o_kernel(is_jagged=true)、POST hstu_bwd_convert_dq_kernel 原样调用。

关键洞察:group 永远是 packed(jagged),所以 LSE/D 的 [head, ΣL] 布局与 M5 jagged 路一字不差——这让 M5 写好的 softmax pipeline 直接 mode-agnostic 复用。三个已 promoted 文件(M5 softmax pipeline / SiLU pipeline / no_group dispatch)在本 commit 零 diff。

最精妙处:group = packed = jagged。 group 模式天然把所有 batch 的 token 连续打包成 [head, ΣL],这和 jagged 同款。因此 M5 早已写好、对 batched/jagged 都 mode-agnostic 的 softmax pipeline,在 group 路上无需任何改动就能复用——LSE/D 的 base 公式 i_nhead*ΣL + query_start、seq stride=1 与 M5 jagged 路一字不差(kernel.hpp:1449-1453、1432)。M5b 的工作量因此被压到只新写「装配逻辑」而非「数学」。

3  逐文件 review(为什么这样改)

① params.hpp — group 契约补两字段 改动

  • :164 lse_ptr 注释升级为「softmax path only (M5b);[head, ΣL] seq-continuous packed」——点明 group LSE 的 packed 布局。
  • :167 新增 d_ptr(PRE 产物 D=rowsum(O*dO),softmax 才用)、:168 nhead_stride_lsed(LSE 与 D 共用,== ΣL,group packed 下 seq stride=1)。
  • 只动 HstuAttentionGroupBwdParams(:116 起);no_group 结构体一字未改——M0 立的「params 字段名定死、只加不改结构」军令状继续成立。
hstu_attention_bwd_params.hpp:164-168 — group 契约新增的两个 softmax 字段 const void* lse_ptr; // softmax path only (M5b); [head, ΣL] seq-continuous packed // ---- softmax PRE output (M5b): D = rowsum(O*dO), same [head,ΣL] layout as LSE ---- void* d_ptr; // softmax path only ck_tile::index_t nhead_stride_lsed; // == ΣL (group packed; LSE/D seq stride is 1)

② bwd_kernel.hpp — 新 MAIN kernel(M4×M5 融合点)新增

整个 HstuAttentionBwdDQDKDVGroupSoftmaxKernel 共 359 行,位于 :1214-1565。它 = M4 group kernel 的骨架(per-group 超参 + jagged offset + 双 pipeline 分支)× M5 softmax kernel(LSE/D dram window + softmax pipeline 调用,去 scale_p)。

  • per-group 超参(:1411-1417):i_group = i_batch / num_batch_per_group(readfirstlane 标量化),据此取 per-group 的 window_size/contextual_seqlen/min_full_attn_seqlen。softmax 不读 group_attn_scale/group_max_seqlen——因为 softmax 不用 scale_p,scale 由 LSE 取代。
  • jagged offset + 早退:query_start = q_offsets[i_batch](:1401),if(i_n0 >= seqlen_kv) return;(:1406-1407,M4 同款,group 恒 packed)。
  • LSE/D 定位(:1432、:1449-1453):batch_offset_lsed = query_start(seq stride=1),base = i_nhead*nhead_stride_lsed + batch_offset_lsed,nhead_stride_lsed == ΣL——与 M5 jagged 路一字不差。
  • 双 pipeline 运行时分支(:1536-1560):if(window_size>0) 走 PipelineLocal(with-local mask),else 走 PipelineNoLocal(without-local)——两条都是 M5 softmax pipeline 实例,调用签名无 scale_p(只传 lse/d window, mask, alpha, smem)。
  • 收尾 write_dkdv lambda(:1514 附近)两分支共享,mask 无关。
hstu_attention_bwd_kernel.hpp:1411-1417 — per-group 超参(softmax 不取 scale_p) const index_t i_group = __builtin_amdgcn_readfirstlane(i_batch / kargs.num_batch_per_group); const index_t window_size = reinterpret_cast<const int32_t*>(kargs.group_window_size_ptr)[i_group]; const index_t contextual_seqlen = reinterpret_cast<const int32_t*>(kargs.group_contextual_seqlen_ptr)[i_group]; const index_t min_full_attn_seqlen = reinterpret_cast<const int32_t*>(kargs.group_min_full_attn_seqlen_ptr)[i_group];
hstu_attention_bwd_kernel.hpp:1536-1560 — 双 pipeline 分支,调用无 scale_p(对比 SiLU 路多传 scale_p) if(window_size > 0) { const int eff_min_full = (seqlen_q - num_target > min_full_attn_seqlen) ? min_full_attn_seqlen : (seqlen_q - num_target); auto mask = make_hstu_self_attention_block_mask_with_local<LocalMask>( /*is_tile_in_first_split=*/true, seqlen_q, contextual_seqlen, num_target, window_size, eff_min_full); auto [dk_acc_tile, dv_acc_tile] = PipelineLocal{}(q_dram_window, k_dram_window, v_dram_window, do_dram_window, lse_dram_window, d_dram_window, dq_dram_window, mask, kargs.alpha, smem_ptr); // 注意:无 scale_p,scale 由 LSE 取代 write_dkdv(dk_acc_tile, dv_acc_tile); } else { auto mask = make_hstu_self_attention_block_mask_without_local<NoLocalMask>( seqlen_q, contextual_seqlen, num_target); auto [dk_acc_tile, dv_acc_tile] = PipelineNoLocal{}(q_dram_window, k_dram_window, v_dram_window, do_dram_window, lse_dram_window, d_dram_window, dq_dram_window, mask, kargs.alpha, smem_ptr); write_dkdv(dk_acc_tile, dv_acc_tile); }
融合的精髓: M4 group kernel 的双 pipeline 分支结构(window_size>0 选 with/without-local)和 M5 softmax kernel 的 LSE/D window + 无-scale_p 调用,是两套正交的逻辑。M5b 没有重写任何一套,而是把 M4 的「选哪条 pipeline」骨架里的 pipeline 实例换成 M5 的 softmax pipeline,并补上 LSE/D window 的构造。359 行里没有新的反向数学,全是装配。

③ group_backward_dispatch.hpp — group RunSoftmax(去 throw)改动

  • :21 include hstu_attention_with_softmax_bwd_pipeline.hpp——把 M5 写好的 softmax pipeline 引进 group dispatch。
  • :191-313 新增 RunSoftmax:镜像 M5 no_group 的四段式——PRE(hstu_bwd_dot_do_o_kernel,is_jagged=true 见 :232,group packed [head,ΣL] = jagged 同款)→ memset dq_acc → MAIN(launch GroupSoftmaxKernel)→ POST(hstu_bwd_convert_dq_kernel 原样复用)。
  • 两条 pipeline 均实例化自 HstuAttentionWithSoftmaxBwdDQDKDVPipelineKRKTRVR(:202-204),LocalMask/NoLocalMask 由 kUseCausal 编译期选。
  • :320-321 kUseSoftmax 分支从 throw 改为调 RunSoftmax;SiLU 分支(:323 RunSilu)逐字不变。
hstu_attention_group_backward_dispatch.hpp:317-323 — kUseSoftmax 分支去 throw,SiLU 分支不变 if constexpr(kIsDeterministic) throw std::runtime_error("... deterministic ... (M6)"); else if constexpr(kUseSoftmax) RunSoftmax(param, stream); // M5b — 此前是 throw "(M5)" else RunSilu(param, stream); // SiLU 路逐字不变

4  设计动机小结

  1. 复用不重写,合流即装配:M5 softmax pipeline、PRE(is_jagged=true)、POST 全部逐字复用;359 行新 kernel 里没有新的反向数学,只是把 M4 group 骨架的 pipeline 槽位换成 M5 softmax 实例。
  2. group = packed = jagged,所以 mode-agnostic 生效:LSE/D base = i_nhead*ΣL + query_start、seq stride=1(kernel.hpp:1432/1449-1453)与 M5 jagged 路一字不差,这是 pipeline 能直接复用的物理前提。
  3. softmax 不用 scale_p:per-group 仍取 window/contextual/min_full(:1411-1417),但 scale 由 LSE 取代——双 pipeline 调用签名去掉 scale_p(:1536-1560)。
  4. GPU 产 LSE 同喂两侧:harness 跑 group fwd(is_training=true)产的同一份 LSE,既喂 GPU-bwd 又(转置后)喂 reference(harness:815/827),保证两侧 P 一致——延续 M5 策略。
  5. 不碰已 promoted 代码 = 零回归:M5 softmax pipeline / SiLU pipeline / no_group dispatch 三文件在本 commit byte-identical,只在 dispatch 的 kUseSoftmax 分支把 throw 换成调用(:320-321),SiLU 分支不动。
