HSTU Attention Backward — M7b（对称 hdim）：让 tile 形状成为 MaxK 的编译期函数

M7b 解禁对称 head-dim（hdim_qk==hdim_v）∈ {64,96,128,256}。核心洞察:pre-M7b 的 dispatch 虽然按 MaxK 模板化,却硬编码了 hd64 的 tile 形状——MaxK 只流进实例符号、没流进 shape,直接加 headdim 轴会静默复用 hd64 tile（silent-wrong）。本文按最佳阅读顺序逐文件解读,所有行号以 git show c9fe2891:<file> 为准。

读者：要 review 这次 head-dim 扩展的工程师（关键术语配一句白话）
TL;DR — 一句话看懂 M7b

M7b 把「tile 形状」从 dispatch 里硬编码的 hd64 常量抽成一个编译期 selector HstuBwdShape<MaxK>(新建头文件),其中 <64> 与原硬编码逐字等价——这是 hd64 零回归的基石;<96/128/256> 各按 FMHA bwd codegen 蓝本给出自己的 tile。两个 dispatch 改取 selector,3 处「hd64 only」的 throw 换成典范 guard(hdim_qk!=hdim_v || hdim_qk!=MaxK),挡住 HDIM_SWITCH 静默向上取整带来的 silent-wrong。

分两阶段交付:stage1 纯重构(selector+guard+kN0)先证 hd64 byte-identical 零回归,stage2 才把 headdim 轴加进生成器(48 新实例)。reference / pipeline / kernel 逻辑一行未碰(git diff 空)。

3  逐文件 review（为什么这样改）

① bwd_shape.hpp — tile 形状的编译期 selector（核心）新增

  • :9-27 头部注释钉死设计契约:pre-M7b dispatch 按 MaxK 模板化但硬编码 hd64 tile → MaxK 只进符号不进 shape;本文件把 TileFmhaBwdShape 变成 MaxK 的编译期函数。tile 蓝本 = upstream FMHA bwd codegen gfx950/CDNA4(非 trload fp16/bf16)的 fmha_bwd.py 预设。
  • :29-30 primary template 故意只声明不定义——只有四个典范 hdim 有特化,传别的值编译期直接报错(又一道防线)。
  • :33-55 HstuBwdShape<64>:FmhaBlockTile = sequence<32,128,64,32,64,32,32,64,64> 等所有模板实参,与 pre-M7b dispatch 里硬编码的预设逐字等价(零回归不变式;:24-27 注释)。
  • :57-80 <96>:注意 BlockWarps2 = sequence<2,2,1>——Gemm4 的 warp layout 与 64/128/256 不同(:57 注释点明)。
  • :82-105 <128>:bm0=16(q-seqlen block)比 64/96 的 32 小;FmhaBlockTile = sequence<16,128,128,16,128,16,32,128,128>。
  • :107-133 <256>:bm0=16, bn0=64(:114)。:107-110 注释警示:bn0=64 意味着 determ split 数(ceil(seqlen/kN0))相对 128-bn0 的预设翻倍,harness 的 dq_acc workspace 必须按 kN0=64 算,否则 determ reduce 越界——这正是 ⑦ harness 改动的根因。
hstu_attention_bwd_shape.hpp:33-43 — HstuBwdShape<64> 与 pre-M7b 硬编码逐字等价// hd64 — byte-identical to the pre-M7b hardcoded preset in both dispatches. template <> struct HstuBwdShape<64> { using FmhaBlockTile = ck_tile::sequence<32, 128, 64, 32, 64, 32, 32, 64, 64>; using BlockWarps0 = ck_tile::sequence<1, 4, 1>; using BlockWarps1 = ck_tile::sequence<4, 1, 1>; using BlockWarps2 = ck_tile::sequence<1, 4, 1>; using WarpTile0 = ck_tile::sequence<16, 16, 32>; // CDNA4 K-doubled MFMA using WarpTile1 = ck_tile::sequence<16, 16, 16>; using Type = ck_tile::TileFmhaBwdShape<FmhaBlockTile, ... 0 /* kMaxSeqLenQ */>; };
为什么 hd256 的 bn0 单独是 64? hdim 越大,单个 KV block 的 tile 占 LDS 越多;hd256 用满 CDNA4 的 64KB/CU LDS,只能把 bn0 缩到 64 才放得下。这个非对称恰好把「workspace 大小依赖 tile bn0」这件原本被 128 常量掩盖的事暴露出来,所以 harness 不能再写死 128。

② batched_backward_dispatch.hpp — 取 selector + 典范 guard 改动

  • :44-47 删掉原来 ~20 行硬编码 tile,改成一行 using FmhaBwdShape = typename HstuBwdShape<MaxK>::Type;。MaxK 现在真正驱动 shape。
  • :377-380(softmax 分支)与 :396-399(SiLU 分支):原来的 hdim_qk!=64||hdim_v!=64 throw,换成 典范 guard hdim_qk!=hdim_v || hdim_qk!=MaxK。注释(:374-376)讲清:MaxK 是 HDIM_SWITCH 向上取整选的典范 tile,必须要求 hdim==MaxK 让 head-dim 精确贴合 tile(无 pad),否则非典范 hdim 会被静默套到更大 tile。
  • 非对称(hdim_qk!=hdim_v)和任意非典范 hdim 的 pad 路径明确划给 M7c(fc13643e)。
hstu_attention_batched_backward_dispatch.hpp:373-380 — softmax 分支的典范 guard// M5/M7b: softmax (no_group = batched + jagged). symmetric hdim ∈ {64,96,128,256}. // MaxK is the canonical tile picked by HDIM_SWITCH; require hdim_qk==hdim_v==MaxK so // the head-dim fits the tile exactly (no padding) — reject non-canonical hdims that // HDIM_SWITCH would silently round up to a larger tile (M7c handles pad). if(param.hdim_qk != param.hdim_v || param.hdim_qk != MaxK) throw std::runtime_error( "HSTU bwd softmax supports symmetric hdim_qk==hdim_v in {64,96,128,256} only");

4  设计动机小结

  1. 把硬编码常量抽成编译期函数:tile 形状从 dispatch 内联常量(silent 复用 hd64)变成 HstuBwdShape<MaxK>(bwd_shape.hpp:29-133),让 MaxK 真正驱动 shape。
  2. 零回归不变式可验证:HstuBwdShape<64> 与原硬编码逐字等价 → hd64 maxk_64 实例 byte-identical → 106 子集全绿,改重构而非改逻辑。
  3. 把 silent-wrong 变成 loud-throw:HDIM_SWITCH 向上取整 + dispatch 典范 guard(hdim_qk!=hdim_v||hdim_qk!=MaxK),非典范/非对称 hdim 一律显式报错,不静默跑错。
  4. 生成器优先:headdim 只在 generate_instances.py:178 加一条轴,48 个实例自动 fan-out,杜绝手写漂移。
  5. workspace 随 tile 自适应:hd256 bn0=64 暴露了被 128 常量掩盖的 split-count 依赖,harness 改 kN0_bwd=f(hdim) 修正 determ 越界。
  6. 分阶段交付:stage1 纯重构(selector+guard+kN0)证零回归,stage2 才加 hdim——风险隔离,先锁不变量再扩能力。
