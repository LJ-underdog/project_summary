CK · HSTU Backward · M3 代码改动 review

HSTU Attention Backward — M3（jagged 变长）：一个 kernel，靠运行时分支吃下两种布局

M3 让 SiLU+bf16+hd64 反向支持 jagged（变长 packed [1,ΣL,H,D]）模式。卖点是零新增 kernel 实例——同一 SiLU MAIN kernel 靠运行时 is_jagged 选 base offset / 反推 per-batch seqlen，batched 路径行为零变化。本文按依赖顺序逐文件解读每处改动的动机，所有行号以 git show 94174bd9:<file> 为准。

读者：要 review 这套 bwd jagged 改动的工程师（零基础友好，关键术语配一句白话）
TL;DR — 一句话看懂 M3

M3 = 变长 packed 寻址，不动算法、不加实例。把 batched 的「i_batch * batch_stride」base offset 换成 jagged 的「offsets[i_batch] * seq_stride」（token-major，镜像 fwd kernel），并从 cu_seqlens 反推每个 batch 的真实 seqlen_q/seqlen_kv；其后 window/mask/OOB 逻辑全部布局无关地复用。grid 按 max_seqlen_q 开，短 batch 的越界 KV-tile 用一句 early-exit 退出。

因为差异全在「运行时算哪个 base offset」，batched 与 jagged 共用同一个编译实例——这是「运行时分支 vs 编译期实例」取舍里偏向前者的典型案例。

1  总览：M3 到底改了什么

一句话三件事——kernel 学会读 offsets、dispatch 学会按模式喂参数、harness 学会摆 packed 数据：

kernel
offset 二选一 + early-exit
Kargs 加 is_jagged+两个 offsets 指针（kernel:73-75）；operator() 把 base offset 改成 if(is_jagged){…}else{…}（:247-275），jagged 反推 per-batch seqlen 并 i_n0>=seqlen_kv 早退（:279）。
dispatch
去 throw、按模式定尺寸
删掉 jagged throw（M0 占位）；MakeKargs 接 offsets（dispatch:133-137）；dq_acc memset 字节数与 grid.x 按 is_jagged 选（:174-186）。
harness
-jagged + cu_seqlens
新增 -jagged 开关；packed alloc（batches_for_alloc=1，harness:206）+ 前缀和 offsets（:186-194）；CPU reference 走 BOOL_SWITCH_3 的 kIsJagged=true（:436）。
M3 最精妙处： jagged 分支只改了「base offset 怎么算」+「seqlen 从哪来」两件事，然后覆盖 kargs.seqlen_q/seqlen_kv（kernel:263-264）。一旦 seqlen 被改写成 per-batch 真值，后面所有的 window 计算、5 因子 mask、OOB buffer-load 全都原封不动复用——它们只看 kargs.seqlen_*，不关心数据是矩形还是锯齿。这就是「零新增实例」能成立的根因。

3  逐文件 review（为什么这样改）

① bwd_kernel.hpp — jagged 寻址核心 改动

  • :73-75 Kargs 新增三字段：bool is_jagged + seq_q_offsets_ptr / seq_kv_offsets_ptr（int32，size num_batch+1，self-attn 时 kv==q）。注释（:69-72）写明 jagged 下标量 seqlen_q/seqlen_kv 会被忽略。
  • :124-126 / :168-170 MakeKargs 增三个形参并赋值——契约在 M0 已预冻结，这里只是把字段接通。
  • :247-274 operator() 里原来一段「batched offsets」改成 if(kargs.is_jagged){…}else{…}：jagged 取 query_start=q_offsets[i_batch]、key_start=kv_offsets[i_batch]，各 batch_offset_* = start * stride_*（q/do/dq_acc 用 query_start；k/v/dk/dv 用 key_start，:254-260）。
  • :263-264 覆盖 per-batch seqlen：kargs.seqlen_q = q_offsets[i_batch+1] - q_offsets[i_batch]，kv 同理。这是「布局无关复用」的钥匙——窗口/mask/OOB 后面只看这两个值。
  • :279-280 early-exit：if(i_n0 >= kargs.seqlen_kv) return;。grid.x 按 max 尺寸开，短 batch 越界的 KV-tile 直接退；batched grid 精确 → 此分支永不触发，故 batched 行为零变化。
hstu_attention_bwd_kernel.hpp:247-280 — base offset 二选一 + 反推 seqlen + early-exitif(kargs.is_jagged) { const auto* q_offsets = reinterpret_cast<const int32_t*>(kargs.seq_q_offsets_ptr); const auto* kv_offsets = reinterpret_cast<const int32_t*>(kargs.seq_kv_offsets_ptr); const long_index_t query_start = q_offsets[i_batch]; // token-major base, 镜像 fwd const long_index_t key_start = kv_offsets[i_batch]; batch_offset_q = query_start * kargs.stride_q; // q/do/dq_acc 用 query_start batch_offset_k = key_start * kargs.stride_k; // k/v/dk/dv 用 key_start // ... v / do / dk / dv / dq_acc 同理 ... kargs.seqlen_q = q_offsets[i_batch + 1] - q_offsets[i_batch]; // 覆盖标量 → per-batch 真值 kargs.seqlen_kv = kv_offsets[i_batch + 1] - kv_offsets[i_batch]; } else { batch_offset_q = static_cast<long_index_t>(i_batch) * kargs.batch_stride_q; // batched: i_batch*stride // ... 其余同 ... } // jagged: grid.x 按最长序列开,越界 KV-tile 无活. (batched grid 精确 -> 永不触发) if(i_n0 >= kargs.seqlen_kv) return;
为什么 q 用 query_start、k/v 用 key_start？ packed 布局是 token-major [1,ΣL,H,D]：Q/dO/dQ 沿 query 轴排，K/V/dK/dV 沿 key 轴排。self-attention 下两套 offsets 相等，但分开写让 cross-attention（独立 kv offsets）将来零成本接入。

② batched_backward_dispatch.hpp — 去占位、按模式定尺寸 改动

  • :211-213 Run() 顶部加注释点明设计：jagged 由同一 SiLU MAIN kernel 处理，差异仅 base offset/seqlen，运行时由 is_jagged 选 ——无独立实例。同时删掉 M0 留下的 if(param.is_jagged) throw …(M3) 占位。
  • :133-137 MakeKargs 传 param.is_jagged + q offsets；kv offsets 按 is_cross_attention ? seq_kv_offsets_ptr : seq_q_offsets_ptr（self 时 kv 喂 q）。
  • :174-180 dq_acc 清零字节数：jagged 用 batch_stride_dq_acc（=dim0 stride=全量 ΣL·H·hdim），batched 用 num_batch * batch_stride_dq_acc。POST elementwise cast 复用同一 dq_acc_elems（:195），packed 连续 buffer 同样成立。
  • :184-186 grid.x 的 seqlen_kv：jagged 用 param.max_seqlen_q（self 时 == max_seqlen_kv），batched 用 param.seqlen_kv——配合 kernel 的 early-exit 兜住短 batch。
hstu_attention_batched_backward_dispatch.hpp:174-186 — dq_acc memset 字节数 + grid.x 按模式// batched 布局 [num_batch, sq, h, hdim]; jagged 是 dim0=1 packed [1, ΣL, h, hdim], // 其 dim0 stride (batch_stride_dq_acc) 即全量元素数. const size_t dq_acc_elems = param.is_jagged ? static_cast<size_t>(param.batch_stride_dq_acc) : static_cast<size_t>(param.num_batch) * static_cast<size_t>(param.batch_stride_dq_acc); HIP_CHECK_ERROR(hipMemsetAsync( param.dq_acc_ptr, 0, dq_acc_elems * sizeof(typename TC::GemmAccDataType), stream)); // jagged: grid.x 必须覆盖最长 per-batch seqlen_kv (self-attn 时 == max_seqlen_q); // 超出某 batch 长度的 KV-tile 在 kernel 内 early-exit. const ck_tile::index_t grid_seqlen_kv = param.is_jagged ? param.max_seqlen_q : param.seqlen_kv; dim3 grid = Kernel::GridSize(param.num_batch, param.num_head, grid_seqlen_kv);

③ example_hstu_attention_bwd.cpp — packed 数据 + cu_seqlens + 对拍 改动

  • :96 新增 -jagged 开关；:95 -seqlens 说明升级为「batched:单值；jagged:逗号列表，supplement 到 num_batch」。:154 仅 batched 才强制单值；:160-161 jagged 把 per-batch 列表补齐到 num_batch。
  • :186-194 构造 cu_seqlens 前缀和：seq_offsets_q.push_back(0) 起步，每 batch 的物理长 = seqlens[i] + num_target[i] + contextual（镜像 fwd harness），累加得 phy_seqlen_q=ΣL。:195 self 下 phy_seqlen_kv=phy_seqlen_q；:203 kv offsets 别名 q offsets。
  • :206 batches_for_alloc = is_jagged ? 1 : num_batch——所有 Q/K/V/O/dO/dQ/dK/dV/dq_acc 按 [1, ΣL, H, D] packed 分配（:212-237）。
  • :266 / :279-280 offsets 上 device；:291-296 与 :346-351 把 is_jagged + offsets 指针喂给 GPU fwd 参数（产 O，避免 packed 上越界）与 GPU bwd 参数。
  • :436-441 CPU reference 由 BOOL_SWITCH_2 升级为 BOOL_SWITCH_3，多降一个 is_jagged → kIsJagged 模板常量，调 reference_no_group_hstu_attention_bwd<…, kIsJagged, …>（:433-434 jagged 传真 offsets，batched 传 empty）。
example_hstu_attention_bwd.cpp:186-203 — 构造 cu_seqlens 前缀和（token-major packed）if(is_jagged) { seq_offsets_q.push_back(0); for(int i = 0; i < num_batch; i++) { const int batch_seqlen = seq_lengths_q[i] + (num_targets.empty() ? 0 : num_targets[i]) + contextual_seqlen; phy_seqlen_q += batch_seqlen; // 累加 = ΣL seq_offsets_q.push_back(phy_seqlen_q); // 前缀和 → cu_seqlens } phy_seqlen_kv = phy_seqlen_q; // self-attention } else { phy_seqlen_q = max_seqlen_q; phy_seqlen_kv = max_seqlen_kv; } const std::vector<int>& seq_offsets_kv = seq_offsets_q; // self-attention: kv 别名 q
为什么 GPU fwd 也要喂 offsets？ SiLU 路径的 bwd 本身不依赖 fwd 的 O，但 harness 仍先跑 GPU fwd 产 O；packed 布局下若 fwd 用 batched 寻址会越界踩别的 batch 的数据。喂 is_jagged+offsets 保证 fwd 也按锯齿正确寻址（harness:291-296）。

4  一图看懂：batched 矩形 vs jagged 锯齿

batched 把每个 batch padding 到 max_seqlen 摆成规整矩形（dim0=num_batch）；jagged 把所有 batch 的真实 token 首尾相接 packed 成一条（dim0=1，长度 ΣL），用 cu_seqlens 前缀和指针标出每段起点。grid 仍按 max 开 → 短 batch 多出来的 KV-tile 由 kernel i_n0>=seqlen_kv 早退。

橙色指针 = cu_seqlens 前缀和;每个 batch 的 base offset 与 per-batch seqlen 都由相邻两项算出。batched 的 pad 区(灰虚线)被 jagged 完全省掉。

5  设计动机小结

  1. 运行时分支换零新增实例：jagged 与 batched 仅 base offset/seqlen 不同,用一个 is_jagged 在 kernel 内二选一(kernel:247),共用同一编译实例。代价是每线程一次分支,收益是不爆实例数、不增编译时间(dispatch:211-213)。
  2. 覆盖 seqlen 让下游布局无关:jagged 反推 per-batch seqlen 后覆盖 kargs.seqlen_*(kernel:263-264),window/mask/OOB 全部原样复用——这是「不动算法」的关键。
  3. grid 按 max + kernel early-exit:grid.x 用 max_seqlen_q 统一开(dispatch:184-186),短 batch 越界 tile 一句 return 退(kernel:279);batched grid 精确 → 该分支永不触发,batched 零回归。
  4. 镜像 fwd 的 packed 寻址:token-major base=offsets[i]·seq_stride 与 fwd kernel 完全一致,降低 host 构造与心智成本;q/kv offsets 分开存,为 cross-attention 预铺。
  5. harness 三处同源喂 offsets:GPU fwd / GPU bwd / CPU reference 都吃同一套 cu_seqlens(harness:291-296 / 346-351 / 433-441),packed 无 padding(ΣL 精确)→ 每个 token 都被双方写到,全 buffer 对拍合法。
