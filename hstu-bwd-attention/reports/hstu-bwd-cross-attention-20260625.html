CK · HSTU Backward · cross-attention 代码改动 review

HSTU Attention Backward — cross-attention（seqlen_q≠seqlen_kv）：mask 解钉，几何放开

本里程碑让 bwd 正确处理 q 与 kv 各自独立、长度不等的注意力。机制极轻:bwd 在内存/grid/loop 上本就 cross-ready（kv offsets 早已接线），唯一的钉子是 mask 被硬编码成 self（HstuBlockMasking<false>）。修法 = 把它换成运行时 BOOL_SWITCH(is_cross_attention) 选的 kIsCrossAttention 轴。所有行号锚定 commit f2f55622。

读者：要 review 这套 bwd cross 支持的工程师（关注「为什么改动这么小却覆盖全矩阵」）
TL;DR — 一句话看懂 cross

cross-attention = 把一个钉子拔掉。dispatch 5 处 mask typedef 的硬编码 <false> 包进 BOOL_SWITCH(is_cross_attention)，kernel 4 处 mask 构造用 if constexpr(kIsCrossAttention) 分叉到 make_hstu_cross_attention_block_mask_*（把 seqlen_kv 喂进 seqlen_k 槽），再给 params 加 1 个纯 host 字段 max_seqlen_kv（device MakeKargs 不读 → 设备码不变）。

两大利好:① cross 是运行时 switch、不是 instance 轴 → 零 instance 增长;② CPU reference 本就 cross-ready → 对拍 oracle 一行未改。self 腿 max_seqlen_kv==max_seqlen_q → byte-identical 零回归。

1  总览：cross-attention 到底改了什么

本质只有一处语义改动（mask 的 self/cross 选择），其余都是把它喂进既有机器:

核心
mask 解钉为运行时轴
dispatch 把 HstuBlockMasking<false> 包进 BOOL_SWITCH(is_cross_attention);5 处 mask-typedef（batched 1 + group 2×2）统一处理。
kernel
4 处 cross builder 分叉
if constexpr(FmhaMask::kIsCrossAttention) 切到 make_hstu_cross_attention_block_mask_*，把 seqlen_kv 喂进 seqlen_k 槽;self 腿逐字保留。
契约
+1 纯 host 字段
params 加 max_seqlen_kv（bwd_params.hpp:33-34/:128-130）;device MakeKargs 不读 → 设备码不变;bwd 是 KV-block 并行,故 grid/num_splits 按它。
验证
harness 解钉独立 kv
harness 加 -seqlens_kv + 独立 kv offsets + max_seqlen_kv;reference 本就 cross-ready,只多喂 kv 维度。
为什么改动这么小? jagged（M3）早就把独立的 q/kv offsets 接进了内存视图与循环边界——bwd 处理「两条独立序列」的骨架其实从 M3 起就在。cross 与 self 的唯一真区别是 mask 几何:self 假设 q、kv 同一条序列（对角线对齐 row=col），cross 必须用独立 seqlen_kv 计算 row↔col 偏移。所以本里程碑只需放开那个被钉死的 mask 模板形参，其余全是复用。

3  逐文件 review（为什么这样改）

① params.hpp — +max_seqlen_kv（纯 host 字段）改动

  • :33-34（no_group）/ :128-130（group）各加 1 个字段 max_seqlen_kv。注释点死设计意图:「bwd is KV-block-parallel … self path: caller sets max_seqlen_kv == max_seqlen_q → grid/num_splits unchanged → byte-identical」。
  • 为什么是 host-only:device 的 MakeKargs 不读这个字段,它只在 host 端用来算 grid/num_splits。device kargs 不变 ⇒ 设备符号一字未动——这正是 self 腿 byte-identical 的根。
  • 没有改 q/k/v 任何指针或 stride:jagged 的独立 kv offsets（seq_kv_offsets_ptr）从 M3 起就在,cross 不需要新内存契约。
hstu_attention_bwd_params.hpp:31-34 — no_group params 的 cross 字段 ck_tile::index_t max_seqlen_q; // jagged mode only // cross-attention KV grid sizing (bwd is KV-block-parallel). self path: caller sets // max_seqlen_kv == max_seqlen_q -> grid/num_splits unchanged -> byte-identical. ck_tile::index_t max_seqlen_kv; // jagged mode only

② batched_backward_dispatch.hpp — mask 解钉 + grid 按 kv 放大 改动

  • :393-400 解钉的核心一拳:原本 using Mask = HstuBlockMasking<false /*cross*/, …> 现在外包一层 BOOL_SWITCH(param.is_cross_attention, kIsCrossAttention),模板首参由硬编码 false 变成 kIsCrossAttention。注释言明这镜像 fwd dispatch（cross 是运行时 switch、不是 instance 轴,两腿编进同一 .cpp）。
  • 包在哪一层很关键:该 switch 嵌在 BOOL_SWITCH_2(pad) + BOOL_SWITCH(use_local) 内层,只包 mask typedef + 下游 Pipeline/Kernel——false 腿解析成与 M7c 完全相同的 HstuBlockMasking<false,…>::Type ⇒ byte-identical。
  • :65-69 grid 按 kv 维度放大:grid_seqlen_kv = is_jagged ? max_seqlen_kv : seqlen_kv（原来 jagged 路用的是 max_seqlen_q）。bwd 是 KV-block 并行,当 seqlen_kv > seqlen_q 时若仍按 q 维度铺 grid,尾部 KV-block 会被静默漏掉 → 静默错误。self 路 max_seqlen_kv==max_seqlen_q ⇒ 数值不变。
hstu_attention_batched_backward_dispatch.hpp:388-400 — mask 从硬编码 self 解钉成运行时 cross 轴 BOOL_SWITCH(use_local, kUseLocal, [&] { // cross-attention is a RUNTIME switch (mirrors fwd dispatch :97), not an // instance axis: both legs compile in the same .cpp. ... BOOL_SWITCH(param.is_cross_attention, kIsCrossAttention, [&] { using Mask = typename ck_tile:: HstuBlockMasking<kIsCrossAttention, kUseCausal, kUseLocal>::Type; if constexpr(kUseSoftmax) RunSoftmax<Mask, kPadHeadDimQ, kPadHeadDimV>(param, stream); else RunSilu<Mask, kPadHeadDimQ, kPadHeadDimV>(param, stream); }); });
cross 最精妙处:零 instance 增长。 cross/self 编进同一个 .cpp 同一个 instance,靠运行时 BOOL_SWITCH 在两腿间选,而非新增 codegen 轴。这意味着既有 64 个 batched bwd instance 数量一个不多,编译矩阵不膨胀;代价仅是每个 instance 内多一个 if constexpr 分支(false 腿被死代码消除,故 self byte-identical)。

③ group_backward_dispatch.hpp — 双 pipeline 共包一个 cross switch 改动

  • group 的 RunSilu（:147-151）与 RunSoftmax（:217-221）各把 local + no-local 两条 mask typedef 一起包进同一个 BOOL_SWITCH(param.is_cross_attention)——因为 group kernel 在运行时按「是否 with-local」二选一双 pipeline,两条都得同步走 cross。
  • :101 grid + num_splits 改用 max_seqlen_kv:GridSize(num_batch, num_head, param.max_seqlen_kv) 与 integer_divide_ceil(param.max_seqlen_kv, kN0)（原本都是 max_seqlen_q）。self 路别名回 max_seqlen_q ⇒ 不变。
  • 这是这 5 处 mask-typedef 站点的最后两处（batched 1 + group RunSilu 的 local/no-local 2 + group RunSoftmax 的 local/no-local 2 = 5）。
hstu_attention_group_backward_dispatch.hpp:147-151 — group RunSilu 把 local/no-local 双 mask 一起 cross 化 BOOL_SWITCH(param.is_cross_attention, kIsCrossAttention, [&] { using LocalMask = typename ck_tile::HstuBlockMasking<kIsCrossAttention, kUseCausal, true>::Type; using NoLocalMask = typename ck_tile::HstuBlockMasking<kIsCrossAttention, kUseCausal, false>::Type;

④ bwd_kernel.hpp — 4 处 mask builder 喂 seqlen_kv 进 seqlen_k 槽 改动

  • 4 个 kernel 各在 mask 构造处加 if constexpr(FmhaMask::kIsCrossAttention) 分叉:no_group SiLU :407、no_group softmax :854、group SiLU :1267、group softmax :1652。每处又分 with-local / without-local 两子调用。
  • cross 腿走 make_hstu_cross_attention_block_mask_with_local / _without_local,把 kargs.seqlen_kv 喂进 seqlen_k 槽;self 腿逐字保留原 make_hstu_self_attention_* 调用。
  • 为什么必须走 wrapper:cross/self 两个 mask 构造器的参数顺序不同（cross 多一个 seqlen_kv 实参,with-local 包装器把 num_target 重排到末位）——直接拼 ctor 极易错位。统一走 make_hstu_* wrapper 保证参序与 reference 调用点逐字对齐（done §3 R2/R3）。
  • if constexpr 让 self（false）腿被死代码消除 ⇒ self 编出来与 M7c byte-identical。
hstu_attention_bwd_kernel.hpp:407-422 — no_group SiLU with-local mask builder 的 cross 分叉 if constexpr(FmhaMask::kIsCrossAttention) { return make_hstu_cross_attention_block_mask_with_local<FmhaMask>( /*is_tile_in_first_split=*/true, kargs.seqlen_q, kargs.seqlen_kv, // <- 喂进 seqlen_k 槽 kargs.contextual_seqlen, num_target, kargs.max_attn_len, eff_min_full); } else { return make_hstu_self_attention_block_mask_with_local<FmhaMask>( /*is_tile_in_first_split=*/true, kargs.seqlen_q, kargs.contextual_seqlen, num_target, kargs.max_attn_len, eff_min_full); }

4  设计动机小结

  1. 拔钉而非重写:bwd 内存/grid/loop 从 M3 起就吃独立 q/kv offsets,唯一阻碍是 mask 被钉死 HstuBlockMasking<false>。cross = 把这颗钉子换成运行时轴,语义新写量为零。
  2. 运行时 switch 而非 instance 轴:BOOL_SWITCH(is_cross_attention) 把 cross/self 编进同一 instance（dispatch:393-400），零 instance 增长、编译矩阵不膨胀。
  3. 纯 host 字段保 byte-identical:max_seqlen_kv（params:33-34）device MakeKargs 不读,self 腿 == max_seqlen_q ⇒ 设备符号一字未动。
  4. 统一走 mask wrapper:4 处 kernel builder（:407/:854/:1267/:1652）都经 make_hstu_cross_attention_block_mask_* 而非直拼 ctor,保参序与 reference 逐字对齐（R2/R3）。
  5. reference 复用为 oracle:CPU reference 早接收 is_cross_attention（harness:654）⇒ 对拍 oracle 零改动,cross 与 self 同一把尺子量。
R1 反证（mask 开关确实承重）: reviewer 把 cross mask 篡改回 self 几何 → cross 案 FAIL（误差 4.70 vs 正常 1.95e-3）。证明这个 BOOL_SWITCH 不是装饰,是真正在分叉几何。（done §3 R1）
