一、项目是什么

起点：HSTU attention 的 backward 此前只有 855 行 CPU 参考（reference_hstu_attention_bwd.hpp），无 GPU kernel。目标：在 gfx950 / MI350X / CDNA4 上实现 GPU bwd，复用 ck_tile FMHA bwd 基建（PRE dot_do_o → MAIN 5-GEMM kr_ktr_vr → POST convert/reduce）。

反向的数学核心是 5 个 GEMM + 激活/掩码：dS=Q·Kᵀ 重算、dV=Pᵀ·dO、dP=dO·Vᵀ、dK=dSᵀ·Q、dQ=dS·K。其三段式 kernel 结构与各段墙钟占比见图1。基础原理见早期深读讲义：FMHA bwd 入门 · 5-GEMM 深读 · MAIN pipeline 7 阶段 · saved tensors · CK vs HSTU bwd · QKV layout。

图1：bwd kernel 三段结构。dQ 需跨 KV-block 累加（dQ_acc），故有 atomic / deterministic 两条归约路；MAIN 占墙钟 84–90%（profile 实测），是 M8 perf 的收紧对象。

最终能力边界（commit 048f0a9a）：SiLU + softmax × 全模式（batched / jagged / group） × self + cross-attention（seqlen_q ≠ seqlen_kv 全方向） × 全 5 因子 mask × causal{0,1} × bf16 + fp16 × 任意 hdim_qk/hdim_v ∈ (0,256]（对称 + 非对称 + 非典范，经 head-dim padding） × dQ atomic + deterministic（全模式）。真 reject：hdim>256。out-of-scope：target_in_kv、非方形 tile、独立 dO layout。

这条能力边界按「轴」展开见图2——每条轴的取值均已对拍覆盖，真 reject 与 out-of-scope 项明确分列。

图2：能力边界矩阵。左侧 7 条轴的取值均已对拍覆盖（绿）；右侧明确分列真 reject（hdim>256，显式 throw）与 out-of-scope（target_in_kv / 非方形 tile / 独立 dO layout）——边界诚实、不夸大成「任意」。

三、M8 性能结论（evidence-driven）

rocprofv3 实测：MAIN dqdkdv 主导 84–90% wall-time、矩阵核闲 ~90%（MfmaUtil 9.9%）、非 memory-bound。瓶颈 = GetTileRangeAlongY 保守全扫的浪费 q-tile。收紧后 MAIN 加速 causal 1.25–1.60× · window 4.7–9.8×（窄窗 window16 最高 9.8×，benchmark.csv 录值），诚实 Amdahl 归因（实测 < 模型，因只砍 q-loop、K/V load + atomic 写 + 启动开销不减）。各档加速见图4。

图4：M8 MAIN 加速实测。B2 causal 1.25–1.60×；B3 window 越窄赢越多（window16 达 9.4×/9.8×）。各 window 档共用全扫基线（全扫与 window 大小无关）。详见 M8 讲义。

占用率 investigation 定论（未上 B7）：VGPR 真值 248（rocprofv3 报半值 124 是单位假象）；occupancy 被 VGPR+LDS 共卡 2 blocks/CU，但真瓶颈是 VALU/SFU（VALUBusy 41% ≫ MfmaUtil 18%），非 occupancy-bound → B7 提占用率低 ROI（需 tile 重设计）。SiLU 比 softmax 慢 26% = sigmoid 需 2 个超越运算（exp+rcp）vs softmax 1 个，本质开销非 bug。

四、方法论 / 工程纪律（贯穿全程）

每个里程碑都走同一条「四方闭合」证据链，底座是一组可证伪的工具——见图5。

图5：四方闭合 + 证据栈。上排是每里程碑的人/角色流程（coder → reviewer 独立重建 → lead 亲核 → 对抗实验）；下排是支撑结论的可证伪工具（co_symbols / poison-pad / 离线校验器 / reverse-proof）。下文逐条展开。

  • kernel-design-rocm skill：task contract + draft 闸门 + 每候选对拍验证 + 证据 workspace（candidates.jsonl / benchmark.csv / profile/ / runs/）。
  • 分阶段 + 硬检查点：复杂里程碑先证「重构本身零回归」（如 M7b/M7c/cross/M8 的 Stage 1 后必停），lead 亲核放行才进下一阶段。
  • 四方闭合：coder 实现 + reviewer 独立重建复核 + lead 亲核 + 对抗实验（reverse-proof / formula-revert）。
  • 零回归铁证：co_symbols.py 逐设备符号 byte-identity（gfx950 code object 反汇编 sha256）；MI/纯加性改动须 byte-identical，behavior 改动须 surgical（仅目标符号变）。
  • silent-wrong 正向证：poison-pad（NaN 填 pad 尾，泄漏即 FAIL）证 OOB 归零；离线穷举 superset 校验器（validate_tile_range_y，~2M checks）证收紧不漏梯度——比对拍更早更硬，M8 中抓到 2 个对拍可能漏的 under-tighten bug。
  • 对抗 reverse-proof：故意篡改令测试/校验器 FAIL，证检查非 vacuous（cross 的 mask→self、M8 的破坏收紧）。
  • ultracode 混合编排：设计阶段用 Workflow 多 agent 并行分析 + critique 广度；实现阶段用 tmux pane 有状态 + 跨多轮 build 的连续性。

五、关键教训

  • 测试覆盖洞：bug P1-1 漏测因矩阵只测「对角线」；新特性须 causal×因子 交叉覆盖。M6b 又一次：「同组多 batch 异 seqlen + 长 batch 大 target」漏覆盖致一格 FAIL。
  • silent-wrong 比 throw 危险：未支持组合不 throw 会静默算错；要么对拍/穷举覆盖，要么显式 throw（M7b/c 的 guard、cross 的 target_in_kv）。
  • 下 bug 定性前找 owner 核实：曾把上游 fwd 默认推导误判 bug，核实为用法约定（HANDOFF §6）；后又实测上游 5204dc75 的 num_targets 修复因 */+ 笔误仍不对。
  • 改有未提交改动的文件别 git checkout（M7c N3 事故）；做对抗实验用独立 worktree + cp。
  • perf 模型会高估：[derived] 模型受 Amdahl 限，实测多少记多少（M8 causal 1.6× vs 模型 1.9×、window ~10× vs 22×）。
  • workflow 综合 agent 会幻觉路径/行号（如把测试驱动写成不存在的 scripts/）；综合产物 lead 必核事实。
