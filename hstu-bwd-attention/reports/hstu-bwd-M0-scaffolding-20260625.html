3  逐文件 review（为什么这样改）

① params.hpp — 数据契约（核心）新增

  • :17 HstuAttentionNoGroupBwdParams：一个结构体同时承载 batched + jagged，靠 :24 is_jagged 运行时区分（DESIGN §4.6）。Group 单列结构体 :116，M0 仅占位（:118 注释「M4 实现」）。
  • :19-41 复用 fwd 输入全集（Q/K/V/O + hdim/num_head/strides），刻意与 hstu_attention_params.hpp 对齐，降低 host 构造成本。:36 o_ptr 注明只有 softmax 路径要 O（PRE 算 D=rowsum(O.*dO)）。
  • :43-45 scales：alpha=QK 缩放（= fwd scale_s）；attn_scale→SiLU 输出缩放 scale_p，softmax 不用。两个 scale 先入字段，M1 才真正传进 pipeline。
  • :69-95 bwd 专属字段：do_ptr（dO）、lse_ptr（softmax 才有，SiLU=nullptr）、dq/dk/dv 三件套、d_ptr（PRE 产物）。
  • :97-103 dQ workspace：dq_acc_ptr 为 float 累加区，atomic 路径 num_splits=1，deterministic 路径 ceil(max_seqlen_k/kN0)（M6）。dQ 数值正确性的关键预留。
  • :106 kIsDeterministic：虽是模板轴，但以 bool 字段存在，让 host 据此挑实例。

② api.hpp — 入口 新增

  • :20-22 仅新增 hstu_attention_no_group_backward_bf16 一个 entry；注释明确 fp16→M7、group→M4。最小暴露面。

③ bwd_kernel.hpp — 算法骨架（只有注释 + 空 namespace）新增

  • :15-20 3-kernel 流水线蓝图：[PRE] D=rowsum(O.*dO)(M5) → [MAIN] 5 GEMM/7 stage 出 dV/dK + float dq_acc(M1) → [POST] dq_acc(float)→dQ(M1)。SiLU 只跑 MAIN→POST。
  • :22-25 M1/M5/M6 的 TODO 钉死在代码里——文档即代码。M0 此文件无可执行内容，纯粹把后续要长出来的形状先画好。

④ batched_backward_dispatch.hpp — 选型 + 占位 新增

  • :34-40 6 轴模板签名：<InOutDataType, kUseCausal, kUseSoftmax, kHasBias, kIsDeterministic, MaxK>，与 fwd / DESIGN §4.3 对齐。
  • :42-62 hd64 tile 形状直接搬 FMHA bwd '64' preset。M0 定义但 RunSilu 暂未用——为 M1 预铺。
  • :66-84 RunSilu = M0 的桩：hipMemsetAsync 把 dQ/dK/dV 清零，:72-76 用 num_batch * batch_stride_* 算元素数。为什么是 memset：让 harness 的 fwd→bwd→对拍 端到端跑起来（结果虽 0），先验证接线，再填数学。

M0 最精妙处： 未实现路径各编译成一句 throw，但因 if constexpr 包裹，未启用的分支根本不实例化——编译开销为零、运行时给出清晰「未实现，见 Mx」报错。这把「未来要支持但现在没有」编码成了可执行的占位。

⑤ no_group_backward_bf16.cpp — 入口实现 新增

  • :23 BOOL_SWITCH_2(use_causal, …, use_softmax, …)：把两个运行时 bool 降维成模板常量，再调 :25 run_batched_backward_dispatch<bf16, …>。
  • :28-30 bias/deterministic 写死 false、MaxK 写死 64（DESIGN §4.5 MVP）；完整 fan-out 留 M1+。

⑥ instances/* — 显式实例化 新增

  • *_ref.hpp:12-42：4 个 extern template（causal×softmax 的 2×2），告诉每个 TU「这些实例在别处定义」。
  • 4 个 *.cpp 各显式实例化一个组合（如 has_causal_softmax_true...:12-18）。为什么拆文件：每组合独立编译单元 → 并行/增量编译，CK 一贯做法。
  • 文件头 :5-7 标注「自动生成，勿改」。

⑦ generate_instances.py — 实例生成器 改动

  • :23-41 fwd/bwd 实例的模板字符串 + 文件名模板；:45-58 bool→字符串映射。改生成器而非手写，保证实例与 dispatch 签名永远同步。

⑧ CMakeLists.txt — 构建目标 改动

  • 新增 tile_example_hstu_attention_bwd，EXCLUDE_FROM_ALL：默认全量构建不带它，半成品不污染 CI。
  • file(GLOB ...*backward*.cpp) + 额外 GLOB *forward_bf16*.cpp：注释点明——bwd harness 要先在 GPU 跑 fwd 产 O 再做 bwd，故必须把 fwd bf16 entry/实例一起链入。
  • gfx950 分支 -fno-slp-vectorize（镜像 fwd 的流水线优化开关）。

⑨ example_hstu_attention_bwd.cpp — 验证 harness（506 行）新增

  • 端到端骨架：随机 Q/K/V → GPU fwd 得 O → 调 hstu_attention_no_group_backward_bf16 → （M0 阶段 bwd 输出全 0，仅验证不崩、接线通）。后续里程碑在此加 CPU 参考对拍。

4  设计动机小结

  1. 接口先冻结，逻辑后填充：params 字段名一次定死（params.hpp:13-15），换来 M1–M8 全程零 params 重构。
  2. 未实现 = 可执行占位：if constexpr+throw（dispatch:88-108）让未来路径有清晰报错、零编译开销、零误用。
  3. 先通链路再填数学：RunSilu 用 memset 桩（:66-84），先把 fwd→bwd→对拍 跑通。
  4. 构建隔离：EXCLUDE_FROM_ALL 让半成品不污染主构建；GLOB 自动纳管实例。
  5. 生成器优先：实例由 generate_instances.py 产出，杜绝手写实例与签名漂移。
