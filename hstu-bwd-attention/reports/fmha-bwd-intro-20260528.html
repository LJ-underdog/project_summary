TL;DR

本文讲清楚三件事：(1) backward 公式如何从 forward 推导出来；(2) CK 用三个独立 kernel 分工完成 backward；(3) 主 pipeline 的七阶段实现逐行解读。

技术要点速览：用 forward 存下的 O, LSE 在 tile 内重算 S, P，借助一次性算好的 D = rowsum(O ⊙ dO) 把 softmax Jacobian 化为 element-wise；并行划分按 KV 切到 workgroup，dK, dV 在 register 完成 reduction，dQ 走 atomicAdd 或 deterministic split-reduce + fp32 workspace。CK 通过 3 个独立 kernel (dot_do_o → dq_dk_dv → convert_dq) + 4 种 pipeline 变体（KR / IGLP / TrLoad × QR / decode）实现。

1. 数学原理

从链式法则推导 attention backward 的 5 条核心公式，引出 D 这个关键中间量，以及为什么需要重计算 P。

1.2 Backward 五条公式 + D 的化简

已知 dO = ∂L / ∂O，目标求 dQ, dK, dV。从 O = PV 链式法则展开：

Softmax Jacobian 化简：softmax 反传公式为 ∂L/∂Sij = Pij(∂L/∂Pij − Σk Pik ∂L/∂Pik)， 令 ρi = Σk Pik dPik，即得 dS = P ⊙ (dP − ρ)。 后续推导证明 ρi = Di，从而无需 materialize P 或 dP。
dV = PT dO dP = dO VT dSij = Pij (dPij - rhoi) where rhoi = sumk Pik dPik dQ = dS K / sqrt(d) dK = dST Q / sqrt(d)

关键化简：展开 rho 并用 O = PV 即 Oid = sumk Pik Vkd：

rhoi = sumk Pik dPik = sumk Pik sumd dOid Vkd = sumd dOid Oid =: Di
意义：rho 不需要 materialize P 或 dP 就能算出来，只需 fwd 存下的 O 和 bwd 输入的 dO。这就是 block_fmha_bwd_dot_do_o.hpp 这个 pre-compute pass 的全部任务。

D 的预计算：双层 sweep 累加 o ⊙ dO，最后乘 p_undrop 把 dropout 概率因子吸收进 D。一次 row reduction 干掉整个 softmax Jacobian 的 dense 性。LDS 用量 = 0（line 31）。

1.3 重计算 P 的原理

主循环里给定 tile S(i,j) = Q(i) (K(j))T / sqrt(d)（重新算一次），用存下的 LSE(i) 直接还原：

Pij = exp(Sij - LSEi)
数学等价于 exp(S - m) / l（因为 LSE = m + log l），但分母并入 LSE 一次性减掉更省一次除法 & 数值稳定。CK 实测中还会预乘 log2e 走 hardware exp2 替代 exp（见 §3 stage 2）。

1.4 双层循环 + 并行策略

FA-2 bwd 有两种数学等价的循环顺序。CK 选择 KV 外、Q 内：每个 workgroup 负责一个 K/V tile，扫过所有相关 Q tile。优点是 dK, dV 在 register 完成 reduction，代价是 dQ 跨 workgroup 累加需要 atomic 或 split-reduce。

// kr_ktr_vr.hpp:583-602 -- Softmax with exp2 trick
auto p = tile_elementwise_in(
  [&](auto s, auto lse_i){
    return exp2(scale * s - log2e * lse_i);
  }, s_acc, lse);
用 exp2 替代 exp：LSE 是以 base-e 算的，预乘 log2e 后改走 hardware exp2 指令，更快且精度等价。scale 是 softmax scaling (1/sqrt(d))，提前与 S 相乘吸收一次 elementwise pass。

// kr_ktr_vr.hpp:655-667 -- dS with dropout flag
sweep_tile_span(ds_spans[0], [&](auto idx0){
  sweep_tile_span(ds_spans[1], [&](auto idx1){
    bool undrop_flag = p[ij] >= 0;

      (!IsDropout || undrop_flag

P 负值作 dropout flag：dropout.Run 把被 drop 的 P 设为负数。dS 公式两条路径：keep 走 p*(dp-d)，drop 走 p*d（p<0 提供符号）。约定省一次 zero-fill 的代码生成。

3.3 dQ Accumulation -- 两条路径详解

为什么 dQ 特别：dV/dK 每个 KV-block 由唯一 workgroup 累加（Q 是内循环），无并发；而 dQi = sumj dSij Kj 求和方向是 j (KV)，跨不同 workgroup → 必须并发累加。

路径触发机制代价确定性
atomicAdd!kIsDeterministic (默认)硬件 v2f16/v2bf16 原子加直写 dq无额外 workspacefp 加法非结合 -> bit 不可复现
split-workspace + reducekIsDeterministic主 pipeline 写 fp32 workspace[s, ...]，convert_dq kernel 顺序 reduce + cast+nsplits×Sq×H×d×4B DRAM, +1 kernel launchbit-exact reproducible
Precision Note

atomic 路径用的是 fp16/bf16 packed atomic add（generic_memory_space_atomic.hpp:326）。dq_acc 在 register 是 fp32，通过 update_vectorized_elements 内部 cast 后做硬件 atomic。超长 seqlen + 多 KV-block 累加会累积舍入误差 -- deterministic 路径就是为此而生。

4.3 常见问题

为什么不直接存 fwd 的 S 或 P，省去重计算？
两者都是 O(S2) 显存。典型 seqlen=8K, batch=4, head=32, fp16: S 矩阵 = 4×32×8192×8192×2B = 16 GB，根本放不下。重计算只用 O(S×d) 的 Q/K/V 和 O(S) 的 LSE，总开销不超过 O 本身。
CK 为什么选 KV 外、Q 内而不是反过来？
causal mask 下大约一半 KV-block 被多个 Q-block 访问，把 KV 留在最内层会重复 reload。外 KV 把 K/V 一次性 preload 到 reg，节省 DRAM 带宽；代价是 dQ 需要 atomic 或 split-reduce，但这是单次写而非多次读，trade-off 更好。FA-2 论文也用这个方向。
deterministic 路径什么时候必须开？
三种场景：(1) bit-exact reproducibility 测试或调试；(2) 数值敏感的训练（fp16 atomic 多次累加会有 ULP 级误差，对小学习率训练可能影响收敛）；(3) 跨 GPU 数量复现实验（atomic 序与 launch 调度相关）。代价是 +nsplits×Sq×H×d×4B workspace + convert_dq kernel 一次额外 launch。性能不敏感时直接开。
