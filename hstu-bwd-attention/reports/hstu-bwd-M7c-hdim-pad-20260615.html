CK · HSTU Backward · M7c asymmetric + 非典范 hdim 实现讲义

HSTU Attention Backward — M7c：接受 hdim_qk≠hdim_v 与任意非典范 hdim，办法是「激活一套已接线却死掉的 head-dim padding」

这份文档讲清 M7c 如何把 bwd 从 仅 symmetric 典范 hdim {64,96,128,256}（M7b）扩到 hdim_qk / hdim_v 任意 ∈ (0,256]（对称 + 非对称 + 非典范 48/80/100/192/200…）。核心不是写新算法——pre-M7c 的 bwd 每个 DRAM view / LDS window / epilogue 早就 honor kPadHeadDimQ/V，只是被喂 constexpr 0 且被 guard-throw 挡在门外（接线已活、机制死了）。M7c 用一个运行时 BOOL_SWITCH_2 把它打开，不新增任何 instance。最难的不是开关，是怎么证明越界的 head-dim load 真归零、越界 store 真跳过——M7c 用 -poison_pad（NaN 毒化 pad 尾）+ 两条 reverse-proof 把这点钉成可证伪的工程论证。范围诚实标注：hdim>256 仍真 reject、非方形 tile out-of-scope。所有片段引磁盘真实行号（commit 17515fcc，基线 1ae97750 = M7b）。

TL;DR — 一句话看懂 M7c

bwd 的 kernel/pipeline/epilogue 全都已经按 kPadHeadDimQ/V 模板化——pad 是注入的真值门。M7c 只做一件事：把两个 dispatch 里写死的 constexpr kPadHeadDimQ/V = 0 换成运行时取模派生的 NTTP（!(hdim % tile == 0)，镜像 fwd），用 BOOL_SWITCH_2 喂进 RunSilu/RunSoftmax；同时把 M7b 的 hdim==MaxK guard-throw 放松成 hdim>MaxK。pipeline / kernel / reference 一行未改（git diff 为空）；不新增 instance（pad 非 codegen 轴）。

最关键的设计点：canonical hdim（hdim%MaxK==0）下两个 flag 都派生为 false ⇒ 实例化出与 M7b 逐符号 byte-identical 的 kernel = 零回归基石；非典范 / 非对称经 pad 走通。正确性依赖越界 head-dim load 恰好归零、越界 store 恰好跳过——这条不变式不靠 bf16 容差蒙混，而用 -poison_pad（pad 尾填 NaN）正向证 + 两条 reverse-proof 反向判伪。

1  M7c 是什么：解禁任意 hdim ∈ (0,256]（对称 + 非对称 + 非典范）

M7c 把反向支持的 head-dim 从 symmetric 典范 {64,96,128,256}（M7b 要求 hdim_qk==hdim_v==MaxK）扩成 hdim_qk / hdim_v 各自任意 ∈ (0,256]。办法 = 激活 head-dim padding：两个 hdim 都向上 round 到同一个方形 tile MaxK（HDIM_SWITCH 选 ≥max 的最小典范值），pad 进这个 tile。不动 dtype（bf16+fp16 已 M7a 通）、不动 kernel 算法、不新增 instance。

In scope（M7c 新解禁）
任意 hdim ∈ (0,256]
非对称 64/128, 128/64, 96/256；非典范 48 / 80 / 100 / 192 / 200；两者组合 80/128, 100/64。经 head-dim pad 走通，全模式覆盖。
真 reject（结构性，保留）
hdim > 256
hstu_attention_hdim_switch.hpp 的 else-throw 未碰。实测 512/512、300/300、asym 256/512、group 512 全部 throw "Head-dim sizes not supported!"。
Out of scope（非缺口隐瞒）
非方形 tile
bhdq != bhdv（qk/v round 到不同 tile）不支持——HSTU/FMHA 都只证方形。M7c 选单一方形 MaxK + 独立 pad；若需属 M8。
白话： M7b 是「让 kernel 换更大的 tile 跑」，M7c 是「让现成的 padding 机制把不满 tile 的 hdim 补齐到 tile 跑」。难点不在算法，在怎么保证 pad 出来的列在收缩时贡献恰好 0、在输出时一个字节都不写——否则会静默毒化梯度或污染相邻 head。这正是 §4 的主线。

2  核心洞察：pad 机制结构上已完整，只是被钉死

这是整单最值得讲的点。pre-M7c 的四个 bwd kernel（no_group SiLU+softmax、group SiLU+softmax）的每个 DRAM view、每个 LDS window、每个 epilogue 都已经按 fwd 同款方式 honor kPadHeadDimQ/V——只是被两件事钉死：① dispatch 把它喂 constexpr 0；② 入口 guard-throw 把非典范 hdim 直接挡掉。M7c = 把这两道锁打开，一行 kernel/pipeline 不碰。

3  pad 模型 + 逐 GEMM：两个独立 flag，绝不交叉接线

pad 模型（与 fwd 同，tensor_view.hpp）：pad = ceil(real/tile)*tile - real，右 pad 是逐元素 validity 谓词、非 clamp——越界 head-dim load 零替代、越界 head-dim store 跳过。故 padded 收缩列贡献恰好 0、padded 输出列从不写。正确性依赖「越界 load 返回恰好 0」这条不变式。

两个 flag 各自跟踪自己那组张量，绝不交叉（否则把张量 round 到错 tile = 静默毒化梯度）：

tile = kQKHeaddim

V 组 · flag = kPadHeadDimV
tile = kVHeaddim
张量：V · dO · dV · O，全 hdim_v 宽。pad 谓词 !(hdim_v % kVHeaddim==0)。

4  怎么证 OOB 真归零：poison-pad + 两条 reverse-proof

这是 M7c 最强的工程论证。bf16 容差 5e-2 会掩盖 OOB 读到的垃圾——光看「对拍绿了」证明不了 load 真归零。M7c 用 -poison_pad：harness over-alloc head-dim 到 MaxK，把 pad 尾填 NaN。任一 padded load 若没归零 → NaN 传播 → 输出 NaN → check_err 硬 FAIL。这是肯定性证据，不靠容差。

poison-pad 双向断言（harness,-poison_pad=1）： 输入 Q/K/V/dO 的 pad 尾 [real_hd, MaxK) 填 NaN → 证 load-zero 任一越界 load 泄漏 → NaN 进收缩 → 输出 NaN → check_err FAIL 输出 dK/dV 全缓冲预填 NaN,real 列被写、pad 尾必须留 NaN → 证 store-skip epilogue 若写 pad 尾 → 尾非 NaN → store-skip 标记 FAIL reference 只喂真实 hdim 抽取副本,比对只读真实列(容差未松)

【图2】poison-pad 机制 + 两条 reverse-proof（证检查非 vacuous）

图2：上 = 正向 poison（机制对则 NaN 被吸收，对拍 PASS + store-skip 尾留 NaN）；中 = reverse-proof #1（强制 pad=false → NaN 泄漏 → 硬 FAIL，证 load-zero 检查能判伪）；下 = reverse-proof #2（只关 dk/dv 视图谓词、loads 不动 → 梯度仍 PASS 但 store-skip FAIL，隔离证 store-skip 标记非 vacuous）。

为什么单列「非 vacuous」： 一个永远 PASS 的检查等于没检查。poison 的全部价值在于「机制坏了它会 FAIL」。reviewer 不只跑正向 poison（全绿），还主动破坏机制看它是否变红——#1 关 pad 谓词、#2 单独关 store 谓词，两者都实测 FAIL。这把「OOB 真归零 / 真跳过」从「相信」升级成「证伪过」。

5  精确归因：head-dim store-skip 的载荷元件是 DRAM-view 谓词

这是 review 阶段挖出的精确归因（reverse-proof #2 的副产物）。bwd 的 dK/dV 写回涉及两处看似都跟 pad 有关的代码：① Default2DEpilogueProblem 的末位 bool flag (kPadHeadDimQ>0)；② dk_dram/dv_dram DRAM view 的 pad 谓词 sequence<false,(kPadHeadDimQ>0)>。实测发现：head-dim store-skip 的真正落点是 ② 视图谓词，① epilogue flag 对 head-dim 冗余。

真 reject：hdim > 256（hstu_attention_hdim_switch.hpp else-throw，实测 512/300/asym-512/group-512 全 throw）。 Out of scope：非方形 tile（bhdq≠bhdv）——M7c 选单一方形 MaxK + 独立 pad；qk/v round 到不同 tile 属 M8。本文档不把范围夸大成「任意 hdim」。
  • dq_acc store-skip 测试盲区（§6）：poison over-alloc 吸收 OOB 写，由代码核实兜底（同 dK/dV 谓词，reverse-proof #2 已证该谓词有效）+ 真实列正确性兜底。production exact-alloc 无 OOB。
  • LSE 数值盲区（继承 M5/M5b）：两侧共用 GPU fwd LSE，靠 fwd 里程碑兜底；hdim 未改变此结构。
